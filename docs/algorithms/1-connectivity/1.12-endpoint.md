# 1.12 The endpoint (PeerEndpoint)

Section 1, *Connectivity*, of [Problems WebRTC solves](../../02-webrtc-problems-solved.md). Problems addressed:

- Setting up a whole call from SDP -> one object that applies descriptions and wires ICE, DTLS-SRTP, RTP and data channels

## The issue

Gathering ICE, running DTLS, keying SRTP, creating the RTP session and the data channel transport are separate pieces; a call needs them joined and driven by the SDP: apply an offer, produce an answer, add trickled candidates and tear down. One endpoint that owns that wiring keeps application code to a few calls.

## Design

An endpoint that sets up a call from SDP (C6 part 3, #1064): the transport half of libwebrtc M157's pc/sdp_offer_answer.cc and pc/peer_connection.cc (compare/webrtc/reference/pc/) over JsepTransportController (sm/pc/jsep_transport_controller.h), with the library's RTP session (sm/rtp/session.h) as the media channels.

What it does, as libwebrtc does for C6's subset (one audio and one video transceiver, Unified Plan): - CreateOffer / CreateAnswer through MediaSessionDescriptionFactory (#1063) with the engines' default codecs

```
  (Opus; H.264 constrained baseline with RTX) and header extensions, BUNDLE and rtcp-mux, a fresh 64-bit session
  id and version 2 (WebRtcSessionDescriptionFactory). The answer follows the offer's m= sections: audio and video
  are answered (sendrecv while this end sends), the data section as below, and any other section is rejected.
```

- SetLocalDescription / SetRemoteDescription check the signaling state (stable -> have-local-offer or

```
  have-remote-offer -> stable), apply the description to the transports, record the payload types
  (SdpPayloadTypeSuggester) and, after a local description, start ICE gathering. Candidates in a remote
  description are added (UseCandidatesInRemoteDescription).
```

- AddIceCandidate adds a trickled candidate to the transport of its mid (or of its m-line index); a candidate for

```
  a rejected section is ignored. Gathered candidates come out through the ice candidate callback with their mid
  and m-line index (OnIceCandidate).
```

- When an answer is applied, the RTP session is configured from the negotiated sections, as the voice and video

```
  channels are by SetLocalContent / SetRemoteContent: the send streams take the local section's SSRCs (video with
  its RTX SSRC from the FID group), the receive streams the remote section's, both the answer's payload types
  (Opus; the first H.264 and its RTX), the negotiated header extensions (one id map: BUNDLE requires the same
  ids), the MIDs when the MID extension is negotiated, NACK as negotiated for H.264, and the CNAME of the local
  stream. Each section's demuxer sink (its MID and the remote SSRCs) and header extension map are registered on
  the BUNDLE transport, as BaseChannel does; RTP and RTCP it receives go to the session, and the session's
  packets go out through it, protected with the DTLS-SRTP keys (PF_SRTP_BYPASS).
```

- Data channels (C7 part 5, #1091), as pc/data_channel_controller.cc and the SCTP half of pc/sdp_offer_answer.cc,

```
  with the per-connection switch `enable_data_channels` on (the default, as libwebrtc):
  - CreateDataChannel before or after the offer; the offer carries the m=application section (UDP/DTLS/SCTP,
    a=sctp-port 5000, a=max-message-size 262144) once a channel exists (GetOptionsForOffer adds it last, when
    HasDataChannels(), with the next mid), on the BUNDLE transport;
  - an answer accepts the first data section of a remote offer (GetOptionsForAnswer) and rejects the others;
  - when both descriptions have the section (PushdownMediaDescription: "complete offer/answer with an SCTP m=
    section before starting SCTP"), the SCTP transport (sm/sctp/, #1082) starts over the section's DTLS
    transport with the local and remote ports and the smaller max message size (the local one if the remote's
    is 0); stream ids follow the DTLS role (DataChannelController);
  - in-band (DCEP) and negotiated channels open, and the remote side's in-band channels are announced through
    the data channel callback; a rejected data section closes the channels (DestroyDataChannelTransport).
  With the switch off: no m=application in an offer, a data section in a remote offer is rejected (port 0), no
  SCTP object is created, and CreateDataChannel fails (kInvalidState). Built without SM_WITH_DATACHANNEL, none of
  this is compiled in and CreateDataChannel fails with kUnsupportedOperation.
```

The library's time model: nothing reads a clock or starts a thread. The owner runs Process(now) at NextProcessTime(now) and delivers the sockets' packets (the port allocator's socket factory) itself.

Differences from libwebrtc, none of them on the wire: - One audio and one video transceiver, added at construction; no tracks, streams or transceiver API, no

```
  renegotiation after the first offer/answer (a second offer is refused), no rollback or pranswer, and no
  unsignaled (SSRC-less) receive streams.
```

- The RTP session is created when the answer is applied, not per channel at the first description; until then

```
  nothing is sent (no early media), which libwebrtc can't send either before DTLS-SRTP is up.
```

- The SCTP transport is created by the endpoint when SCTP starts, on the DTLS transport the data section ended

```
  up on, rather than one per JsepTransport at its creation (JsepTransportController's sctp factory); the same
  association on the wire. No always_negotiate_data_channels, no SCTP SNAP (sctp-init), no renegotiation.
```

- STUN needs its crypto hooks: call p2p::InstallStunCryptoFromTls() once at startup (sm::p2p_tls).

The transports a call's session descriptions set up (C6 part 3, #1064): libwebrtc M157's pc/jsep_transport.{h,cc}, pc/jsep_transport_controller.{h,cc} and the BUNDLE bookkeeping of pc/jsep_transport_collection.h (compare/webrtc/reference/pc/), for C6's subset.

What it does, as libwebrtc does: - Applying a local or remote description creates, for each m= section that is not rejected and is the first of

```
  its BUNDLE group (or in none), a JsepTransport: a P2PTransportChannel (ICE, component 1), a DtlsTransport with
  the local certificate over it, and a DtlsSrtpTransport over that. rtcp-mux is required (kRtcpMuxPolicyRequire,
  PeerConnection's default), so there is no RTCP component; a section without a=rtcp-mux is refused.
```

- BUNDLE (RFC 8843) as BundleManager does: an answer (or any description with max-bundle) replaces the

```
  established groups, an offer only updates groups already established. The other mids of an established group
  use the first mid's transport, and when an answer is applied the transports no mid uses any more are destroyed
  (JsepTransportCollection::CommitTransports). The offer/answer checks of ValidateAndMaybeUpdateBundleGroups are
  kept (a mid in two groups, a group added or changed in an answer, an answer that drops a bundled section).
```

- The ICE role is set by the first local description (controlling for an offer, controlled for an answer), with

```
  DetermineIceRole's ICE-lite exceptions. ICE credentials go to the channel from each description; trickled
  candidates (AddRemoteCandidates) need the remote description and go to the transport of their mid.
```

- On an answer (local or remote), NegotiateAndSetDtlsParameters: the DTLS role from both a=setup values

```
  (NegotiateDtlsRole, RFC 5763 section 5) and the remote fingerprint go to the DTLS transport. A local fingerprint
  must be the local certificate's (VerifyCertificateFingerprint). Encrypted header extension ids (RFC 6904) go to
  the DTLS-SRTP transport, merged over a BUNDLE group.
```

- Gathered candidates are reported with the transport's name (its first mid).

The library's time model: nothing reads a clock or starts a thread. Calls that can send take `now`; the owner runs Process(now) at NextProcessTime() (ICE checks, DTLS retransmissions), and delivers the sockets' packets itself.

Differences from libwebrtc, none of them on the wire: - One thread: no network-thread hops, and callbacks run inside the call that caused them. RTCError is bool plus a

```
  message.
```

- Left out until a part needs them: kRtcpMuxPolicyNegotiate (non-muxed RTCP), rollback and pranswer commits,

```
  ICE restarts' role re-evaluation (redetermine_role_on_ice_restart), DTLS-in-STUN (SPED), cryptex, the
  aggregate ICE/DTLS/connection states (the transports' own states are read instead), and the SCTP transport per
  JsepTransport (PeerEndpoint creates the one it uses on the data section's DTLS transport when SCTP starts, #1091).
```

- pc/jsep_transport_collection.cc is not in compare/webrtc/reference/; BundleManager::Update and the commit are

```
  ported from M157's behaviour as its header describes it.
```

libwebrtc M157 counterpart: `pc/jsep_transport_controller.{h,cc}`, `pc/peer_connection` (the signalling part), `pc/jsep_transport`. Differences from libwebrtc: [libwebrtc parity inventory](../../design/libwebrtc-parity.md), section [10.19](../../design/libwebrtc-parity.md#1019-the-endpoint-that-sets-up-a-call-from-sdp-srcpcjsep_transport_controllerpeer_endpointcc-c6-part-3-1064), [10.21](../../design/libwebrtc-parity.md#1021-data-channels-on-the-endpoint-srcpcpeer_endpointcc-c7-part-5-1091). Requirement C6 part 3 and C7 part 5. Other tests: `tests/interop/browser` (a call with headless Chrome, a data channel message each way).

namespace sm::sctp {
class SctpTransport;
}  // namespace sm::sctp

namespace sm::pc {

class DataChannelController;
class SctpDataChannel;

struct PeerEndpointConfig {
  // Not owned; must outlive the endpoint. Its socket factory carries the ICE traffic.
  p2p::PortAllocator* allocator = nullptr;
  // The DTLS certificate; null: one is made (RTCCertificateGenerator) with this name.
  std::shared_ptr<const tls::SslIdentity> certificate;
  std::string certificate_name = "WebRTC";
  JsepTransportController::Config transport;
  bool audio = true;  // An audio transceiver (sendrecv).
  bool video = true;  // A video transceiver (sendrecv).
  // The track and stream ids of the senders (a=msid).
  std::string stream_id = "stream";
  std::string audio_track_id = "audio";
  std::string video_track_id = "video";
  // The RTP session's settings; SSRCs, CNAME, MIDs, extensions and payload types are filled in from the SDP.
  rtp::SessionConfig session;
  rtp::AudioStreamConfig audio_stream;
  rtp::VideoStreamConfig video_stream;
  // Decodes the received Opus frames; not owned. Null: no audio receive stream.
  rtp::AudioDecoder* audio_decoder = nullptr;
  // Data channels for this connection (C7's runtime switch). Off: no SCTP object and no m=application. Has no
  // effect when the library is built without SM_WITH_DATACHANNEL.
  bool enable_data_channels = true;

  // The host runs its own media sessions (the test bench, #1087): the endpoint makes no rtp::Session. It
  // demuxes what the BUNDLE transport receives for the negotiated sections to `on_media_packet` (RTP and RTCP,
  // after SRTP), and sends the host's packets with SendMediaPacket. Off: the endpoint's own session, as above.
  bool external_media = false;
  std::function<void(std::span<const uint8_t> packet, bool rtcp, Timestamp arrival)> on_media_packet;
  // The SSRCs the local description announces (a=ssrc, the FID group), for a host whose sessions send on fixed
  // SSRCs, as an app that munges the SDP before SetLocalDescription. Unset: the generated ones.
  std::optional<uint32_t> audio_ssrc, video_ssrc, video_rtx_ssrc;
  // Simulcast send (C17, issue #1162): the RIDs of the video sender's encodings, lowest resolution first, as
  // RTCRtpTransceiverInit.sendEncodings with rids (e.g. {"q", "h", "f"}). With two or more, the offer carries an
  // a=rid:<rid> send line per encoding and a=simulcast:send <rid>;<rid>;... and no SSRCs (sdp_offer_answer.cc
  // GetMediaDescriptionOptionsForTransceiver, media_session.cc CreateStreamParamsForNewSenderWithRids), as an SFU
  // such as LiveKit expects; when the answer is applied the SSRCs are generated per layer, with RTX (BaseChannel::
  // UpdateLocalStreams_w), and the session gets one video send stream per layer with its RID
  // (video_simulcast_sends()). An answer without a=simulcast or the RID extension rejects simulcast and only the
  // first encoding stays active (DisableSimulcastInSender); a layer the answer pauses (~rid) or leaves out is
  // inactive (UpdateSimulcastLayerStatusInSender). Empty or one RID: no simulcast.
  std::vector<std::string> video_simulcast_rids;
};

// One negotiated simulcast encoding of the video sender (RtpEncodingParameters rid and active).
struct SimulcastEncoding {
  std::string rid;
  bool active = true;
};

// PeerConnectionInterface::SignalingState, for C6's subset.
enum class SignalingState { kStable, kHaveLocalOffer, kHaveRemoteOffer, kClosed };

class PeerEndpoint {
 public:
  using IceCandidateCallback = std::function<void(std::unique_ptr<IceCandidate>)>;

  PeerEndpoint(PeerEndpointConfig config, Timestamp now);
  ~PeerEndpoint();
  PeerEndpoint(const PeerEndpoint&) = delete;
  PeerEndpoint& operator=(const PeerEndpoint&) = delete;

  std::unique_ptr<SessionDescriptionInterface> CreateOffer(std::string* error = nullptr);
  // Needs a remote offer.
  std::unique_ptr<SessionDescriptionInterface> CreateAnswer(std::string* error = nullptr);
  bool SetLocalDescription(std::unique_ptr<SessionDescriptionInterface> desc, Timestamp now,
                           std::string* error = nullptr);
  bool SetRemoteDescription(std::unique_ptr<SessionDescriptionInterface> desc, Timestamp now,
                            std::string* error = nullptr);
  bool AddIceCandidate(const IceCandidate& candidate, Timestamp now, std::string* error = nullptr);
  void SetOnIceCandidate(IceCandidateCallback cb) { on_ice_candidate_ = std::move(cb); }

  SignalingState signaling_state() const { return signaling_state_; }
  const SessionDescriptionInterface* local_description() const { return local_description_.get(); }
  const SessionDescriptionInterface* remote_description() const { return remote_description_.get(); }
  JsepTransportController& transport_controller() { return transport_controller_; }
  // The transport of the first audio or video section (the BUNDLE transport); null before a description.
  JsepTransport* media_transport() const;
  // Both ends' ICE is writable, DTLS connected and SRTP keyed.
  bool IsConnected() const;

  // The RTP session, once an answer is applied; null before.
  rtp::Session* session() { return session_.get(); }
  std::optional<rtp::AudioSendId> audio_send() const { return audio_send_; }
  std::optional<rtp::VideoSendId> video_send() const { return video_send_; }
  std::optional<rtp::AudioRecvId> audio_receive() const { return audio_recv_; }
  std::optional<rtp::VideoRecvId> video_receive() const { return video_recv_; }
  // Simulcast (PeerEndpointConfig::video_simulcast_rids): the send stream of each layer, lowest first (video_send()
  // is the first), and each encoding's RID and negotiated state, once an answer is applied. Empty without simulcast.
  const std::vector<rtp::VideoSendId>& video_simulcast_sends() const { return video_simulcast_sends_; }
  const std::vector<SimulcastEncoding>& video_simulcast() const { return video_simulcast_; }

  // RTCPeerConnection.createDataChannel(), before or after the offer. Null, with `error` set, when data channels are
  // off for this connection (kInvalidState), not built (kUnsupportedOperation), or the config is invalid.
  std::shared_ptr<SctpDataChannel> CreateDataChannel(std::string_view label, const DataChannelInit& init,
                                                     Timestamp now, RtcError* error = nullptr);
  // The remote side opened a channel in-band (PeerConnectionObserver::OnDataChannel).
  void SetOnDataChannel(std::function<void(std::shared_ptr<SctpDataChannel>)> callback);
  bool data_channels_enabled() const { return data_channels_ != nullptr; }
  // Null when data channels are off or not built.
  DataChannelController* data_channel_controller();
  // The SCTP transport; null until SCTP starts, and always with data channels off.
  sctp::SctpTransport* sctp_transport();
  // The negotiated data section's mid, once a description with one is applied.
  const std::optional<std::string>& sctp_mid() const { return sctp_mid_; }

  // ICE checks, DTLS retransmissions and the RTP session's timers due by `now`; the session's packets go out.
  void Process(Timestamp now);
  Timestamp NextProcessTime(Timestamp now) const;
  // Sends the session's queued packets (after SendAudio / SendVideo on session()).
  void FlushOutgoing(Timestamp now);

  // external_media: sends one RTP or RTCP packet of the host's sessions over the BUNDLE transport (SRTP); false if
  // it can't (not connected, no transport).
  bool SendMediaPacket(std::span<const uint8_t> packet, bool rtcp, Timestamp now);
  // The ICE and DTLS timers only (external_media, whose host runs the sessions).
  void ProcessTransport(Timestamp now);

  // Packets the session produced that the transport could not send (not writable yet, or SRTP not active).
  int send_failures() const { return send_failures_; }

};

}  // namespace sm::pc

namespace sm::pc {

// pc/jsep_transport.h's JsepTransportDescription.
struct JsepTransportDescription {
  bool rtcp_mux_enabled = true;
  std::vector<int> encrypted_header_extension_ids;
  p2p::TransportDescription transport_desc;
};

// pc/jsep_transport.h: one ICE + DTLS + DTLS-SRTP transport and the descriptions applied to it.
class JsepTransport {
 public:
  JsepTransport(std::string mid, std::shared_ptr<const tls::SslIdentity> certificate,
                std::unique_ptr<p2p::P2PTransportChannel> ice, std::unique_ptr<p2p::DtlsTransport> dtls,
                std::unique_ptr<DtlsSrtpTransport> rtp_transport);
  ~JsepTransport();
  JsepTransport(const JsepTransport&) = delete;
  JsepTransport& operator=(const JsepTransport&) = delete;

  const std::string& name() const { return mid_; }
  bool SetLocalJsepTransportDescription(const JsepTransportDescription& d, p2p::SdpType type, Timestamp now,
                                        std::string* error);
  bool SetRemoteJsepTransportDescription(const JsepTransportDescription& d, p2p::SdpType type, Timestamp now,
                                         std::string* error);
  bool AddRemoteCandidates(const std::vector<p2p::Candidate>& candidates, Timestamp now, std::string* error);
  std::optional<p2p::SslRole> GetDtlsRole() const;

  const JsepTransportDescription* local_description() const { return local_description_.get(); }
  const JsepTransportDescription* remote_description() const { return remote_description_.get(); }
  p2p::P2PTransportChannel* ice_transport() const { return ice_.get(); }
  p2p::DtlsTransport* rtp_dtls_transport() const { return dtls_.get(); }
  DtlsSrtpTransport* rtp_transport() const { return rtp_transport_.get(); }

};

// PeerConnectionInterface::BundlePolicy.
enum class BundlePolicy { kBalanced, kMaxBundle, kMaxCompat };

class JsepTransportController {
 public:
  struct Config {
    // kBundlePolicyBalanced, PeerConnection's default.
    BundlePolicy bundle_policy = BundlePolicy::kBalanced;
    // CryptoOptions::Srtp::enable_encrypted_rtp_header_extensions: off by default.
    bool enable_encrypted_rtp_header_extensions = false;
    std::optional<p2p::IceConfig> ice_config;
    // Config::async_dns_resolver_factory, given to every ICE transport: resolves remote hostname (mDNS) candidates
    // (#1152). Not owned; must outlive the controller. libwebrtc's PeerConnection always has one; the library starts
    // no threads, so the host passes one (the apps: OsDnsResolverFactory in apps/net). Null: hostname candidates are
    // dropped, as libwebrtc's channel does without one.
    p2p::AsyncDnsResolverFactoryInterface* async_dns_resolver_factory = nullptr;
  };
  // (transport name, candidate): a candidate the transport gathered.
  using CandidateCallback = std::function<void(const std::string& transport_name, const p2p::Candidate&)>;

  // `allocator` is not owned and must outlive the controller.
  JsepTransportController(p2p::PortAllocator* allocator, Config config);
  ~JsepTransportController();
  JsepTransportController(const JsepTransportController&) = delete;
  JsepTransportController& operator=(const JsepTransportController&) = delete;

  // The certificate every DTLS transport uses; set once, before the first description.
  bool SetLocalCertificate(std::shared_ptr<const tls::SslIdentity> certificate);
  const std::shared_ptr<const tls::SslIdentity>& local_certificate() const { return certificate_; }

  bool SetLocalDescription(p2p::SdpType type, const SessionDescription* local_desc,
                           const SessionDescription* remote_desc, Timestamp now, std::string* error = nullptr);
  bool SetRemoteDescription(p2p::SdpType type, const SessionDescription* local_desc,
                            const SessionDescription* remote_desc, Timestamp now, std::string* error = nullptr);
  bool AddRemoteCandidates(std::string_view mid, const std::vector<p2p::Candidate>& candidates, Timestamp now,
                           std::string* error = nullptr);
  void MaybeStartGathering(Timestamp now);

  // The transports of a mid; null if it has none (rejected, or unknown).
  JsepTransport* GetJsepTransportForMid(std::string_view mid) const;
  DtlsSrtpTransport* GetRtpTransport(std::string_view mid) const;
  p2p::DtlsTransport* GetDtlsTransport(std::string_view mid) const;
  std::optional<p2p::SslRole> GetDtlsRole(std::string_view mid) const;
  p2p::IceRole ice_role() const { return ice_role_; }
  // The established BUNDLE groups.
  const std::vector<ContentGroup>& bundle_groups() const { return bundle_groups_; }
  size_t transport_count() const { return transports_.size(); }

  void SubscribeIceCandidateGathered(CandidateCallback cb) { on_candidate_ = std::move(cb); }

  // ICE checks and DTLS handshake retransmissions due by `now`.
  void Process(Timestamp now);
  Timestamp NextProcessTime() const;

};

}  // namespace sm::pc

## Metrics and observability

Every class implements `MetricsSource::ExportMetrics`, so it can be registered in a `MetricsRegistry` and exported as JSON or Prometheus text. Histograms expand to `.count/.mean/.p50/.p95/.p99/.max`.
