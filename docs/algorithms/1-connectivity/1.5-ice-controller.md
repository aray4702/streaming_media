# 1.5 The ICE controller

Section 1, *Connectivity*, of [Problems WebRTC solves](../../02-webrtc-problems-solved.md). Problems addressed:

- Deciding which pair to ping, use and switch to -> libwebrtc's `BasicIceController` and the wrapping active controller

## The issue

With many candidate pairs the agent must decide which to ping next, which to use for media, when switching to another pair is worth it and which to prune. The choice weighs priority, network cost, the pair's state and recent RTT; choosing differently from libwebrtc makes calls pick a relay when a direct path exists, or flap between pairs.

## Design

The ICE controller interface (#1002, part of ICE #990): libwebrtc M157's p2p/base/ice_controller_interface.{h,cc} and ice_controller_factory_interface.h (compare/webrtc/reference/p2p/base/).

An ICE controller decides which candidate pair (Connection) to ping, which to use, which to prune and which to forget the learned state of. P2PTransportChannel owns the connections and hands the controller const pointers; the controller asks for the mutations (Ping, Prune, ForgetLearnedState) through its results.

The library's time model replaces libwebrtc's clock: the calls that read Environment's clock there (HasPingableConnection, GetConnectionToPing, FindNextPingableConnection, ShouldSwitchConnection, SortAndSwitchConnection) take `now`, and IceControllerFactoryArgs has no Environment.

libwebrtc M157's BasicIceController (p2p/base/basic_ice_controller.{h,cc}, compare/webrtc/reference/p2p/base/), the ICE controller P2PTransportChannel uses by default (#1002, part of ICE #990): - Pinging: a weak channel (the selected pair not writable and receiving, or none) pings at the weak interval

```
  (48 ms), a strong one at 480 ms, and every active pair gets kMinPingsAtWeakPingInterval (3) pings at the weak
  interval first. The next pair to ping: the selected one when past its ping interval (900 ms while weak or not
  stable, 2.5 s once stable); on a weak channel the best writable pair per network, least recently pinged first;
  then triggered checks (a check arrived after our last ping), oldest first; then unpinged pairs before pinged ones,
  least recently pinged first, ties to the sort order. Backup pairs (state completed, not selected) are pinged
  every 25 s.
```

- Sorting: writable (or presumed writable) first, then write state, receiving, connected; on the controlled side

```
  the remote nomination and the last data received; then the network preference, the VPN preference, the network
  cost, the pair priority, the younger generation and unpruned before pruned; equal pairs by RTT.
```

- Switching: only to a pair that is ready to send (writable, unreliable or presumed writable). The first selection

```
  may be dampened (field trials, off by default). A pair on a worse network must be receiving. A pair that is
  receiving while the selected one is not wins only once both states are older than the receiving switching delay
  (1 s), else a recheck after that delay; equal pairs switch only for an RTT 10 ms lower.
```

- Pruning: a pair is pruned when a strong pair on its network is at least as good by candidates. - Nomination (USE-CANDIDATE): semi-aggressive by default.

The library's time model: the calls that read the clock there take `now` (sm/p2p/ice_controller_interface.h).

libwebrtc M157's p2p/base/active_ice_controller_interface.h and active_ice_controller_factory_interface.h (compare/webrtc/reference/p2p/base/): a module that actively manages the connection an ICE transport uses (#1002).

The library's time model: what libwebrtc posts to the network thread runs in Process(now), at NextProcessTime(), and the requests that post or switch take `now`.

libwebrtc M157's p2p/base/wrapping_active_ice_controller.{h,cc} (compare/webrtc/reference/p2p/base/): a legacy (passive) ICE controller, BasicIceController by default, packaged as an active one (#1002). P2PTransportChannel uses it: it pings the pair the wrapped controller picks every recheck delay once a pair is pingable, sorts and switches on request (at once, or as the next task), rechecks after the delay a switch result asks for, prunes after each sort (the controlled side only once its selected pair is nominated), and forgets the learned state it is told to.

The library's time model replaces the network thread: PostTask and PostDelayedTask queue the task with its due time, and Process(now) runs the due ones in order (a task posted while it runs runs in the same call if it is due). Destroying the controller drops its tasks, as libwebrtc's ScopedTaskSafety does.

libwebrtc M157's p2p/base/ice_switch_reason.{h,cc} (compare/webrtc/reference/p2p/base/): why the ICE transport re-sorts its candidate pairs or switches the selected one (#1002).

libwebrtc M157 counterpart: `p2p/base/{ice_controller_interface,basic_ice_controller,active_ice_controller_interface,wrapping_active_ice_controller,ice_switch_reason}.{h,cc}`. Differences from libwebrtc: [libwebrtc parity inventory](../../design/libwebrtc-parity.md), section [10.6](../../design/libwebrtc-parity.md#106-the-ice-controller-srcp2pbasic_ice_controllerwrapping_active_ice_controllercc-c3-part-6-1002). Requirement C3 part 6.

```cpp
namespace sm::p2p {

struct IceRecheckEvent {
  IceRecheckEvent(IceSwitchReason _reason, int _recheck_delay_ms)
      : reason(_reason), recheck_delay_ms(_recheck_delay_ms) {}
  std::string ToString() const;

  IceSwitchReason reason;
  int recheck_delay_ms;
};

class IceControllerInterface {
 public:
  // This represents the result of a switch call.
  struct SwitchResult {
    // Connection that we should (optionally) switch to.
    std::optional<const Connection*> connection;
    // An optional recheck event for when a Switch() should be attempted again.
    std::optional<IceRecheckEvent> recheck_event;
    // A vector with connection to run ForgetLearnedState on.
    std::vector<const Connection*> connections_to_forget_state_on;
  };

  // This represents the result of a call to GetConnectionToPing.
  struct PingResult {
    PingResult(const Connection* conn, int _recheck_delay_ms)
        : connection(conn ? std::optional<const Connection*>(conn) : std::nullopt),
          recheck_delay_ms(_recheck_delay_ms) {}
    PingResult(const Connection* conn, TimeDelta recheck_delay)
        : connection(conn ? std::optional<const Connection*>(conn) : std::nullopt),
          recheck_delay_ms(static_cast<int>(recheck_delay.ms())) {}

    TimeDelta recheck_delay() const { return TimeDelta::Millis(recheck_delay_ms); }

    // Connection that we should (optionally) ping.
    const std::optional<const Connection*> connection;
    // The delay before P2PTransportChannel shall call GetConnectionToPing() again.
    const int recheck_delay_ms = 0;
  };

  virtual ~IceControllerInterface() = default;

  // These setters are called when the state of P2PTransportChannel is mutated.
  virtual void SetIceConfig(const IceConfig& config) = 0;
  virtual void SetSelectedConnection(const Connection* selected_connection) = 0;
  virtual void AddConnection(const Connection* connection) = 0;
  virtual void OnConnectionDestroyed(const Connection* connection) = 0;

  // These are all connections that has been added and not destroyed.
  virtual std::span<const Connection* const> GetConnections() const = 0;

  // Is there a pingable connection? Boot-straps pinging: after this returns true GetConnectionToPing() is called
  // periodically.
  virtual bool HasPingableConnection(Timestamp now) const = 0;

  // Selects a connection to Ping, or nullptr if none.
  virtual PingResult GetConnectionToPing(Timestamp now, Timestamp last_ping_sent) = 0;

  // Compute the "STUN_ATTR_USE_CANDIDATE" for `conn`.
  virtual bool GetUseCandidateAttr(const Connection* conn, NominationMode mode, IceMode remote_ice_mode) const = 0;

  // Only to let unit tests simulate pinging by marking a connection pinged.
  virtual const Connection* FindNextPingableConnection(Timestamp now) = 0;
  virtual void MarkConnectionPinged(const Connection* con) = 0;

  // Check if we should switch to `connection`, for IceSwitchReasons that can switch directly i.e without resorting.
  virtual SwitchResult ShouldSwitchConnection(Timestamp now, IceSwitchReason reason, const Connection* connection) = 0;

  // Sort connections and check if we should switch.
  virtual SwitchResult SortAndSwitchConnection(Timestamp now, IceSwitchReason reason) = 0;

  // Prune connections.
  virtual std::vector<const Connection*> PruneConnections() = 0;
};
```

```cpp
namespace sm::p2p {

class ActiveIceControllerInterface {
 public:
  virtual ~ActiveIceControllerInterface() = default;

  // Sets the current ICE configuration.
  virtual void SetIceConfig(const IceConfig& config) = 0;
  // Called when a new connection is added to the ICE transport.
  virtual void OnConnectionAdded(const Connection* connection) = 0;
  // Called when the transport switches that connection in active use.
  virtual void OnConnectionSwitched(const Connection* connection) = 0;
  // Called when a connection is destroyed.
  virtual void OnConnectionDestroyed(const Connection* connection) = 0;
  // Called when a STUN ping has been sent on a connection (not that a response has been received).
  virtual void OnConnectionPinged(const Connection* connection) = 0;
  // Called when the rtt estimate, write state, receiving, connected or nominated of a connection changes.
  virtual void OnConnectionUpdated(const Connection* connection) = 0;
  // Compute "STUN_ATTR_USE_CANDIDATE" for a STUN ping on the given connection.
  virtual bool GetUseCandidateAttribute(const Connection* connection, NominationMode mode,
                                        IceMode remote_ice_mode) const = 0;
  // Called to enque a request to pick and switch to the best available connection.
  virtual void OnSortAndSwitchRequest(Timestamp now, IceSwitchReason reason) = 0;
  // Called to pick and switch to the best available connection immediately.
  virtual void OnImmediateSortAndSwitchRequest(Timestamp now, IceSwitchReason reason) = 0;
  // Called to switch to the given connection immediately without checking for the best available connection.
  virtual bool OnImmediateSwitchRequest(Timestamp now, IceSwitchReason reason, const Connection* selected) = 0;

  // Runs the tasks due at `now` (libwebrtc posts them to the network thread).
  virtual void Process(Timestamp now) = 0;
  // When Process should next run; PlusInfinity if nothing is pending.
  virtual Timestamp NextProcessTime() const = 0;

  // Only for unit tests
  virtual const Connection* FindNextPingableConnection(Timestamp now) = 0;
};

// An active ICE controller may be constructed with the same arguments as a legacy ICE controller, plus the ICE agent
// it interacts with.
```
