# 1.3 Connections: candidate-pair checks

Section 1, *Connectivity*, of [Problems WebRTC solves](../../02-webrtc-problems-solved.md). Problems addressed:

- Choosing a working path -> a connection per candidate pair, with STUN pings, nomination and consent freshness (RFC 7675)

## The issue

Candidates only describe addresses; whether a pair works is learned by trying it. Each local and remote candidate pair is a connection that pings with STUN, tracks whether it can send and receive, estimates its RTT and may be nominated. A connection that stops answering must be noticed within seconds, or the call stays on a dead path; ping too often and the checks flood the network.

## Design

ICE candidate pairs (issue #1000, part of ICE #990, milestone 3): libwebrtc M157's p2p/base/connection.{h,cc} and connection_info.{h,cc} (compare/webrtc/reference/p2p/base/).

A Connection is one candidate pair: a local candidate of its Port and a remote candidate. It runs the pair's connectivity checks (RFC 5245 7, RFC 8445) and keeps its state as libwebrtc does: - Ping() sends a STUN binding request with USERNAME "RFRAG:LFRAG", GOOG-NETWORK-INFO, ICE-CONTROLLING or

```
  ICE-CONTROLLED with the tie-breaker, USE-CANDIDATE or NOMINATION (controlling side), PRIORITY (the local
  candidate's priority with the peer-reflexive type preference), MESSAGE-INTEGRITY and FINGERPRINT. Each check is
  sent once (no STUN retransmissions) and its transaction is dropped after kConnectionResponseTimeout (60 s).
  With GOOG-PING announced by both sides (enable_goog_ping, off by default) an unchanged request goes as a short
  GOOG-PING instead.
```

- An incoming check (already checked by the Port: username, MESSAGE-INTEGRITY) marks the pair receiving and is

```
  answered with XOR-MAPPED-ADDRESS; the ICE role conflict rule (RFC 5245 7.2.1.1) answers 487 or raises the role
  conflict signal. On the controlled side USE-CANDIDATE or NOMINATION nominates the pair.
```

- A response (MESSAGE-INTEGRITY checked with the remote password) makes the pair writable, updates the RTT (a 3:1

```
  moving average, 3 s before the first sample) and, if its XOR-MAPPED-ADDRESS is not a known local candidate,
  turns the local candidate into a peer-reflexive one (RFC 5245 7.1.3.2.1). A 487 raises the role conflict signal;
  400 and other non-recoverable errors fail the pair and destroy it.
```

- Write states: writable after a response; unreliable after kConnectionWriteConnectFailures (5) unanswered checks

```
  and kConnectionWriteConnectTimeout (5 s) without a response; timed out after kConnectionWriteTimeout (15 s)
  without one. This is consent freshness (RFC 7675) as libwebrtc implements it: a pair whose checks go unanswered
  stops being writable. Receiving: something arrived within the receiving timeout (2.5 s), or the last check was
  answered.
```

- Dead: received nothing for kDeadConnectionReceiveTimeout (30 s) with a check outstanding as long, or for the

```
  dead_connection_timeout field trial (30 s) with none; never received anything and pruned for
  kMinConnectionLifetime (10 s). UpdateState then destroys it.
```

The library's time model replaces libwebrtc's network thread and clock: calls that read the clock there take `now` here (as there, times at or before Timestamp 0 mean "never", so the caller's clock starts after 0) (a received packet's arrival time), nothing posts a task, and the Port runs the pair's STUN transactions in Port::Process. libwebrtc's DestroyConnectionAsync posts the delete; here the Port deletes the connection at its next Process (NextProcessTime says when).

Not here: the DTLS-in-STUN piggyback (M157 has it behind a field trial that is off; see dtls_transport.h), the RTC event log (ice_logger), and the Unix-epoch conversion of the stats' timestamps (they stay in the caller's time base). The RTT estimate is libwebrtc's EventBasedExponentialMovingAverage (rtc_base/numerics/), and the rate trackers are BitrateTracker's RateStatistics (rtc_base/bitrate_tracker.cc: a 1 s window, kBpsScale 8000) used directly.

libwebrtc M157's p2p/base/connection_info.{h,cc} (compare/webrtc/reference/p2p/base/): a candidate pair's state and statistics (RTCIceCandidatePairStats).

STUN transactions (issue #997, part of ICE #990, milestone 3): libwebrtc M157's p2p/base/stun_request.{h,cc} (compare/webrtc/reference/p2p/base/).

A StunRequest is one outstanding request; the StunRequestManager keeps them by transaction id, retransmits them on libwebrtc's schedule and matches responses to them: - first send after the given delay, then resends 250, 500, 1000, 2000,

```
  4000, 8000, 8000 and 8000 ms apart (STUN_INITIAL_RTO = 250 ms doubling,
  capped at STUN_MAX_RTO = 8000 ms), 9 sends in all
  (STUN_MAX_RETRANSMISSIONS = 8), and the timeout 8000 ms after the last
  send: 39750 ms after the first (STUN_TOTAL_TIMEOUT);
```

- a response is checked as CheckResponse does: by transaction id, then

```
  MESSAGE-INTEGRITY with the request's password when the request requires
  authentication (revalidated if it was checked with another password),
  unauthenticated TURN responses refused except 401 and 300 errors, and a
  response with unknown comprehension-required attributes discarded and the
  transaction failed (RFC 5389 7.3.3 and 7.3.4).
```

The library's time model replaces libwebrtc's task queue: nothing reads a clock or posts a task. The manager's owner passes `now` in and calls Process(now) at NextProcessTime(); the request callbacks get `now`.

Transaction ids guard against spoofed responses (RFC 5389 section 6), so they must be unpredictable on a real call. The manager refuses to send a request while STUN's random-bytes hook is not installed (sm/p2p/stun.h, SetStunCrypto; InstallStunCryptoFromTls() in sm/p2p/stun_crypto_tls.h installs BoringSSL's), unless a test allows the fixed-seed fallback.

libwebrtc M157 counterpart: `p2p/base/connection.{h,cc}`, `connection_info.h`. Differences from libwebrtc: [libwebrtc parity inventory](../../design/libwebrtc-parity.md), section [10.4](../../design/libwebrtc-parity.md#104-connections-candidate-pairs-and-their-checks-srcp2pconnectioncc-c3-part-4-1000). Requirement C3 part 4. Ping intervals, RTT estimation, the writable/receiving timeouts and the consent checks follow `connection.cc` and `p2p_constants.h`.

```cpp
namespace sm::p2p {

// https://w3c.github.io/webrtc-stats/#dom-rtcstatsicecandidatepairstate
enum class IceCandidatePairState {
  WAITING = 0,  // Check has not been performed, Waiting pair on CL.
  IN_PROGRESS,  // Check has been sent, transaction is in progress.
  SUCCEEDED,    // Check already done, produced a successful result.
  FAILED,       // Check for this connection failed.
  // According to spec there should also be a frozen state, but nothing is ever frozen.
};

struct ConnectionInfo {
  bool best_connection = false;            // Is this the best connection we have?
  bool writable = false;                   // Has this connection received a STUN response?
  bool receiving = false;                  // Has this connection received anything?
  bool timeout = false;                    // Has this connection timed out?
  size_t rtt = 0;                          // The STUN RTT for this connection.
  size_t sent_discarded_bytes = 0;         // Outgoing bytes discarded on socket errors.

  size_t sent_bytes_second = 0;            // Bps over the last measurement interval.

  const void* key = nullptr;  // Identifies the connection.
```

```cpp
namespace sm::p2p {

class StunRequest;

inline constexpr int kAllRequestsForTest = 0;
inline constexpr int STUN_TOTAL_TIMEOUT = 39750;  // ms
// stun_request.cc's schedule.
inline constexpr int STUN_INITIAL_RTO = 250;        // ms
inline constexpr int STUN_MAX_RETRANSMISSIONS = 8;  // 9 sends in all.
inline constexpr int STUN_MAX_RTO = 8000;           // ms

// The send callback must not add or remove requests (it runs inside a send).
class StunRequestManager {
 public:
  using SendPacketFn = std::function<void(Timestamp now, std::span<const uint8_t>, StunRequest*)>;

  explicit StunRequestManager(SendPacketFn send_packet);
  ~StunRequestManager();
  StunRequestManager(const StunRequestManager&) = delete;
  StunRequestManager& operator=(const StunRequestManager&) = delete;

  // Starts `request`: sent at `now + delay` (now if zero), then resent until a
  // response or the timeout. Returns false, and drops the request, when
  // transaction ids would be predictable (see the top of the file).
  bool Send(Timestamp now, std::unique_ptr<StunRequest> request, TimeDelta delay = TimeDelta::Zero());

  // Sends, resends and times out what is due by `now`.
  void Process(Timestamp now);
  // When Process next has something to do; PlusInfinity when idle.
  Timestamp NextProcessTime() const;

  // Sends every request of `msg_type` (or all) again now and restarts its
  // schedule.
  void FlushForTest(Timestamp now, int msg_type);
  bool HasRequestForTest(int msg_type) const;

  // Drops every request without calling it back.
  void Clear();

  // Matches a response to its request and calls the request back. True if it
  // was a response to one of ours that was accepted.
  bool CheckResponse(Timestamp now, StunMessage* msg);
  // The same from the bytes: looks the transaction id up first, then parses.
  bool CheckResponse(Timestamp now, std::span<const uint8_t> payload);

  bool empty() const { return requests_.empty(); }

  // Allows the fixed-seed transaction ids of sm/p2p/stun.h when no crypto is
  // installed. Tests only.
  void set_allow_predictable_ids_for_testing(bool allow) { allow_predictable_ids_ = allow; }

};

class StunRequest {
 public:
  // A binding-less request with an invalid type and a generated id, as
  // libwebrtc's first constructor; subclasses fill mutable_msg().
  explicit StunRequest(StunRequestManager& manager);
  StunRequest(StunRequestManager& manager, std::unique_ptr<StunMessage> message);
  virtual ~StunRequest();
  StunRequest(const StunRequest&) = delete;
  StunRequest& operator=(const StunRequest&) = delete;

  StunRequestManager* manager() { return &manager_; }
  const std::string& id() const { return msg_->transaction_id(); }
  uint32_t reduced_transaction_id() const { return msg_->reduced_transaction_id(); }
  int type() const { return msg_->type(); }
  const StunMessage* msg() const { return msg_.get(); }
  // Time since the latest send.
  TimeDelta Elapsed(Timestamp now) const { return now - tstamp_; }
  void SetAuthenticationRequired(bool val) { authentication_required_ = val; }
  bool AuthenticationRequired() const { return authentication_required_; }

 protected:
  friend class StunRequestManager;
  StunMessage* mutable_msg() { return msg_.get(); }

  virtual void OnResponse(Timestamp /*now*/, StunMessage* /*response*/) {}
  virtual void OnErrorResponse(Timestamp /*now*/, StunMessage* /*response*/) {}
  virtual void OnTimeout(Timestamp /*now*/) {}
  // Called after each send; the base counts sends and decides the timeout.
  virtual void OnSent(Timestamp now);
  // Delay to the next send: 0 before the first, then the backoff.
  virtual int resend_delay() const;
  void set_timed_out() { timeout_ = true; }

};

}  // namespace sm::p2p
```

**End-to-end test** (sender -> simulated network -> receiver, `tests/e2e/`):


Two ports ping each other through the emulated network: the pair goes from unreachable to writable, receiving and then nominated; it loses writability when pings stop and is pruned when consent expires.
