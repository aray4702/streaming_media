# 1.6 The ICE agent (P2PTransportChannel)

Section 1, *Connectivity*, of [Problems WebRTC solves](../../02-webrtc-problems-solved.md). Problems addressed:

- One transport per media bundle that finds, checks and keeps a path -> `P2PTransportChannel`

## The issue

ICE is the whole procedure: gather candidates, exchange them (possibly while gathering goes on), check pairs, nominate one, keep it alive with consent checks and recover when it fails. One object per transport has to run it with the roles, role conflicts, timers and trickle handling that browsers' ICE implementations do, or interoperability with a browser breaks.

## Design

The ICE agent (issue #1002 part 2, C3 part 6, ICE #990, milestone 3): libwebrtc M157's p2p/base/p2p_transport_channel.{h,cc} (compare/webrtc/reference/p2p/base/).

P2PTransportChannel is one ICE transport (one component of one m-section). It gathers local candidates through a PortAllocator session, pairs them with the remote candidates it is given (and with peer-reflexive ones learned from incoming checks), and lets its ICE controller (WrappingActiveIceController over BasicIceController, #1028) choose which pairs to ping, which one to select, and which to prune, as libwebrtc does: - MaybeStartGathering takes a pooled session with the local credentials, or creates one; new credentials (an ICE

```
  restart) stop the old sessions, prune their ports, and gather again. The gathering state follows the session
  (complete when allocation is done, unless gathering continually).
```

- Every ready port is paired with every remembered remote candidate of the current generation (ports of older

```
  sessions are pruned and pair only with candidates that arrived through them). A remote candidate of an older
  generation (by ufrag) is dropped; one with an unknown ufrag is held for the next generation.
```

- Pings carry USE-CANDIDATE by the controller's nomination rule (semi-aggressive by default) or, with renomination

```
  on both sides, NOMINATION with a counter that grows with each switch. The controlled side switches to a pair the
  remote nominated, or that data arrived on.
```

- State: INIT until a connection exists, FAILED when none is active, COMPLETED when each network has at most one

```
  active connection, CONNECTING otherwise; the standard RTCIceTransportState (new, checking, connected,
  disconnected, failed) beside it. Writable follows the selected connection (or a presumed-writable TURN-TURN
  pair); receiving is any connection receiving. When every connection has timed out they are all destroyed.
```

- With continual gathering, networks without a connection are regathered every

```
  regather_on_failed_networks_interval (5 min) once pinging has started.
```

- SendPacket sends on the selected connection while it is writable, unreliable or presumed writable (ENOTCONN

```
  otherwise); received data is handed up whichever connection it came on.
```

Same constants and defaults as libwebrtc: IceConfig with the receiving timeout (2.5 s), backup ping interval (25 s), stable writable ping interval (2.5 s), regather interval (5 min), receiving switching delay (1 s), presume_writable_when_fully_relayed on, gather once, and the WebRTC-IceFieldTrials defaults.

The library's time model replaces libwebrtc's network thread and clock. Calls that read the clock there take `now` here; the channel runs its allocator sessions (and through them the ports and their connections' STUN transactions), its controller's queued tasks and the regathering timer in Process(now), at NextProcessTime(). The calls that take no `now` (SetRemoteIceParameters, SetIceConfig, and the signals of sockets and connections) use the time of the last call that had one (a connection's signal: the later of that and its last receive), so the owner calls Process(now) before handing the sockets their packets at `now`, as the test bench's loops do.

Not here (see docs/design/libwebrtc-parity.md 10.9): hostname (mDNS) candidates and their DNS resolution (the library's addresses carry no hostname, as 10.3), the local network access permission (always granted), the STUN dictionary (GOOG-DELTA; no library API writes it), the DTLS-in-STUN piggyback (off by default in M157), the RTC event log, the field trial strings (WebRTC-IceFieldTrials and the others are at their defaults; a caller may pass IceFieldTrials), socket options from field trials (WebRTC-DscpFieldTrial, -SetSocketReceiveBuffer, -RFC8888CongestionControlFeedback: off by default), and candidate stats in GetStats.

libwebrtc M157's p2p/base/ice_agent_interface.h (compare/webrtc/reference/p2p/base/): what an active ICE controller asks of the ICE transport (P2PTransportChannel implements it, #1002). Calls that send, switch or update state take `now` (the library's time model).

The ICE transport interface the DTLS transport runs over (#1006): the declarations of libwebrtc's p2p/base/ice_transport_internal.h at M157 (compare/webrtc/reference/). P2PTransportChannel implements it with #1002; until then the tests use a fake (tests/unit/p2p_dtls/fake_ice_transport.h, after p2p/test/ fake_ice_transport.h).

IceConfig carries libwebrtc's defaults (*_or_default) and IsValid since #1002's ICE controller part.

The candidate methods and signals (AddRemoteCandidate, gathering, the selected candidate pair, GetStats) came with P2PTransportChannel (#1002 part 2). Left out: the STUN dictionary (GetDictionaryWriter and its callbacks; no library API writes the dictionary) and the DTLS-in-STUN piggyback callbacks, which M157 has behind a field trial that is off by default (IceConfig::dtls_handshake_in_stun is kept, false). IceTransportStats has no candidate_stats_list (the allocator session's GetCandidateStatsFromReadyPorts is not ported).

libwebrtc M157's p2p/base/transport_description.h and transport_info.h (compare/webrtc/reference/p2p/base/): the ICE role, mode and credentials that the port, the connection (#1000) and the ICE transport share, and the transport half of a session description (#1062, C6 part 1): ice-ufrag/ice-pwd, ice-options, ice-lite, the DTLS fingerprint and a=setup, per m= section (TransportInfo). One definition, so the port, the ICE transport interface (#1006), the DTLS transport and the SDP layer (sm/pc/session_description.h) can be included together.

Differences from libwebrtc: - ConnectionRole is an enum class (kNone, kActive, ...) rather than CONNECTIONROLE_*; SdpType (api/jsep.h) is here

```
  too, because the DTLS role negotiation (sm/p2p/dtls_transport.h) needs it without the SDP layer.
```

- IceParameters::Parse/Validate return the error text (empty when valid) instead of RTCError(SYNTAX_ERROR).

A packet transport: what ICE gives the DTLS layer and DTLS gives the RTP/SCTP layers (#1006, part of DTLS-SRTP #991, milestone 3). libwebrtc's p2p/base/packet_transport_internal.{h,cc} at M157 (compare/webrtc/reference/), with the library's time model: nothing reads a clock or starts a thread, so SendPacket and the state signals carry `now`, and callbacks run on the caller's thread inside the call that caused them.

Differences from libwebrtc, none of them on the wire: - Callback lists are std::function lists removed by tag (CallbackList), as in sm/p2p/async_packet_socket.h. - The network route (network_route(), the route-changed signal) came with P2PTransportChannel (#1002); NetworkRoute

```
  is in sm/p2p/network_route.h.
```

- No SequenceChecker: like every module in the library, a transport is used from one thread at a time.

libwebrtc M157 counterpart: `p2p/base/{p2p_transport_channel,ice_agent_interface,ice_transport_internal,transport_description,packet_transport_internal}.{h,cc}`. Differences from libwebrtc: [libwebrtc parity inventory](../../design/libwebrtc-parity.md), section [10.9](../../design/libwebrtc-parity.md#109-the-ice-agent-srcp2pp2p_transport_channelcc-c3-part-6-1002). Requirement C3 part 6. Gathering, role conflicts, nomination, consent, continual gathering and IceConfig as `PeerConnection` sets them.

namespace sm::p2p {

class IceAgentInterface {
 public:
  virtual ~IceAgentInterface() = default;

  // Get the time when the last ping was sent.
  virtual Timestamp GetLastPingSent() const = 0;
  // Get the ICE role of this ICE agent.
  virtual IceRole GetIceRole() const = 0;
  // Called when a pingable connection first becomes available.
  virtual void OnStartedPinging() = 0;
  // Update the state of all available connections.
  virtual void UpdateConnectionStates(Timestamp now) = 0;
  // Update the internal state of the ICE agent, at the end of a sequence of actions.
  virtual void UpdateState(Timestamp now) = 0;
  // Reset the given connections to a state of newly connected connections (STATE_WRITE_INIT, not receiving, no pending
  // requests, a reset RTT estimate), keeping connected, the remote candidate and the statistics. SignalStateChange is
  // not triggered.
  virtual void ForgetLearnedStateForConnections(std::span<const Connection* const> connections) = 0;
  // Send a STUN ping request for the given connection.
  virtual void SendPingRequest(Timestamp now, const Connection* connection) = 0;
  // Switch the transport to use the given connection.
  virtual void SwitchSelectedConnection(Timestamp now, const Connection* new_connection, IceSwitchReason reason) = 0;
  // Prune away the given connections. Returns true if pruning is permitted and successfully performed.
  virtual bool PruneConnections(Timestamp now, std::span<const Connection* const> connections) = 0;

// ICE Nomination mode.
enum class NominationMode {
  REGULAR,         // Nominate once per ICE restart (Not implemented yet).
  AGGRESSIVE,      // Nominate every connection except that it will behave as if REGULAR when the remote is an
                   // ICE-LITE endpoint.
  SEMI_AGGRESSIVE  // Our current implementation of the nomination algorithm. The details are described in
                   // P2PTransportChannel.

// IceConfig (#1002): unset fields take the *_or_default values, libwebrtc's constants in sm/p2p/p2p_constants.h.
// IceConfigFromRtcConfiguration (below) is the RTCConfiguration constructor (#1002 part 3).
struct IceConfig {
  // The ICE connection receiving timeout value.
  std::optional<TimeDelta> receiving_timeout;
  // Time interval to ping a backup connection when the ICE channel is strongly connected.
  std::optional<TimeDelta> backup_connection_ping_interval;
  ContinualGatheringPolicy continual_gathering_policy = ContinualGatheringPolicy::kGatherOnce;
  bool gather_continually() const { return continual_gathering_policy == ContinualGatheringPolicy::kGatherContinually; }
  // Whether we should prioritize Relay/Relay candidate when nothing is writable yet.
  bool prioritize_most_likely_candidate_pairs = false;
  // Writable connections are pinged at a slower rate once stablized.
  std::optional<TimeDelta> stable_writable_connection_ping_interval;
  // Presume TURN-to-TURN candidate pairs will succeed, even before a binding response is received.
  bool presume_writable_when_fully_relayed = false;
  // Surface candidates gathered but filtered out when the candidate filter is widened.
  bool surface_ice_candidates_on_ice_transport_type_changed = false;
  // Interval to check on all networks and to perform ICE regathering on any active network having no connection.
  std::optional<TimeDelta> regather_on_failed_networks_interval;
  // The time period in which we will not switch the selected connection when a new connection becomes receiving but
  // the selected connection is not, in case the selected connection may become receiving soon.
  std::optional<TimeDelta> receiving_switching_delay;
  // Default nomination mode if the remote does not support renomination.
  NominationMode default_nomination_mode = NominationMode::SEMI_AGGRESSIVE;
  // The ping interval of a pair that is writable and receiving (strong connectivity); kStrongPingInterval if unset.

  std::optional<TimeDelta> ice_unwritable_timeout;

  std::optional<int> ice_unwritable_min_checks;

  std::optional<TimeDelta> ice_inactive_timeout;
  // The interval at which STUN candidates resend STUN binding requests to keep NAT bindings open.
  std::optional<TimeDelta> stun_keepalive_interval;
  std::optional<AdapterType> network_preference;

  kPfSrtpBypass = 0x01,  // An encrypted SRTP packet; DTLS passes it through untouched.

// rtc_base/callback_list.h's CallbackList with tags: receivers may be added or removed while it sends, and a
// receiver removed during a send is not called after that.
template <typename... Args>
class TaggedCallbackList {
 public:
  using Callback = std::function<void(Args...)>;
  void Add(const void* tag, Callback cb) { receivers_.push_back({tag, std::make_shared<Callback>(std::move(cb))}); }
  void Remove(const void* tag) {
    std::erase_if(receivers_, [tag](const Entry& e) {
      if (e.tag != tag) return false;
      *e.cb = nullptr;
      return true;
    });
  }
  void Send(Args... args) {
    const std::vector<Entry> snapshot = receivers_;
    for (const Entry& e : snapshot) {
      if (*e.cb) (*e.cb)(args...);
    }
  }
  bool empty() const { return receivers_.empty(); }

  };
  std::vector<Entry> receivers_;
};

class PacketTransportInternal {
 public:
  using StateCallback = std::function<void(PacketTransportInternal*, Timestamp now)>;

  virtual bool receiving() const = 0;
