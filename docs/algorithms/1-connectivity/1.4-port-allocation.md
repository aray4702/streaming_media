# 1.4 Port allocation

Section 1, *Connectivity*, of [Problems WebRTC solves](../../02-webrtc-problems-solved.md). Problems addressed:

- Gathering candidates on every interface -> network enumeration and a port allocator that opens ports as networks appear: UDP, server-reflexive, relay and ICE-TCP (RFC 6544) host candidates

## The issue

A machine can have a Wi-Fi interface, a cellular one, a VPN and several addresses on each, and they change during a call. Something has to enumerate the networks, open ports on them, gather candidates in the right order and start again when a network appears or goes, while honouring the application's filters and TURN servers.

## Design

The list of networks a port allocator gathers on (issue #1001, part of ICE #990, milestone 3): libwebrtc M157's NetworkManager and NetworkManagerBase from rtc_base/network.{h,cc} (compare/webrtc/reference/rtc_base/).

NetworkManager is the interface BasicPortAllocator reads: the current networks, the "any address" networks (used when adapter enumeration is disabled or yields nothing), the enumeration permission, the default local addresses, and a networks-changed signal. NetworkManagerBase keeps the list as libwebrtc does: MergeNetworkList consolidates networks by key (name%prefix/len), keeps the Network objects of networks it already knew (so their ids and the ports bound on them stay valid), marks the ones that went away inactive, sorts by adapter type, then RFC 3484 precedence of the best IP, then key, and gives the networks preferences 127, 126, ... in that order. Ids start at 1.

An OS network monitor (C11, C12) implements NetworkManager over the host's interfaces later. StaticNetworkManager is the emulated network's: the caller adds and removes interfaces (an address, a name, an adapter type), as libwebrtc's test FakeNetworkManager does, and the networks change when it does.

Differences from libwebrtc: no mDNS responder (GetMdnsResponder is always null, so the allocator never obfuscates host candidates), no VPN list or MAC-based VPN detection, no network preference or slice, and the network thread is the caller's: the networks-changed signal runs inside the call that changed them (StartUpdating, MergeNetworkList). StaticNetworkManager follows rtc_base/fake_network.h's FakeNetworkManager (prefix lengths /24 and /64, "test<N>" names, the first-update rule).

The port allocator interface (issue #1001, part of ICE #990, milestone 3): libwebrtc M157's p2p/base/port_allocator.{h,cc} (compare/webrtc/reference/ p2p/base/).

A PortAllocator holds the ICE configuration shared by the transports of a call (STUN and TURN servers, the flags, the port range, the step delay, the candidate filter, the ICE tie-breaker) and makes a PortAllocatorSession per transport component; the session gathers ports and candidates and signals them. A pool of sessions can start gathering before the transports exist (candidate_pool_size): TakePooledSession hands one over with the transport's ICE credentials. Same constants and defaults as libwebrtc: flags 0, the step delay 1 s (kDefaultStepDelay), at most 5 IPv6 networks, the candidate filter CF_ALL, no port range.

Differences from libwebrtc: - No thread checks: the library's calls run on the caller's thread. - No mDNS obfuscation (MdnsObfuscationEnabled is false), so

```
  SanitizeCandidate only removes related addresses, as libwebrtc without an
  mDNS responder; no TurnCustomizer, TLS certificate verifier or TURN
  logging id (C4).
```

- PortPrunePolicy and VpnPreference are api/transport/enums.h's

```
  (sm/p2p/transport_enums.h, shared with the ICE controller).
```

The port allocator ICE uses (issue #1001, part of ICE #990, milestone 3): libwebrtc M157's p2p/client/basic_port_allocator.{h,cc} (compare/webrtc/reference/p2p/client/).

A BasicPortAllocatorSession gathers on every network the NetworkManager lists, after filtering them as libwebrtc does (the ignore mask, by default loopback; the VPN preference; link-local and costly networks when the flags say so; at most max_ipv6_networks IPv6 networks, picked by adapter type), with one AllocationSequence per network. A sequence runs its phases a step delay apart (1 s by default): UDP (a UDPPort for the host candidate, and a StunPort for the server-reflexive ones, or the UDPPort itself gathers both on a shared socket with PORTALLOCATOR_ENABLE_SHARED_SOCKET), then relay (TURN), then TCP (a TCPPort, sm/p2p/tcp_port.h, #1151: a passive host candidate on a listen socket, or an active one when allow_tcp_listen is off), and completes. IPv6 networks are used only with PORTALLOCATOR_ENABLE_IPV6 (and IPv6 Wi-Fi only with ..._IPV6_ON_WIFI). Phases another sequence already covers on the same network and best IP are skipped. Each port's candidates are signalled through the candidate filter (a public host address passes as reflexive), the port is "ready" once it has a pairable candidate (port ready, then KeepAliveUntilPruned), and the session reports allocation done when every sequence and port has finished.

When the networks change, sequences on networks that went away are stopped and their ports pruned (candidates removed), and new networks are gathered on (continual gathering: ICE regathering is signalled). RegatherOnFailedNetworks does the same for networks whose ports have no connection. ClearGettingPorts stops the current gathering (ports still gathering count as failed), StopGettingPorts stops for good.

The library's time model replaces libwebrtc's network thread: the session queues what libwebrtc posts and runs it, and its ports, in Process(now); the owner calls Process at NextProcessTime(). Ports are owned by the session; a port that destroys itself is deleted at the end of the Process call that destroyed it.

Differences from libwebrtc: - Relay ports come from the RelayPortFactoryInterface the caller gives, or by default a

```
  TurnPortFactory (sm/p2p/turn_port.h, #1031), as libwebrtc; TURN to the
  server is UDP only until C4 part 4.
  PortConfiguration does not add DTLS TURN servers as STUN servers
  (ProtocolType has no PROTO_DTLS until C4).
```

- No mDNS (host candidates are never obfuscated), no local network access

```
  permission, no VPN list, no field trials (WebRTC-UseTurnServerAsStunServer
  is at its default, enabled).
```

- PeerConnection's settings (shared socket, IPv6, IPv6 on Wi-Fi, the

```
  minimum step delay) are applied by ConfigureAsPeerConnection
  (port_allocator.h), not by the allocator itself, as in libwebrtc.
```

libwebrtc M157's p2p/base/ice_credentials_iterator.{h,cc} (compare/webrtc/reference/p2p/base/): hands out the pooled sessions' ICE credentials (PortAllocator::GetPooledIceCredentials), newest first, then random ones (#1002).

ICE-TCP host candidates (issue #1151, milestone 3): libwebrtc M157's p2p/base/tcp_port.{h,cc} (compare/webrtc/reference/p2p/base/).

A TCPPort gathers one TCP host candidate on its network (RFC 6544): with a listen socket (the allocator's allow_tcp_listen, true by default) a passive candidate at the listener's address; without one an active candidate at the network's best IP and the discard port 9. It makes a TCPConnection per remote candidate: - Outgoing (a remote passive candidate, or a remote candidate without a

```
  tcptype and a real port): the connection opens a client socket to it
  (AsyncTcpSocket, the RFC 4571 2-byte length framing RFC 6544 uses) and is
  not connected until the socket's connect event. A remote active candidate
  (not peer-reflexive) gets no connection: it connects to us.
```

- Incoming: the listener's accepted sockets wait in the port, which answers

```
  the STUN traffic on them as for an unknown address (Port::OnReadPacket
  with PROTO_TCP); the ICE agent then makes a peer-reflexive active remote
  candidate and a connection that takes the accepted socket over.
```

- A connection whose socket closes is "pretending to be writable"

```
  (tcp_port.cc's state diagram): an outgoing one reconnects on its next send
  or check, and the connection is destroyed if it is still pretending
  kConnectionWriteConnectTimeout (5 s) after the close. Data is refused
  until the first STUN response on the new socket. A socket bound to an
  address of another network is dropped (OnConnect), except loopback or the
  any address.
```

- Options set on the port (TCP_NODELAY, set by the constructor) go to the

```
  accepted sockets; client sockets get TCP_NODELAY from the factory.
```

The library's time model replaces libwebrtc's network thread: calls that may send take `now`; the owner calls Process(now) at NextProcessTime(), which runs what libwebrtc posts (the deferred FailAndPrune of a connection whose socket could not be made) and the reconnection timeouts. Socket close events carry no time, so a close is timed at the latest time the port has seen (`now` of its last call or packet), as TurnPort does.

Not ported: SSLTCP's fake TLS (OPT_TLS_FAKE; the factory makes no such socket, 10.8), and the RTC_DCHECKs on threads.

libwebrtc M157 counterpart: `rtc_base/network.{h,cc}` (the manager part), `p2p/base/{port_allocator,basic_port_allocator}.{h,cc}`, `p2p/base/ice_credentials_iterator.{h,cc}`, `p2p/base/tcp_port.{h,cc}` (`TCPPort`, `TCPConnection`). Differences from libwebrtc: [libwebrtc parity inventory](../../design/libwebrtc-parity.md), section [10.5](../../design/libwebrtc-parity.md#105-port-allocation-srcp2pnetwork_managerport_allocatorbasic_port_allocatorcc-c3-part-5-1001), [10.22](../../design/libwebrtc-parity.md#1022-ice-tcp-host-candidates-srcp2ptcp_portcc-1151). Requirement C3 part 5. The allocator is set up as `PeerConnection` sets it up (flags, candidate filter, pool size, TURN servers, TCP candidates on as `kTcpCandidatePolicyEnabled`). Its last phase makes a `TCPPort` (#1151): a passive host candidate on a listen socket (`allow_tcp_listen`, on by default) or an active one at the discard port, with libwebrtc's reconnect state machine over 1.9's sockets. Other tests: `sm_ice_compare`'s ICE-TCP table (UDP blocked at one or both endpoints; #1151).

// rtc_base/network.h: by default, loopback networks are ignored.
inline constexpr int kDefaultNetworkIgnoreMask = ADAPTER_TYPE_LOOPBACK;

class NetworkManager {
 public:
  enum EnumerationPermission {
    ENUMERATION_ALLOWED,  // Adapter enumeration is allowed (0 networks means none).
    ENUMERATION_BLOCKED,  // Disabled: GetAnyAddressNetworks() should be used.
  };

  virtual ~NetworkManager() = default;

  // Starts and stops watching the networks. The networks-changed signal
  // follows the first StartUpdating once the list is known.
  virtual void StartUpdating() = 0;
  virtual void StopUpdating() = 0;
  // The current networks, sorted and with preferences set. Valid until the
  // next change.
  virtual std::vector<const Network*> GetNetworks() const = 0;
  virtual EnumerationPermission enumeration_permission() const { return ENUMERATION_ALLOWED; }
  // An IPv4 and an IPv6 network bound to the any address, type
  // ADAPTER_TYPE_ANY, whose default local address is this manager's.
  virtual std::vector<const Network*> GetAnyAddressNetworks() = 0;
  // The address the OS would route public traffic from. False if unknown.
  virtual bool GetDefaultLocalAddress(IpFamily family, IpAddress* ipaddr) const = 0;

  void SubscribeNetworksChanged(const void* tag, std::function<void()> cb) {
    networks_changed_.emplace_back(tag, std::move(cb));
  }
  void UnsubscribeNetworksChanged(const void* tag) {
    std::erase_if(networks_changed_, [tag](const auto& e) { return e.first == tag; });
  }
  void NotifyNetworksChanged() {
    auto cbs = networks_changed_;  // A receiver may unsubscribe while it runs.
    for (auto& [tag, cb] : cbs) cb();
  }

};

## Test methods

**Unit tests** (deterministic, no network):

- `P2pNetworkManager`: 2 cases in the source (not run by tools/run_all.sh)
- `P2pPortAllocator`: 7 cases in the source (not run by tools/run_all.sh)

- `P2pIceCredentialsIterator`: 3 cases in the source (not run by tools/run_all.sh)
- `P2pTcpPort`: 11 cases in the source (not run by tools/run_all.sh)

**End-to-end test** (sender -> simulated network -> receiver, `tests/e2e/`):


An allocator session on a multi-homed emulated host opens a port per network and per protocol (UDP, STUN, TURN, TCP), reports candidates as they are gathered and gathers again when a network is added or removed (continual gathering). Two TCP ports connect over the emulated TCP (active to passive, an accepted socket handed to the connection), reconnect after the far end closes, and drop a socket bound to another network's address.
