# 7.3 Video orientation (CVO)

Section 7, *Video quality and processing*, of [Problems WebRTC solves](../../02-webrtc-problems-solved.md). Problems addressed:

- Rotated camera -> video orientation header extension (CVO)

## The issue

Phone and tablet camera sensors are mounted in landscape. When the user holds the device upright, or turns it during the call, the captured image is rotated relative to what should be displayed. Rotating every frame before encoding costs CPU and memory bandwidth, and it changes the encoded resolution (portrait versus landscape) mid-stream, which forces new keyframes and encoder reconfiguration on every turn. Front cameras are also mirrored. The receiver needs to know the capture orientation for each frame to display it upright.

## Design

"urn:3gpp:video-orientation").

A phone sensor is mounted in landscape; when the user holds the phone upright the captured frames are rotated. Instead of rotating every frame before encoding (costly, and it changes the encoded resolution mid-stream), the sender signals the rotation in a one-byte RTP header extension:  0 0 0 0 C F R1 R0  (C: back camera, F: horizontal flip, R: rotation in 90-degree steps, clockwise). The receiver rotates at render time.

See the [libwebrtc parity inventory](../../design/libwebrtc-parity.md#7-video-quality-and-processing) for the differences from libwebrtc. On the wire (issue #567), rtp::RtpSender writes the extension as libwebrtc's RTPSenderVideo::AddRtpHeaderExtensions (rtp_sender_video.cc:388-408) when it is mapped: on the last packet of a keyframe, of a frame whose rotation changed, and of every frame whose rotation is not 0, with the byte of ConvertVideoRotationToCVOByte (rtp_cvo.h; the camera and flip bits 0). The packetizer leaves the room as last_packet_reduction_len. rtp::RtpReceiver gives each frame the rotation of its last packet, 0 without the extension (rtp_video_stream_receiver2.cc:797-802, 1108). Session::SendVideo takes it as EncodedVideoFrame::rotation. 

## Implementation skeleton

Files: [include/sm/video/orientation.h](../../../include/sm/video/orientation.h), [src/video/orientation.cc](../../../src/video/orientation.cc).

Public API (generated from the header; private members omitted):

```cpp
namespace sm::video {

enum class Rotation : uint8_t { k0 = 0, k90 = 1, k180 = 2, k270 = 3 };

struct VideoOrientation {
  Rotation rotation = Rotation::k0;
  bool flip = false;         // Horizontal mirror (applied before rotation).
  bool back_camera = false;
};

uint8_t EncodeCvo(const VideoOrientation& o);
VideoOrientation DecodeCvo(uint8_t b);
// Returns the frame mirrored (if flip) and rotated clockwise.
I420Frame ApplyOrientation(const I420Frame& in, const VideoOrientation& o);
// Inverse: what the camera captured, given the upright image.
VideoOrientation Inverse(const VideoOrientation& o);

}  // namespace sm::video
```

## Test methods

**Unit tests** (deterministic, no network):

- `Orientation`: `CvoByteAndRotation`, `InverseRestoresAllEightCases`

**End-to-end test** (sender -> simulated network -> receiver, `tests/e2e/`):

- `E2E_Orientation`: `RotatingPhoneRendersUpright`

A phone rotating through all 4 rotations, with and without mirroring; frames carry CVO in a real RTP header extension and the receiver must show the scene upright, bit-exact.
