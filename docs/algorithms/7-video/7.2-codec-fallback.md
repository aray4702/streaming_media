# 7.2 Hardware -> software codec fallback

Section 7, *Video quality and processing*, of [Problems WebRTC solves](../../02-webrtc-problems-solved.md). Problems addressed:

- Decoder errors or corrupt bitstream -> decoder fallback (hardware -> software)
- Hardware encoder failure -> automatic fallback to a software encoder

## The issue

Hardware encoders and decoders (MediaCodec, VideoToolbox, V4L2) are essential for battery life and performance, but they fail in practice. Some refuse certain resolutions, fail to initialize when another app holds the hardware, return errors under memory pressure, or have device-specific bugs. If the application simply stops when the hardware codec fails, the call goes black. Switching to software must happen quickly, but not on a single transient error. The new codec has no reference state, so a keyframe is needed immediately. Hardware should perhaps be retried later without flapping back and forth.

## Design

Hardware encoders/decoders (MediaCodec, VideoToolbox, V4L2 M2M) can fail to initialize, reject a resolution, or start returning errors under memory pressure. The controller switches to the software implementation when initialization fails, after `max_consecutive_errors` errors in a row, or when the error rate over the last `window` frames exceeds `max_error_rate`. Every switch requests a keyframe (the new codec has no reference state). Optionally the hardware path is retried after `retry_hardware_after`, with exponential back-off if it fails again.

See the [libwebrtc parity inventory](../../design/libwebrtc-parity.md#7-video-quality-and-processing) for the differences from libwebrtc. 

## Implementation skeleton

Files: [include/sm/video/codec_fallback.h](../../../include/sm/video/codec_fallback.h), [src/video/codec_fallback.cc](../../../src/video/codec_fallback.cc).

Public API (generated from the header; private members omitted):

```cpp
namespace sm::video {

enum class CodecImpl { kHardware, kSoftware };

struct CodecFallbackConfig {
  int max_consecutive_errors = 3;
  size_t window = 100;
  double max_error_rate = 0.10;
  TimeDelta retry_hardware_after = TimeDelta::Seconds(60);  // Zero: never.
  EventSink* events = nullptr;
};

struct CodecFallbackStats {
  uint64_t frames = 0, errors = 0, fallbacks = 0, hardware_retries = 0;
};

class CodecFallbackController : public MetricsSource {
 public:
  explicit CodecFallbackController(CodecFallbackConfig cfg = {}) : cfg_(cfg), retry_after_(cfg.retry_hardware_after) {}
  void OnInitResult(bool ok, Timestamp now);
  void OnFrameResult(bool ok, Timestamp now);
  // Call periodically: may move back to hardware after the retry delay.
  void Process(Timestamp now);
  CodecImpl active() const { return impl_; }
  bool TakeKeyframeRequest();
  const CodecFallbackStats& stats() const { return stats_; }
  void ExportMetrics(MetricsWriter& w) const override;

};

}  // namespace sm::video
```

## Test methods

**Unit tests** (deterministic, no network):

- `CodecFallback`: `InitFailureAndConsecutiveErrors`, `ErrorRateAndRetryBackoff`

**End-to-end test** (sender -> simulated network -> receiver, `tests/e2e/`):

- `E2E_CodecFallback`: `HardwareFailureMidCallKeepsVideoFlowing`

A hardware encoder that starts failing 30% of frames at 10 s; checks that exactly one fallback happens with one keyframe, and that the longest gap between encoded frames stays small.
