# 7.2 Hardware -> software encoder fallback

Section 7, *Video quality and processing*, of [Problems WebRTC solves](../../02-webrtc-problems-solved.md). Problems addressed:

- Hardware encoder failure -> automatic fallback to a software encoder

## The issue

Hardware encoders and decoders (MediaCodec, VideoToolbox, V4L2) are essential for battery life and performance, but they fail in practice. Some refuse certain resolutions, fail to initialize when another app holds the hardware, return errors under memory pressure, or have device-specific bugs. If the application simply stops when the hardware codec fails, the call goes black. Switching to software must happen quickly, but not on a single transient error. The new codec has no reference state, so a keyframe is needed immediately. Hardware should perhaps be retried later without flapping back and forth.

## Design

A port of libwebrtc's VideoEncoderSoftwareFallbackWrapper (api/video_codecs/video_encoder_software_fallback_wrapper.cc). The app runs the codecs (program.md 0.1), so it hands this wrapper its two encoders through `FallbackEncoder`, and the wrapper decides which one is used, as libwebrtc's does.

InitEncode tries the forced fallback first (below), then the main (hardware) encoder. If the main encoder fails, other than with kSimulcastParametersNotSupported, the software encoder is initialized instead; if that fails too, the main encoder's error is returned. An encode that returns kFallbackSoftware from the main encoder moves to the software encoder, releases the main one, and the same frame is encoded again by the software encoder (EncodeWithMainEncoder). Any other error is returned as is: there is no error counting and no error rate. Nothing switches back on a timer: the state lasts until Release(), and the next InitEncode tries the main encoder again. On every switch the new encoder gets the last rates, RTT and packet loss (PrimeEncoder). A freshly initialized encoder starts with a keyframe, so the wrapper requests none.

Forced fallback: the field trial WebRTC-Video-EncoderFallbackSettings (`resolution_threshold_px`), or, without it, WebRTC-VP8-Forced-Fallback-Encoder-v2 ("Enabled-<min_pixels>,<max_pixels>, <min_bps>", VP8 single stream only), uses the software encoder for every resolution up to `max_pixels` (default 320x240). Both are off by default, as in libwebrtc. GetEncoderInfo merges the two encoders' info as libwebrtc does.

Not ported: the temporal-layer based forced switch (`prefer_temporal_support`), because temporal layers are removed (#572), and the OnLossNotification replay (the library has no encoder loss-notification input). Decoder fallback (video_decoder_software_fallback_wrapper.cc) is not in compare/webrtc/reference/ and is not provided.

See the [libwebrtc parity inventory](../../design/libwebrtc-parity.md#7-video-quality-and-processing) for the differences from libwebrtc. Since #573 a port of libwebrtc's VideoEncoderSoftwareFallbackWrapper; the header comment above lists what is not ported.

## Implementation skeleton

Files: [include/sm/video/codec_fallback.h](../../../include/sm/video/codec_fallback.h), [src/video/codec_fallback.cc](../../../src/video/codec_fallback.cc).

Public API (generated from the header; private members omitted):

```cpp
namespace sm::video {

// The WEBRTC_VIDEO_CODEC_* results the wrapper tells apart.
enum class EncoderStatus { kOk, kError, kFallbackSoftware, kSimulcastParametersNotSupported };

// VideoCodec, the fields the wrapper reads.
struct EncoderCodecSettings {
  int width = 0;
  int height = 0;
  bool vp8 = false;
  int simulcast_streams = 1;
};

// VideoEncoder::EncoderInfo, the fields the wrapper reads or merges.
struct FallbackEncoderInfo {
  int requested_resolution_alignment = 1;
  bool apply_alignment_to_all_simulcast_layers = false;
  std::optional<size_t> max_pixels_per_frame;
  int min_pixels_per_frame = 320 * 180;  // ScalingSettings, kDefaultMinPixelsPerFrame.
  bool supports_native_handle = false;
};

struct EncoderRates {
  DataRate bitrate = DataRate::Zero();
  double framerate_fps = 0;
};

// One of the app's encoders, as the wrapper drives it.
class FallbackEncoder {
 public:
  virtual ~FallbackEncoder() = default;
  virtual EncoderStatus InitEncode(const EncoderCodecSettings& settings) = 0;
  virtual void Release() = 0;
  virtual void SetRates(const EncoderRates& rates) = 0;
  virtual void OnRttUpdate(TimeDelta rtt) = 0;
  virtual void OnPacketLossRateUpdate(float packet_loss_rate) = 0;
  virtual FallbackEncoderInfo GetEncoderInfo() const = 0;
};

struct CodecFallbackConfig {
  // WebRTC-Video-EncoderFallbackSettings/resolution_threshold_px:N/; unset is off.
  std::optional<int> resolution_threshold_px;
  // WebRTC-VP8-Forced-Fallback-Encoder-v2's value; off unless it starts with "Enabled".
  std::string vp8_forced_fallback;
  EventSink* events = nullptr;
};

// libwebrtc's ForcedFallbackParams (resolution-based switch only).
struct ForcedFallbackParams {
  bool vp8_specific_resolution_switch = false;
  int min_pixels = 320 * 180;
  int max_pixels = 320 * 240;
  bool SupportsResolutionBasedSwitch(const EncoderCodecSettings& codec) const;
};

// ParseFallbackParamsFromFieldTrials; `main_info` is the main encoder's info.
std::optional<ForcedFallbackParams> ParseForcedFallbackParams(const CodecFallbackConfig& cfg,
                                                              const FallbackEncoderInfo& main_info);

enum class EncoderState { kUninitialized, kMainEncoderUsed, kFallbackDueToFailure, kForcedFallback };

struct CodecFallbackStats {
  uint64_t frames = 0, errors = 0, fallbacks = 0, forced_fallbacks = 0;
};

class CodecFallbackController : public MetricsSource {
 public:
  // `sw` is the software fallback, `hw` the main encoder; both outlive this.
  CodecFallbackController(CodecFallbackConfig cfg, FallbackEncoder& sw, FallbackEncoder& hw);

  EncoderStatus InitEncode(const EncoderCodecSettings& settings, Timestamp now);
  void Release();

  // The encoder to encode the next frame with; nullptr while uninitialized
  // (libwebrtc's Encode returns WEBRTC_VIDEO_CODEC_ERROR then).
  FallbackEncoder* current();
  // Report the result of encoding a frame with current(). Returns true when
  // the main encoder asked for the software fallback and it initialized: the
  // app then encodes the same frame with current() (the fallback), converted
  // to I420 at the codec size unless the fallback supports native handles.
  // Otherwise the app keeps `status` as the frame's result.
  bool OnEncodeResult(EncoderStatus status, Timestamp now);

  void SetRates(const EncoderRates& rates);
  void OnRttUpdate(TimeDelta rtt);
  void OnPacketLossRateUpdate(float packet_loss_rate);
  FallbackEncoderInfo GetEncoderInfo() const;

  EncoderState state() const { return state_; }
  bool IsFallbackActive() const {
    return state_ == EncoderState::kForcedFallback || state_ == EncoderState::kFallbackDueToFailure;
  }
  const std::optional<ForcedFallbackParams>& forced_params() const { return forced_; }
  const CodecFallbackStats& stats() const { return stats_; }
  void ExportMetrics(MetricsWriter& w) const override;

};

}  // namespace sm::video
```

## Test methods

**Unit tests** (deterministic, no network):

- `CodecFallback`: `InitFailureAndConsecutiveErrors`, `ErrorRateAndRetryBackoff`

**End-to-end test** (sender -> simulated network -> receiver, `tests/e2e/`):

- `E2E_CodecFallback`: `HardwareFailureMidCallKeepsVideoFlowing`

A hardware encoder that starts failing at 10 s and asks for the software fallback on its 10th error; checks that plain errors don't switch, that exactly one fallback happens, that the fallback is primed with the last rate and starts with a keyframe, and that the frame that asked is encoded by the fallback, so the longest gap between encoded frames stays small.

## Verification notes

#573 replaced the library's own CodecFallbackController (3 consecutive errors, 10% error rate over 100 frames, hardware retry after 60 s with back-off, none of which libwebrtc has) with the port. libwebrtc's unit test file is not in reference/; CodecFallback.* covers the wrapper's cases from the source: init failure, both failing, simulcast parameters, fallback request only from the main encoder, failed fallback init, release and re-init, forced fallback by resolution and by the VP8 trial with its parameter checks, and the info merge.
