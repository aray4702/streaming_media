# 7.5 Codec negotiation

Section 7, *Video quality and processing*, of [Problems WebRTC solves](../../02-webrtc-problems-solved.md). Problems addressed:

- Many codecs and devices -> codec negotiation (VP8, VP9, H.264, AV1, H.265 recently)

## The issue

Every endpoint supports a different set of codecs (VP8, VP9, H.264, AV1, H.265), each in profiles and levels with different capabilities. Some are hardware accelerated on a given device. Two endpoints must agree on what to use, in a single offer/answer exchange. Some rules are codec specific: two H.264 entries with different profiles are different codecs, but different levels just limit resolution and frame rate. Getting this wrong means black video (sending a profile the decoder cannot handle), poor battery (picking software when hardware was available) or mismatched payload types (packets sent with numbers the other side maps to a different codec).

## Design

rules from RFC 6184 / RFC 7741 / VP9 and AV1 RTP payload formats).

The answerer keeps offered codecs it supports, in its own preference order (hardware-accelerated codecs first by default), reusing the offerer's payload types. Codec identity rules:

```
  H.264  same profile (from profile-level-id) and packetization-mode;
         the answered level is the lower of the two
  VP9    same profile-id (default 0)
  AV1    same profile (default 0)
  VP8    name match
```

RTCP feedback (nack, nack pli, ccm fir, transport-cc, goog-remb) is the intersection. RTX entries (apt=) are answered for each kept codec.

See the [libwebrtc parity inventory](../../design/libwebrtc-parity.md#7-video-quality-and-processing) for the differences from libwebrtc. 

## Implementation skeleton

Files: [include/sm/video/codec_negotiation.h](../../../include/sm/video/codec_negotiation.h), [src/video/codec_negotiation.cc](../../../src/video/codec_negotiation.cc).

Public API (generated from the header; private members omitted):

```cpp
namespace sm::video {

struct CodecCapability {
  std::string name;  // "VP8", "VP9", "H264", "AV1", "H265", "rtx"
  int payload_type = 0;
  std::map<std::string, std::string> params;  // fmtp
  std::vector<std::string> feedback;          // rtcp-fb
  bool hardware = false;
};

enum class H264Profile { kConstrainedBaseline, kBaseline, kMain, kHigh, kConstrainedHigh, kUnknown };

struct H264ProfileLevel {
  H264Profile profile = H264Profile::kUnknown;
  int level_idc = 0;  // e.g. 31 = level 3.1
};

std::optional<H264ProfileLevel> ParseH264ProfileLevelId(const std::string& hex6);
std::string H264ProfileLevelIdString(const H264ProfileLevel& pl);
bool IsSameCodec(const CodecCapability& a, const CodecCapability& b);

struct NegotiationOptions {
  bool prefer_hardware = true;
};

// Returns the answer (codec list with payload types from the offer).
std::vector<CodecCapability> NegotiateCodecs(const std::vector<CodecCapability>& offer,
                                             const std::vector<CodecCapability>& local,
                                             NegotiationOptions opts = {});

}  // namespace sm::video
```
