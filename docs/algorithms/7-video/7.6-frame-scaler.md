# 7.6 Resolution scaling and aspect handling

Section 7, *Video quality and processing*, of [Problems WebRTC solves](../../02-webrtc-problems-solved.md). Problems addressed:

- Frame size and aspect changes -> resolution adaptation and scaling mid-stream

## The issue

Adaptation changes the encoded resolution mid-call (for bandwidth, CPU, quality or simulcast layer), and displays come in arbitrary sizes and aspect ratios: a 4:3 camera in a 16:9 tile, a portrait phone in a landscape grid. Frames must be scaled on both sides. Cheap scaling (nearest-neighbour or skipping pixels) aliases fine detail into moiré and jagged edges, and mismatched aspect handling stretches faces. The scaler is also one of the most CPU-intensive steps on small devices, so quality and cost both matter.

## Design

Mid-stream resolution changes (from bandwidth/CPU adaptation or simulcast layers) need a scaler on both sides: the sender downscales before encoding, the receiver upscales for display. Downscaling uses an area (box) filter, which integrates every source pixel and so does not alias; upscaling uses bilinear interpolation. Aspect-ratio changes are handled by centre cropping (fill) or letterboxing (fit) on 2-pixel boundaries so chroma stays aligned.

See the [libwebrtc parity inventory](../../design/libwebrtc-parity.md#7-video-quality-and-processing) for the differences from libwebrtc. Portable scalar code, about 1.7 ms per 720p frame on the reference machine; a SIMD library (libyuv) is the natural drop-in for production.

## Implementation skeleton

Files: [include/sm/video/frame_scaler.h](../../../include/sm/video/frame_scaler.h), [src/video/frame_scaler.cc](../../../src/video/frame_scaler.cc).

Public API (generated from the header; private members omitted):

```cpp
namespace sm::video {

enum class AspectMode { kStretch, kCrop, kLetterbox };

// Scales a whole frame to w x h (box filter when shrinking, bilinear when
// enlarging, per axis).
I420Frame Scale(const I420Frame& in, int w, int h);
// Fits `in` into w x h with the given aspect handling.
I420Frame ScaleToFit(const I420Frame& in, int w, int h, AspectMode mode);
// Crops a rectangle (x, y, w, h); coordinates rounded down to even.
I420Frame Crop(const I420Frame& in, int x, int y, int w, int h);

}  // namespace sm::video
```

## Test methods

**Unit tests** (deterministic, no network):

- `FrameScaler`: `DownUpRoundTripQuality`, `BoxFilterPreservesMeanAndAspectModes`

**End-to-end test** (sender -> simulated network -> receiver, `tests/e2e/`):

- `E2E_FrameScaler`: `AdaptationLadderQualityAndAspect`

720p frames down-scaled along the adaptation ladder and up-scaled back for display (PSNR per step), plus a 4:3 camera shown in a 16:9 tile with crop and letterbox.

Throughput benchmarks have a speed budget (ns per item, or a minimum real-time factor for media processing); quality benchmarks rerun an end-to-end scenario and gate its outcome. A benchmark passes only if every requirement holds.
