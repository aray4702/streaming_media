# 4.3 Audio target delay estimation (DelayManager)

Section 4, *Jitter, reordering and timing*, of [Problems WebRTC solves](../../02-webrtc-problems-solved.md). Problems addressed:

- Variable packet arrival (audio) -> NetEq adaptive jitter buffer

## The issue

An audio jitter buffer must hold enough audio to absorb variation in packet arrival time, but every millisecond buffered is a millisecond of conversational delay. Above about 150 ms one-way delay, people start talking over each other. A fixed size is wrong in both directions: too small and late packets cause dropouts, too large and the call feels sluggish even on a good network.

The right size is a statistic of recent network behaviour, such as the delay that 95% of packets beat. It must rise quickly when jitter starts (or dropouts begin at once) and fall slowly (or the buffer oscillates and audio speeds up and slows down audibly). Jitter must also be measured relative to the fastest recent packet, since the clocks are not synchronized and only delay variation is observable.

## Design

Each packet's relative delay is its transit time minus the smallest transit seen in the last `history` window: how much later than the fastest recent packet it arrived. Relative delays go into a histogram with exponential forgetting; the target playout delay is the `quantile` of that histogram, so the buffer grows quickly when jitter rises and decays slowly when the network calms down.

See the [libwebrtc parity inventory](../../design/libwebrtc-parity.md#4-jitter-and-timing) for the differences from libwebrtc. A histogram with forgetting factor 0.983 per packet: rising jitter is learned within a few packets, while falling jitter takes several seconds, so the buffer does not oscillate.

## Implementation skeleton

Files: [include/sm/timing/delay_manager.h](../../../include/sm/timing/delay_manager.h), [src/timing/delay_manager.cc](../../../src/timing/delay_manager.cc).

Public API (generated from the header; private members omitted):

```cpp
namespace sm::timing {

struct DelayManagerConfig {
  double quantile = 0.95;
  double forget_factor = 0.983;   // Per packet.
  int bucket_ms = 10;
  int max_delay_ms = 2000;
  int min_delay_ms = 0;
  TimeDelta history = TimeDelta::Seconds(2);
  int initial_target_ms = 60;
};

class DelayManager : public MetricsSource {
 public:
  explicit DelayManager(DelayManagerConfig cfg = {});
  // Returns the relative delay of this packet in ms.
  std::optional<double> Update(uint32_t rtp_ts, int sample_rate, Timestamp arrival);
  // Target delay rounded up to whole packets of `packet_ms`.
  int TargetDelayMs() const { return target_ms_; }
  void SetPacketDurationMs(int ms) { packet_ms_ = ms; }
  void SetMinimumDelayMs(int ms) { cfg_.min_delay_ms = ms; }
  void Reset();
  void ExportMetrics(MetricsWriter& w) const override;

};

}  // namespace sm::timing
```
