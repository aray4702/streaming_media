# 4.7 Clock drift estimation and compensation

Section 4, *Jitter, reordering and timing*, of [Problems WebRTC solves](../../02-webrtc-problems-solved.md). Problems addressed:

- Clock drift between sender and receiver -> sample-rate drift compensation in the audio device module

## The issue

The sender's and receiver's audio clocks are separate crystals with tolerances of tens to hundreds of ppm. At 200 ppm, the sender produces 12 ms more (or less) audio per minute than the receiver plays. Over a long call the jitter buffer slowly fills until latency becomes unacceptable, or drains until it underruns every few seconds. The drift is far smaller than network jitter, so it cannot be seen packet by packet. It only shows up as a slow trend that must be estimated robustly and compensated without audible pitch changes.

## Design

RlsLineFit: recursive least squares fit y = a*x + b with forgetting; used by the timestamp extrapolator, the drift estimator and RTP->NTP mapping.

ClockDriftEstimator: the sender's media clock and the receiver's clock tick at slightly different rates (crystals are typically within +-50-100 ppm). Transit time = arrival - rtp_ts/rate then grows linearly with slope = drift. Jitter only ever adds delay, so the estimator takes the minimum transit in each window (the lower envelope) and fits a line through those minima. That is far less noisy than fitting raw arrivals.

DriftCompensator: an asynchronous sample-rate converter with a continuously variable ratio (cubic Hermite interpolation with phase kept across calls) plus a PI controller that steers the ratio so a playout buffer stays at its target level.

Using the per-window minimum transit time (lower envelope) instead of every packet makes the drift fit almost immune to jitter. The resampler ratio is limited to +-0.5%.

Public API (generated from the header; private members omitted):

```cpp
namespace sm::timing {

class RlsLineFit {
 public:
  explicit RlsLineFit(double forgetting = 1.0) : lambda_(forgetting) { Reset(); }
  void Reset();
  void Update(double x, double y);
  double slope() const { return w_[0]; }
  double intercept() const { return w_[1]; }
  double Predict(double x) const { return w_[0] * x + w_[1]; }
  uint64_t samples() const { return n_; }

};

struct ClockDriftConfig {
  TimeDelta window = TimeDelta::Seconds(1);  // Minimum-transit window.
  int min_windows = 5;
};

class ClockDriftEstimator : public MetricsSource {
 public:
  explicit ClockDriftEstimator(ClockDriftConfig cfg = {}) : cfg_(cfg) {}
  void OnPacket(uint32_t rtp_ts, int clock_rate, Timestamp arrival);
  // Receiver clock rate relative to sender, in parts per million.
  // Positive: the sender's clock runs slow (media arrives "late" over time).
  double drift_ppm() const { return drift_ppm_; }
  bool converged() const { return fit_.samples() >= static_cast<uint64_t>(cfg_.min_windows); }
  void ExportMetrics(MetricsWriter& w) const override;

};

// PI gains are per call of UpdateFromLevel (designed for one call per
// 10 ms). With the buffer acting as an integrator of gain 10 ms per update,
// kp = 3e-4 and ki = 2.5e-7 give a ~3 s, near critically damped loop.
struct DriftCompensatorConfig {
  double kp = 3e-4;              // Ratio change per ms of level error.
  double ki = 2.5e-7;            // Integral gain per ms of accumulated error.
  double level_smoothing = 0.05; // EMA on the level (packet sawtooth).
  double max_ratio_dev = 0.005;  // +-0.5%: inaudible pitch change.
};

class DriftCompensator : public MetricsSource {
 public:
  explicit DriftCompensator(DriftCompensatorConfig cfg = {}) : cfg_(cfg) {}
  // ratio = output samples per input sample.
  void SetRatio(double r) { ratio_ = r; }
  double ratio() const { return ratio_; }
  // Updates the ratio from the playout buffer level error (ms).
  void UpdateFromLevel(double level_ms, double target_ms);
  // Resamples `in`, appending to `out`. Phase is preserved across calls.
  void Process(std::span<const float> in, std::vector<float>& out);
  void ExportMetrics(MetricsWriter& w) const override;

};

}  // namespace sm::timing
```

## Verification notes

Defect found: the first PI gains gave a ~500 s time constant (slow oscillation, 15.8 ms error). Retuned from the plant model (the buffer integrates at 10 ms per update) to a ~3 s, near critically damped loop, with an EMA on the packet-granular level: the error fell to 1.8 ms.
