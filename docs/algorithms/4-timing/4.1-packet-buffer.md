# 4.1 Packet buffer: reordering, de-duplication, frame assembly

Section 4, *Jitter, reordering and timing*, of [Problems WebRTC solves](../../02-webrtc-problems-solved.md). Problems addressed:

- Out-of-order packets -> sequence-number reordering in the packet buffer
- Duplicate packets -> dedup by sequence number

## The issue

UDP gives no ordering or uniqueness guarantee. Packets of one frame can arrive out of order (per-packet load balancing, Wi-Fi retransmissions, multi-path), duplicated (link-layer retries, mirroring) or interleaved with packets of other frames. A depacketizer that assumes in-order delivery will build corrupt frames or drop good ones. Sequence numbers are 16 bits and wrap every 65 536 packets (a few minutes of video), so "older" and "newer" must be decided on a circle, not by plain comparison.

## Design

Packets are stored by unwrapped sequence number in a bounded window. After each insert the buffer checks whether the packet completed a frame: a run of consecutive sequence numbers with the same RTP timestamp that starts with a frame-start packet and ends with the marker bit. (A frame may open with several start packets, e.g. H.264 parameter sets before the IDR slice: it starts at the first of the contiguous packets that share its timestamp.) Complete frames are returned immediately (possibly out of order; the frame scheduler orders them by decodability). Duplicates and packets older than the window are rejected and counted.

See the [libwebrtc parity inventory](../../design/libwebrtc-parity.md#4-jitter-and-timing) for the differences from libwebrtc. Frame boundaries come from the packetizer's start flag and the RTP marker bit; frames may complete out of order and are ordered later by decodability (3.5) and the frame scheduler (7.7). Version 2 (under `keyframe v2`, issue #76 group 6) sizes the buffer as libwebrtc's PacketBuffer: 512 slots doubling to 2048 when another unassembled packet maps to a slot, a clear plus a keyframe request when it is full at 2048, and a restart when a packet is 1024 behind the lowest sequence number. Packets leave at frame assembly rather than at ClearTo after decode, so slots free earlier than in libwebrtc.

## Implementation skeleton

Files: [include/sm/timing/packet_buffer.h](../../../include/sm/timing/packet_buffer.h), [src/timing/packet_buffer.cc](../../../src/timing/packet_buffer.cc).

Public API (generated from the header; private members omitted):

```cpp
namespace sm::timing {

enum class InsertResult { kInserted, kDuplicate, kTooOld, kBufferCleared };

struct AssembledFrame {
  int64_t first_seq = 0;  // Unwrapped.
  int64_t last_seq = 0;
  uint32_t timestamp = 0;
  std::vector<RtpPacket> packets;
  Timestamp last_arrival;
  size_t size_bytes() const;
};

struct PacketBufferConfig {
  size_t window = 2048;  // Packets of history kept for reordering and dedup.
  // 1 = the bounded window above. 2 = libwebrtc's `video_coding::PacketBuffer`
  // sizing (packet_buffer.cc, #76): the buffer starts at `start_size` slots and
  // doubles up to `max_size` when a slot is taken by another sequence number;
  // when it is full at `max_size` it is cleared and the caller asks for a
  // keyframe (`kBufferCleared`); a packet `max_size / 2` or more behind the
  // lowest sequence number seen restarts the buffer.
  int version = 1;
  size_t start_size = 512;
  size_t max_size = 2048;
  EventSink* events = nullptr;
};

struct PacketBufferStats {
  uint64_t inserted = 0;
  uint64_t duplicates = 0;
  uint64_t too_old = 0;
  uint64_t cleared = 0;          // v2: the buffer was full at max_size and was cleared.
  uint64_t padding = 0;          // Padding-only packets that held a sequence number.
  uint64_t reordered = 0;        // Arrived after a higher sequence number.
  uint64_t frames_assembled = 0;
  Histogram reorder_distance;    // Packets the late packet was behind.
};

class PacketBuffer : public MetricsSource {
 public:
  explicit PacketBuffer(PacketBufferConfig cfg = {});
  // frame_start: the packetizer's "first packet of frame" flag (e.g. VP8 S
  // bit, H.264 FU-A start); the end is the RTP marker bit.
  //
  // `may_continue_frame`: the packet looks like a start but could follow
  // earlier packets of the same frame (an H.264 IDR slice after its SPS and
  // PPS). It then opens the frame only if the packet before it is known to
  // belong to the previous frame; if that one is missing, the buffer waits
  // for it (NACK recovers it) rather than hand over a frame without it.
  InsertResult Insert(RtpPacket p, bool frame_start, Timestamp now, bool may_continue_frame = false);
  // A padding-only packet occupied `seq`: it is received, there is nothing
  // to assemble, and it must not look like a hole (or a duplicate later).
  void NotePadding(uint16_t seq);
  // The sequence number just before `first_seq` that is not a padding-only
  // packet, i.e. the last packet of the preceding frame if it was received.
  int64_t PrecedingMediaSeq(int64_t first_seq) const;
  std::vector<AssembledFrame> PopCompleteFrames();
  size_t capacity() const { return size_; }
  size_t buffered_packets() const { return packets_.size(); }
  const PacketBufferStats& stats() const { return stats_; }
  void ExportMetrics(MetricsWriter& w) const override;

  };
  void TryAssemble(int64_t seq);
  void Trim();
  bool SlotTaken(int64_t seq) const;
  void Clear();

  PacketBufferConfig cfg_;
  SeqNumUnwrapper<uint16_t> unwrapper_;
  std::map<int64_t, Entry> packets_;
  std::set<int64_t> padding_;  // Padding-only sequence numbers within the window.
  std::set<int64_t> done_;  // Sequence numbers already delivered in frames.
  int64_t highest_ = INT64_MIN;
  size_t size_ = 0;                      // v2: current slot count.
  int64_t first_seq_ = INT64_MIN;        // v2: lowest sequence number seen since the last clear.
  int64_t first_inserted_ = INT64_MIN;  // The first packet ever inserted has no predecessor to wait for.
  std::vector<AssembledFrame> ready_;
  PacketBufferStats stats_;
};

}  // namespace sm::timing
```
