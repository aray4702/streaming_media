# 6.4 Automatic gain control and limiter

Section 6, *Audio quality (APM)*, of [Problems WebRTC solves](../../02-webrtc-problems-solved.md). Problems addressed:

- Volume too quiet, too loud, or clipping -> AGC2 automatic gain control, limiter, clipping predictor

## The issue

Talkers differ by 30 dB or more in level: a quiet speaker far from a laptop versus someone leaning into a headset microphone. Without gain control, listeners constantly adjust their volume, quiet speakers are lost under noise, and loud ones clip, which causes harsh distortion that no later processing can undo.

Fixed gain cannot serve both. Adaptive gain must follow the speech level, not the noise (or it amplifies silence into loud hiss). It must change slowly enough not to "pump", and always guarantee that the output never exceeds full scale, even on a sudden shout.

## Design

and clipping detection.

Limiter: splits each frame into 1 ms sub-blocks, computes the gain that keeps every sub-block's peak under `ceiling_dbfs`, applies it instantly (attack) and recovers with an exponential release, interpolating the gain across each sub-block so there are no zipper artifacts. A final hard clip guarantees the ceiling.

AutomaticGainControl: estimates the speech level (RMS during VAD-active frames, slow EMA) and moves the digital gain toward target_level - speech_level, limited to `max_gain_db` and to `max_gain_change_db_per_s` so the gain never pumps. Gain is frozen in non-speech frames, and capped so the noise floor is not amplified above `max_output_noise_dbfs`. Input clipping is counted and turned into a microphone gain recommendation (the analog part of AGC1/AGC2).

See the [libwebrtc parity inventory](../../design/libwebrtc-parity.md#6-audio-quality) for the differences from libwebrtc. As in AGC2, the adaptive digital gain is never negative and is capped so background noise stays under -50 dBFS; attenuation of hot inputs is left to the limiter and the mic-gain recommendation.

## Implementation skeleton

Files: [include/sm/audio/gain_control.h](../../../include/sm/audio/gain_control.h), [src/audio/gain_control.cc](../../../src/audio/gain_control.cc).

Public API (generated from the header; private members omitted):

```cpp
namespace sm::audio {

struct LimiterConfig {
  int sample_rate = 16000;
  float ceiling_dbfs = -1.0f;
  float release_ms = 60.0f;
};

class Limiter : public MetricsSource {
 public:
  explicit Limiter(LimiterConfig cfg = {});
  void Process(std::span<float> x);
  float current_gain_db() const;
  void ExportMetrics(MetricsWriter& w) const override;

};

struct AgcConfig {
  int sample_rate = 16000;
  float target_level_dbfs = -18.0f;  // Speech RMS target.
  float max_gain_db = 30.0f;
  float max_gain_change_db_per_s = 6.0f;
  float max_output_noise_dbfs = -50.0f;
  float level_time_constant_s = 1.0f;
  LimiterConfig limiter;
};

struct AgcStats {
  uint64_t frames = 0;
  uint64_t speech_frames = 0;
  uint64_t clipped_input_samples = 0;
  float speech_level_dbfs = -90.0f;
  float gain_db = 0;
  float noise_floor_dbfs = -90.0f;
};

class AutomaticGainControl : public MetricsSource {
 public:
  explicit AutomaticGainControl(AgcConfig cfg = {});
  // `speech`: VAD decision for this frame.
  void Process(std::span<float> frame, bool speech);
  float gain_db() const { return gain_db_; }
  // Suggested microphone (analog) gain change in dB; negative if the input
  // is clipping, positive if speech stays very quiet even at max gain.
  float recommended_mic_gain_change_db() const;
  const AgcStats& stats() const { return stats_; }
  void ExportMetrics(MetricsWriter& w) const override;

};

}  // namespace sm::audio
```

## Test methods

**Unit tests** (deterministic, no network):

- `GainControl`: `LimiterNeverExceedsCeiling`, `QuietSpeechReachesTarget`, `NoGainOnSilenceAndClippingRecommendation`

**End-to-end test** (sender -> simulated network -> receiver, `tests/e2e/`):

- `E2E_GainControl`: `NormalizesQuietTalkerLeavesLoudToLimiter`

A quiet talker (~-33 dBFS) for 20 s, then a loud one (+20 dB). Quiet speech must reach -18 dBFS; loud speech must not be amplified and every peak must stay under -1 dBFS.

## Verification notes

The first e2e expectations contradicted the AGC2 design (noise cap, no attenuation) and were rewritten to test those behaviours. A unit test reused a buffer that the limiter had already modified in place.
