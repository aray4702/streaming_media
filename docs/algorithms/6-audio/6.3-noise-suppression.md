# 6.3 Noise suppression

Section 6, *Audio quality (APM)*, of [Problems WebRTC solves](../../02-webrtc-problems-solved.md). Problems addressed:

- Background noise -> NS noise suppression (RNNoise-style ML in some builds)

## The issue

Microphones pick up fans, traffic, keyboards, cafes and car noise. The noise masks speech, tires listeners, and wastes bitrate because the encoder spends bits coding noise faithfully. The noise overlaps speech in frequency, so a fixed filter cannot remove it.

Suppression must estimate the noise spectrum while people are talking, from moments and frequencies where speech is absent, and attenuate each frequency according to how much speech it contains at that moment. Doing this crudely produces "musical noise" (random warbling tones) or muffles and chops the speech, which can sound worse than the original noise.

## Design

10 ms hop, 20 ms sqrt-Hann analysis/synthesis windows (50% overlap, perfect reconstruction), zero-padded FFT. Per frequency bin: - noise PSD: minimum-tracking of the smoothed power spectrum (follows

```
   drops immediately, rises at most `noise_rise_db_per_s`), with a
   speech-presence gate so speech does not leak into the estimate;
```

- a-priori SNR, decision-directed (Ephraim-Malah):

```
       xi = a * G_prev^2 * |X_prev|^2 / N + (1 - a) * max(gamma - 1, 0)
```

- Wiener gain G = xi / (1 + xi), floored at -`max_attenuation_db`. Algorithmic latency: one hop (10 ms).

Ported from compare/webrtc/reference/modules/audio_processing/ns/ with libwebrtc's constants and defaults (ns_common.h, suppression_params.cc): - Filter bank (noise_suppressor.cc): 160-sample frames (10 ms of the

```
   0-8 kHz band) extended with the previous 96 samples to a 256-point
   frame, a hybrid Hann/flat window (kBlocks160w256FirstHalf) applied on
   analysis and on synthesis, overlap-add. Algorithmic delay 96 samples
   (6 ms at 16 kHz).
```

- QuantileNoiseEstimator (quantile_noise_estimator.cc): three interleaved

```
   log-quantile estimates (quantile 0.25, 200-frame periods), density
   adapted step.
```

- NoiseEstimator (noise_estimator.cc): during the first 50 frames the

```
   quantile estimate is mixed with a parametric white/pink noise model;
   afterwards it is updated per bin weighted by the speech probability
   (0.9, or 0.99 while speech is likely, decreases always allowed), plus
   a conservative estimate updated only in pauses.
```

- SignalModelEstimator, PriorSignalModelEstimator, Histograms

```
   (signal_model_estimator.cc, prior_signal_model_estimator.cc,
   histograms.cc): the LRT, spectral flatness and spectral difference
   features, with thresholds and weights re-learnt from 500-frame
   histograms.
```

- SpeechProbabilityEstimator (speech_probability_estimator.cc): the

```
   features through tanh maps into a smoothed prior, combined per bin
   with the LRT.
```

- WienerFilter (wiener_filter.cc): decision-directed prior SNR (0.98),

```
   gain snr / (over_subtraction + snr) floored at the level's minimum
   gain, blended with a spectral-subtraction filter on the parametric
   noise during start-up, and the overall scaling ("attenuation
   adjustment") after 200 frames.
```

- NrFft (ns_fft.cc): the 256-point real DFT is Ooura's fft4g

```
   (common_audio/third_party/ooura/fft_size_256/fft4g.cc, sm/audio/fft4g.h),
   with NrFft's layout and its 2/n scaling of the inverse. ns.cc and
   fft4g.cc build with -ffp-contract=off, as Chromium does, so the output
   is bit-exact with libwebrtc's.
```

- Upper bands (32/48 kHz): delayed by 96 samples and scaled by one gain

```
   from the speech probability and Wiener gain of the top 32 bins of the
   lowest band (ComputeUpperBandsGain).
```

As in AudioProcessingImpl::ProcessCaptureStreamLocked, Analyze() reads the capture before the echo canceller and Process() suppresses after it. Bands are laid out as SplittingFilter's (band b at [b * 160, (b + 1) * 160)). Signals are FloatS16 inside (libwebrtc's scale); the API takes and returns this library's [-1, 1] floats. Mono.

The level defaults to k18dB, libwebrtc's kHigh: what WebRtcVoiceEngine::ApplyOptions sets in a call (media/engine/webrtc_voice_engine.cc). NsConfig's own default is k12dB.

Differences from libwebrtc that remain (catalog.py, #241): - One channel (libwebrtc's multi-channel aggregation takes the minimum

```
   filter and gain over the channels; with one channel that is the
   channel's own).
```

See the [libwebrtc parity inventory](../../design/libwebrtc-parity.md#6-audio-quality) for the differences from libwebrtc. Classic statistical NS (Wiener + decision-directed SNR); an ML suppressor (RNNoise) could be plugged into the same 10 ms interface. `apm v2` (#241): `ns::NoiseSuppressor` ports libwebrtc M157's NS (`modules/audio_processing/ns/`: quantile noise estimator with the parametric white/pink model during start-up, LRT, spectral flatness and spectral difference features with histogram-learnt thresholds, speech probability, decision-directed Wiener filter with the attenuation adjustment, 160-sample frames in a 256-point hybrid Hann/flat filter bank, one gain for the upper bands) at kHigh (18 dB floor, over-subtraction 1.1), the level `WebRtcVoiceEngine::ApplyOptions` sets. It analyzes the capture before the AEC and suppresses after it, as `AudioProcessingImpl` does. The 256-point FFT is Ooura's `fft4g` as `NrFft` runs it (`sm/audio/fft4g.h`, from `common_audio/third_party/ooura/fft_size_256/`), bit-exact with libwebrtc's `WebRtc_rdft` (#241). Remaining difference: mono only.

## Verification notes

The first chain test measured SNR against the raw talker, so the HPF's low-frequency phase shift counted as noise; the reference now goes through the same HPF. NS raises SNR from 7.6 to 12.9 dB. libwebrtc's NS (`apm v2`, #241) on the e2e noise case, measured as `sm_apm_compare` measures both stacks: SNR improvement -0.2 dB (libwebrtc -0.1, v1 +5.3), noise attenuation in pauses 17.9 dB (17.9, v1 16.9), level change in speech -3.2 dB (-2.9, v1 -1.3), delay 6 ms (6, v1 10). Like libwebrtc's, it takes the speech down along with the noise in speech frames, so the SNR against the clean talker does not rise. With `fft4g` in place of `RealFft` (#241) the same four values hold; unit `Ns.Fft4gBitExactWithLibwebrtc` pins the transform to the output of libwebrtc M157's prebuilt `WebRtc_rdft`.
