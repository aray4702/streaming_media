# 6.12 Band splitting

Section 6, *Audio quality (APM)*, of [Problems WebRTC solves](../../02-webrtc-problems-solved.md). Problems addressed:

- Wideband capture (32/48 kHz) through processing designed for 16 kHz -> APM band splitting (QMF, three-band filter bank)

## The issue

Microphones and browsers capture at 32 or 48 kHz, but the speech-specific work in audio processing (echo cancellation, noise suppression) is designed for and cheapest at 16 kHz, where most speech energy is. libwebrtc therefore splits each 10 ms frame into 16 kHz bands, runs AEC3 and NS on the lowest one, applies a simple gain to the upper ones and merges them again.

The split has to keep the bands apart (so the suppression of one band does not leak into another as aliasing) and put the signal back together at its own level without audible artefacts, with as little added delay as possible.

## Design

libwebrtc's `SplittingFilter`, which APM uses at 32 and 48 kHz so that AEC3 and NS can run on the lowest 0-8 kHz band (issue #241; modules/audio_processing/splitting_filter.cc). One 10 ms frame of full-band audio becomes `num_bands()` bands of 160 samples each (16 kHz per band), and back. 16 kHz has one band; APM does not split it.

32 kHz, two bands: the all-pass QMF of common_audio/signal_processing/splitting_filter.c (`WebRtcSpl_AnalysisQMF`, `WebRtcSpl_SynthesisQMF`). Even and odd samples each pass a cascade of three first-order all-pass sections (coefficients 0.0979, 0.5643, 0.8737 and 0.3255, 0.7486, 0.9615); their half sum is the low band and their half difference the high band. Synthesis clamps to the S16 range, as libwebrtc does; on this library's [-1, 1) float scale that is [-1, 32767/32768].

48 kHz, three bands: `ThreeBandFilterBank` (modules/audio_processing/three_band_filter_bank.cc), a DCT-modulated FIR filter bank with a 4-tap polyphase branch of the low-pass prototype per delay (Kaiser window, alpha 3.5, 40 dB stop band, 24 samples of delay at 48 kHz). It does not reconstruct perfectly, as in libwebrtc.

Bands are passed as one span of num_bands() * 160 samples, band b at [b * 160, (b + 1) * 160). Mono, as the rest of this library's APM.

See the [libwebrtc parity inventory](../../design/libwebrtc-parity.md#6-audio-quality) for the differences from libwebrtc. A port of libwebrtc's `SplittingFilter` (issue #241): `modules/audio_processing/splitting_filter.cc`, `three_band_filter_bank.cc` and `common_audio/signal_processing/splitting_filter.c`, with their coefficients. It is the first step of the `apm v2` ports (#240 AEC3, #241 NS), which run on the 0-8 kHz band. Differences: mono only (libwebrtc splits every channel of an `AudioBuffer`), and samples on this library's [-1, 1) scale, so the S16 saturation in the QMF synthesis is at [-1, 32767/32768].

## Implementation skeleton

Files: [include/sm/audio/splitting_filter.h](../../../include/sm/audio/splitting_filter.h), [src/audio/splitting_filter.cc](../../../src/audio/splitting_filter.cc).

Public API (generated from the header; private members omitted):

```cpp
namespace sm::audio {

// libwebrtc's ThreeBandFilterBank: 480 samples (10 ms at 48 kHz) <-> three
// bands of 160.
class ThreeBandFilterBank {
 public:
  static constexpr int kNumBands = 3;
  static constexpr int kFullBandSize = 480;
  static constexpr int kSplitBandSize = kFullBandSize / kNumBands;
  static constexpr int kSparsity = 4;
  static constexpr int kStrideLog2 = 2;
  static constexpr int kStride = 1 << kStrideLog2;
  static constexpr int kNumZeroFilters = 2;
  static constexpr int kFilterSize = 4;
  static constexpr int kMemorySize = kFilterSize * kStride - 1;
  static constexpr int kNumNonZeroFilters = kSparsity * kNumBands - kNumZeroFilters;

  ThreeBandFilterBank();
  // `in` has kFullBandSize samples; `out` has kNumBands * kSplitBandSize.
  void Analysis(std::span<const float> in, std::span<float> out);
  // `in` has kNumBands * kSplitBandSize samples; `out` has kFullBandSize.
  void Synthesis(std::span<const float> in, std::span<float> out);

};

class SplittingFilter : public MetricsSource {
 public:
  static constexpr size_t kSamplesPerBand = 160;

  // `sample_rate` is 32000 (two bands) or 48000 (three bands).
  explicit SplittingFilter(int sample_rate);
  int num_bands() const { return num_bands_; }
  size_t full_band_samples() const { return kSamplesPerBand * static_cast<size_t>(num_bands_); }

  // `fullband` and `bands` both have full_band_samples() samples.
  void Analysis(std::span<const float> fullband, std::span<float> bands);
  void Synthesis(std::span<const float> bands, std::span<float> fullband);

  void ExportMetrics(MetricsWriter& w) const override;

};

}  // namespace sm::audio
```

New in #241's first PR. The two-band analysis matches a direct-form evaluation of `WebRtcSpl_AllPassQMF` to 1e-6 across two frames, and both paths were bit-exact with libwebrtc's own `splitting_filter.c` and `three_band_filter_bank.cc` compiled from `reference/` (the three-band files arrive there with #247; golden values pinned in `SplittingFilter.MatchesLibwebrtcOutput`); level through analysis and synthesis is within 0.002 dB at 32 and 48 kHz on a 0.2-4.2 kHz chirp.
