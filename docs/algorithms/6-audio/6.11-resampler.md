# 6.11 Sample-rate conversion

Section 6, *Audio quality (APM)*, of [Problems WebRTC solves](../../02-webrtc-problems-solved.md). Problems addressed:

- Device sample-rate mismatch -> resampler

## The issue

Audio hardware runs at whatever rate the device prefers: 44.1 kHz on many Macs and USB devices, 48 kHz on most phones, 16 kHz on some embedded codecs and Bluetooth headsets. Processing runs at 16 or 48 kHz, and codecs at their own rates. Converting between rates is unavoidable.

Crude conversion (dropping samples or linear interpolation) folds high frequencies back into the audible band (aliasing) and dulls the sound. Conversion between rates that are not simple multiples, like 44.1 kHz and 48 kHz, needs fractional-ratio resampling that keeps exact sample counts over time.

## Design

(common_audio/resampler/resampler.cc), the fixed-point int16 resampler on the signal processing library's allpass half-band filters and fractional polyphase filters (common_audio/signal_processing/resample_by_2.c, resample_by_2_internal.c, resample.c, resample_48khz.c, resample_fractional.c), with their filter coefficients.

Supports the rate pairs whose reduced ratio is one of libwebrtc's 21 modes (1:1, 1:2, 1:3, 1:4, 1:6, 1:12, 2:3, 2:11, 4:11, 8:11, 11:16, 11:32 and their inverses), mono or interleaved stereo. Some modes take only whole blocks (for example 160 input samples for 1:3), as libwebrtc. Every call returns 0 on success and -1 on failure, as libwebrtc.

Differences from libwebrtc: scratch buffers are members, not malloc'ed per call, and the fixed-point sums wrap explicitly (libwebrtc relies on two's-complement overflow under RTC_NO_SANITIZE, bugs.webrtc.org/5486), so the output is the same, bit for bit, without undefined behaviour. The ARMv7 and MIPS assembly variants are not ported; the portable C ones are. Only the library functions this resampler calls are ported (not the 48 <-> 8 kHz ones, which only other modules use).

(common_audio/resampler/push_resampler.cc), the resampler APM and the audio send and receive paths use: one PushSincResampler per channel over a deinterleaved copy, for int16 or FloatS16 samples, up to 8 channels. Matching rates copy. libwebrtc assumes 10 ms blocks throughout: every call passes the same block sizes, and a new size or channel count re-creates the per-channel resamplers (and their state), as libwebrtc.

Ported from compare/webrtc/reference/common_audio/resampler/ {include/push_resampler.h,push_resampler.cc}. Differences: spans and a channel count in place of InterleavedView/MonoView, and the RTC_DCHECKs are asserts.

See the [libwebrtc parity inventory](../../design/libwebrtc-parity.md#6-audio-quality) for the differences from libwebrtc. The Audio Device Module (platform audio I/O, device switching) is platform glue rather than an algorithm and is out of scope; the resampler is what bridges device and processing rates. libwebrtc's resamplers are ported (issue #565): `SplResampler` is `common_audio/resampler/resampler.cc`, the fixed-point int16 resampler on the signal processing library's allpass half-band and fractional filters (`resample_by_2.c`, `resample_by_2_internal.c`, `resample.c`, `resample_48khz.c`, `resample_fractional.c`), with its 21 modes, block sizes and coefficients; `PushResampler<T>` is `push_resampler.cc`, one `PushSincResampler` per channel (int16 or FloatS16, up to 8 channels), which `PushSincResampler` now also takes as int16, as libwebrtc. Differences: scratch buffers are members rather than malloc'ed per call, and the fixed-point sums wrap explicitly where libwebrtc relies on overflow under RTC_NO_SANITIZE (same output); the ARM/MIPS assembly variants are not ported. The library's v1 Kaiser `Resampler` was retired in #565.

```cpp
namespace sm::audio {

template <typename T>
class PushResampler {
 public:
  // Maximum concurrent number of channels.
  static constexpr size_t kMaxNumberOfChannels = 8;
  // 10 ms at 384 kHz, libwebrtc's kMaxSamplesPerChannel10ms.
  static constexpr size_t kMaxSamplesPerChannel10ms = 384000 / 100;

  PushResampler() = default;
  PushResampler(size_t src_samples_per_channel, size_t dst_samples_per_channel, size_t num_channels) {
    EnsureInitialized(src_samples_per_channel, dst_samples_per_channel, num_channels);
  }

  // Interleaved `src` and `dst` of `num_channels` channels.
  void Resample(std::span<const T> src, std::span<T> dst, size_t num_channels) {
    assert(num_channels > 0);
    const size_t src_spc = src.size() / num_channels;
    const size_t dst_spc = dst.size() / num_channels;
    EnsureInitialized(src_spc, dst_spc, num_channels);
    if (src_spc == dst_spc) {
      // The old resampler provides this memcpy facility in the case of
      // matching sample rates, so reproduce it here for the sinc resampler.
      std::copy(src.begin(), src.end(), dst.begin());
      return;
    }
    // Deinterleave.
    for (size_t ch = 0; ch < num_channels; ++ch)
      for (size_t j = 0; j < src_spc; ++j) source_[ch * src_spc + j] = src[j * num_channels + ch];
    for (size_t ch = 0; ch < num_channels; ++ch)
      resamplers_[ch]->Resample(std::span<const T>(&source_[ch * src_spc], src_spc),
                                std::span<T>(&destination_[ch * dst_spc], dst_spc));
    // Interleave.
    for (size_t ch = 0; ch < num_channels; ++ch)
      for (size_t j = 0; j < dst_spc; ++j) dst[j * num_channels + ch] = destination_[ch * dst_spc + j];
  }

  // For a mono channel, which skips the deinterleaving.
  void Resample(std::span<const T> src, std::span<T> dst) {
    EnsureInitialized(src.size(), dst.size(), 1);
    assert(resamplers_.size() == 1);
    if (src.size() == dst.size()) {
      std::copy(src.begin(), src.end(), dst.begin());
    } else {
      resamplers_[0]->Resample(src, dst);
    }
  }

};

}  // namespace sm::audio
```

## Verification notes

#565: `SplResampler` is bit-exact with libwebrtc's own `resampler.cc` and `resample*.c` compiled from `reference/`, on all 94 rate pairs and channel counts that take 10 ms blocks (8, 11, 16, 22, 32, 44, 48 and 96 kHz, mono and stereo; golden hashes in `SplResampler.BitExactWithLibwebrtc`), and passes the ports of `resampler_unittest.cc` and `push_resampler_unittest.cc`. Earlier, on the v1 resampler: defect found: when decimating, the filter used too few taps (transition band several kHz wide), so a 10 kHz tone aliased at only -36 dB into 48 -> 16 kHz output. Taps now scale with the decimation factor: 91 dB rejection, 107 dB SNR.
