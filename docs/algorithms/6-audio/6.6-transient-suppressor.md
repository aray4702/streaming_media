# 6.6 Transient (keyboard click) suppression

Section 6, *Audio quality (APM)*, of [Problems WebRTC solves](../../02-webrtc-problems-solved.md). Problems addressed:

- Keyboard typing noise -> transient suppressor

## The issue

Keyboard clicks are very common in calls (people take notes while talking) and very distracting: loud, sharp, broadband transients a few milliseconds long. Noise suppression does not remove them, because it relies on noise being steady over time and clicks are the opposite. The challenge is telling a keystroke from the start of a spoken syllable, especially a plosive like "p" or "t". Wrong decisions either let clicks through or clip the beginning of words.

## Design

Keystrokes are short (2-10 ms), broadband, and start abruptly (< 1 ms). Each 1 ms sub-block's energy is compared with a fast (4 ms) envelope of the preceding signal, so even a click right after a word stands out; a jump of more than `onset_db` marks a transient (twice that if the frame is voiced speech, see Vad::voiced(), so vowels are left alone), and the following `hold_ms` are attenuated by `attenuation_db` (instant attack, smooth ramp back to unity).

Off by default (#243): libwebrtc M157's APM has no transient suppression; its `AudioProcessing::Config::TransientSuppression` keeps only `enabled`, false by default and deprecated (api/audio/audio_processing.h). With `enabled` false, Process() leaves the audio as it is; set it to opt in.

See the [libwebrtc parity inventory](../../design/libwebrtc-parity.md#6-audio-quality) for the differences from libwebrtc. Uses Vad::voiced() (this frame's own spectrum, no hangover) to avoid attacking vowels. Keeping it as an opt-in (`enabled = true`) for later stages is an Owner decision (#243, 2026-10-22).

## Implementation skeleton

Files: [include/sm/audio/transient_suppressor.h](../../../include/sm/audio/transient_suppressor.h), [src/audio/transient_suppressor.cc](../../../src/audio/transient_suppressor.cc).

Public API (generated from the header; private members omitted):

```cpp
namespace sm::audio {

struct TransientSuppressorConfig {
  bool enabled = false;  // As libwebrtc's Config::TransientSuppression::enabled.
  int sample_rate = 16000;
  float onset_db = 12.0f;
  float attenuation_db = 20.0f;
  float hold_ms = 12.0f;
  float release_ms = 10.0f;
  float envelope_ms = 4.0f;  // Fast: a keystroke rises in < 1 ms, speech does not.
};

class TransientSuppressor : public MetricsSource {
 public:
  explicit TransientSuppressor(TransientSuppressorConfig cfg = {});
  // `voice`: VAD decision; transients during voiced speech are left alone
  // unless they are very strong (2x onset_db).
  void Process(std::span<float> frame, bool voice);
  uint64_t detected() const { return detected_; }
  void ExportMetrics(MetricsWriter& w) const override;

};

}  // namespace sm::audio
```

## Verification notes

Three defects were found and fixed. (1) The envelope started at 1e-8 and was frozen during transients, so it locked into 'transient' forever. (2) The gain ramped down across the first millisecond, which holds most of a click's energy; attack is now instant. (3) A 60 ms envelope still held the speech level right after a word, so a 4 ms envelope (onset detection) is used. Attenuation in pauses went from 3 dB to 13.5 dB. #243: off by default as libwebrtc (`TransientSuppressor.OffByDefaultAsLibwebrtc`: the audio passes unchanged); the tests that measure it opt in with `enabled = true`.
