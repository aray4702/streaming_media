# 6.8 Voice activity detection

Section 6, *Audio quality (APM)*, of [Problems WebRTC solves](../../02-webrtc-problems-solved.md). Problems addressed:

- Silence wasting bandwidth -> VAD
- Detecting who's talking -> voice activity

## The issue

Several components need to know whether someone is speaking. DTX transmits only during speech, AGC measures level only on speech, the transient suppressor protects speech, and the audio level extension carries its result. Energy alone is not enough: a loud fan has more energy than a soft voice, and the background level changes during a call. A detector that confuses noise with speech wastes bandwidth and amplifies noise. One that misses speech clips the starts and ends of words.

## Design

Ported from compare/webrtc/reference/common_audio/vad/: include/vad.h and vad.cc (`Vad`, `CreateVad`, `VadImpl`) over the `WebRtcVad` fixed-point GMM VAD of webrtc_vad.c and vad_core.c, which is ported bit-exact in `agc1_vad.h` (#242: AGC1's `VoiceActivityDetector` runs it in mode 3). Per 10, 20 or 30 ms frame: six sub-band log energies (vad_filterbank.c), a two-Gaussian speech and noise model per band (vad_gmm.c) whose noise side adapts to the minimum of the last 100 frames (vad_sp.c), a log-likelihood ratio test with the aggressiveness mode's thresholds, and a hangover after speech (vad_core.c `kOverHangMax*`).

Where libwebrtc M157 runs a VAD in a call: its `AudioProcessingImpl` reports no VAD decision (`VoiceDetection` was removed; the statistics it fills are the echo metrics, audio_processing_impl.cc:1434-1449). AGC1's `Agc` runs `VoiceActivityDetector` (agc.cc:96, `agc1::Agc`), AGC2 its RNN VAD (gain_controller2.cc:204, `agc2_rnn_vad.h`), and the Opus encoder its own. `webrtc::Vad` (aggressiveness `kVadNormal`) is libwebrtc's standalone VAD, the one `sm_apm_compare` measures this unit against, so it is the catalog unit and the capture chain's per-frame VAD output. The transient suppressor (an opt-in, #243) reads `VoiceActivityDetector`'s pitch-based probability instead, so a broadband click is not speech.

Differences from libwebrtc (scope, not behaviour): - 48 kHz returns kError: `WebRtcVad` here runs at 8, 16 and 32 kHz

```
   (the 48-to-8 kHz resampler is not ported, see `agc1_vad.h`).
```

- A constructor in place of `CreateVad`; `Reset()` re-initializes the

```
   instance as `VadImpl::Reset` (free, create, init, set mode).
```


See the [libwebrtc parity inventory](../../design/libwebrtc-parity.md#6-audio-quality) for the differences from libwebrtc. `Vad` is libwebrtc M157's `webrtc::Vad` (common_audio/vad/vad.cc, `CreateVad`) over the bit-exact `WebRtcVad` port in `agc1_vad.h` (issue #671); aggressiveness kVadNormal by default, as `sm_apm_compare` runs libwebrtc's. M157's `AudioProcessingImpl` reports no VAD decision, so the capture chain's per-frame VAD output is this `Vad`; the opt-in transient suppressor reads libwebrtc's pitch-based `VoiceActivityDetector` (the probability AGC1 reports), so a click is not taken for speech. 48 kHz is not ported (kError). 

## Implementation skeleton

Files: [include/sm/audio/vad.h](../../../include/sm/audio/vad.h), [src/audio/vad.cc](../../../src/audio/vad.cc).

Public API (generated from the header; private members omitted):

```cpp
namespace sm::audio {

struct VadStats {
  uint64_t frames = 0;
  uint64_t speech_frames = 0;
  uint64_t errors = 0;
};

class Vad : public MetricsSource {
 public:
  enum Aggressiveness { kVadNormal = 0, kVadLowBitrate = 1, kVadAggressive = 2, kVadVeryAggressive = 3 };
  enum Activity { kPassive = 0, kActive = 1, kError = -1 };

  explicit Vad(Aggressiveness aggressiveness = kVadNormal);

  // A VAD decision for one frame. Valid sample rates are 8000, 16000 and
  // 32000 Hz, and the frame must be 10, 20 or 30 ms long.
  Activity VoiceActivity(const int16_t* audio, size_t num_samples, int sample_rate_hz);
  // The same for a float frame in [-1, 1).
  Activity VoiceActivity(std::span<const float> frame, int sample_rate_hz);
  // Resets the VAD state.
  void Reset();

  Aggressiveness aggressiveness() const { return aggressiveness_; }
  const VadStats& stats() const { return stats_; }
  void ExportMetrics(MetricsWriter& w) const override;

};

}  // namespace sm::audio
```

## Test methods

**Unit tests** (deterministic, no network):

- `Vad`: `SpeechVersusNoise`, `NoiseLevelStepIsNotSpeech`

**End-to-end test** (sender -> simulated network -> receiver, `tests/e2e/`):

- `E2E_Vad`: `DetectsSpeechAfterNoiseSuppression`

Speech in noise at about 10 dB SNR after noise suppression; recall and false-positive rate (beyond a 250 ms hangover).

## Verification notes

Issue #671 retired the library's own energy/spectral-flatness detector (v1) for libwebrtc's: `Vad.ApiAsLibwebrtc` (vad_unittest.cc's rates, frame lengths and modes on the wrapper), `Vad.IsWebRtcVadAndResets` (decisions equal `WebRtcVad`'s in every mode, and Reset() restarts it as `VadImpl::Reset`), `Vad.NoiseLevelStepAsLibwebrtc` (a +20 dB step to -26 dBFS white noise reads as speech in kVadNormal because the GMM caps its noise means, vad_core.c `kMaximumNoise`; v1 learned the new floor). E2E_Vad recall 99.7 %, false positives 0 % (libwebrtc kVadNormal in `sm_apm_compare`: 99.9 % and 0.0 % on the same talker behind the high-pass filter). The v1 detector's history: musical noise after NS and a slow noise-floor rise were fixed before #671.
