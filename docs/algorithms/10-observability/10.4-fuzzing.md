# 10.4 Fuzzing of the network parsers

Section 10, *Observability*, of [Problems WebRTC solves](../../02-webrtc-problems-solved.md). Problems addressed:

- A parser that reads network input is an attack surface -> a libFuzzer target for each, with a seed corpus replayed in every CI run

## The issue

Parsers read bytes from strangers. A crash or a hang in one of them is a denial of service, and memory errors may be worse. Fuzzing finds such inputs; keeping a seed corpus in the tests turns every one found into a regression test that runs on every build.

Each target in `fuzz/` feeds arbitrary bytes to one parser (RTP, RTCP, transport feedback, H.264, packet buffer, RED, ULPFEC, STUN, TURN, TCP framing, DTLS records, DTLS over ICE, SDP, SCTP packet and socket); ctest replays the committed corpus as `fuzz.<target>` so a regression is a test failure. `SM_BUILD_FUZZERS=ON` builds the real libFuzzer targets.
