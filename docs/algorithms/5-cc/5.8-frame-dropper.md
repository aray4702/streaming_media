# 5.8 Encoder overshoot control (frame dropper)

Section 5, *Bandwidth, congestion and unstable links*, of [Problems WebRTC solves](../../02-webrtc-problems-solved.md). Problems addressed:

- Encoder bitrate overshoot -> encoder rate control, frame dropper

## The issue

Encoders do not hit their target bitrate exactly. Scene changes, keyframes and complex content overshoot, and some hardware encoders run persistently 20-50% over target. The congestion controller then sees more traffic than it allowed, queues build, and the controller lowers the target, which the encoder overshoots again. Real bandwidth is wasted on the overshoot while video quality is cut. Something must enforce the budget by skipping frames when the encoder has spent too much, and correct the encoder's systematic error, without reacting to the single large keyframe every encoder legitimately produces.

## Design

Real encoders miss their target: scene changes and keyframes overshoot, and some hardware encoders run persistently hot. Two complementary tools:

FrameDropper: a port of libwebrtc's modules/video_coding/utility/frame_dropper.{h,cc} (M157), with its constants and defaults. A leaky bucket (the accumulator, in kbits) is filled by every encoded frame and leaks target/fps per captured frame. Above half a second of the target rate it raises a smoothed drop ratio (ExpFilter) and DropFrame() spreads the drops over time, at most 4 s of frames in a row. Keyframes and unusually large delta frames (> 3x the running average) are not added at once but spread over 0.5 s of frames. The accumulator is capped at 3 s of the target rate, and rescaled by new/old target when the target drops (SetRates). The caller order per captured frame is as VideoStreamEncoder: Leak(fps), then DropFrame(); SetRates() on a rate update; Fill() after each encoded frame. Keyframes are not exempt, as in libwebrtc.

EncoderOvershootDetector: measures actual/target utilization over a sliding window and returns an adjusted target (target / utilization) to feed back into the encoder's rate control, removing systematic overshoot.

See the [libwebrtc parity inventory](../../design/libwebrtc-parity.md#5-congestion-control) for the differences from libwebrtc. FrameDropper is a port of libwebrtc's modules/video_coding/utility/frame_dropper.cc (M157) with its constants: 0.5 s leaky bucket, accumulator cap 3 s, drop-ratio, key-frame-ratio and frame-size ExpFilters, keyframes and delta frames over 3x the average spread over 0.5 s of frames, at most 4 s of frames dropped in a row, and the accumulator rescaled by new/old target when the target drops. Keyframes are not exempt, as in VideoStreamEncoder::OnFrame. The session layer's rtp::VideoSendController (issue #37, docs/design/send-controller.md) drives it per captured frame (Leak, DropFrame, SetRates, Fill). Remaining differences (issue #5): the input frame rate is the configured one, not measured; ExpFilter (rtc_base/numerics/exp_filter) is not in compare/webrtc/reference and was written from the upstream class (reported on #57).

Public API (generated from the header; private members omitted):

```cpp
namespace sm::cc {

// rtc_base/numerics/exp_filter.{h,cc}: filtered = a^exp * filtered + (1 - a^exp) * sample,
// seeded by the first sample, optionally capped at `max`. Not in
// compare/webrtc/reference (reported on #57); written from the upstream class.
class ExpFilter {
 public:
  static constexpr float kValueUndefined = -1.0f;
  explicit ExpFilter(float alpha, float max = kValueUndefined) : alpha_(alpha), max_(max) {}
  void Reset(float alpha) {
    alpha_ = alpha;
    filtered_ = kValueUndefined;
  }
  float Apply(float exp, float sample) {
    if (filtered_ == kValueUndefined) {
      filtered_ = sample;
    } else {
      const float alpha = std::pow(alpha_, exp);
      filtered_ = alpha * filtered_ + (1 - alpha) * sample;
    }
    if (max_ != kValueUndefined && filtered_ > max_) filtered_ = max_;
    return filtered_;
  }
  void UpdateBase(float alpha) { alpha_ = alpha; }
  float filtered() const { return filtered_; }

};

class FrameDropper : public MetricsSource {
 public:
  FrameDropper();
  // Back to the initial state (target 300 kbps, 30 fps).
  void Reset();
  // The caller's per-frame sequence, as VideoStreamEncoder::OnFrame:
  // Leak(fps) then DropFrame(). Returns true if the frame is to be dropped.
  bool ShouldDrop(double input_fps);
  void Leak(uint32_t input_framerate);
  bool DropFrame();
  // `target` is rounded to whole kbps as VideoStreamEncoder::OnBitrateUpdated does.
  void SetRates(DataRate target, double fps);
  // After encoding.
  void OnEncodedFrame(DataSize size, bool keyframe);
  double bucket_bytes() const { return accumulator_ * 1000.0 / 8.0; }
  void ExportMetrics(MetricsWriter& w) const override;

};

class EncoderOvershootDetector : public MetricsSource {
 public:
  explicit EncoderOvershootDetector(TimeDelta window = TimeDelta::Seconds(2)) : window_(window) {}
  void SetTarget(DataRate target) { target_ = target; }
  void OnEncodedFrame(DataSize size, Timestamp now);
  // Actual / target over the window (1.0 = on target).
  double Utilization(Timestamp now) const;
  // Target to configure the encoder with to land on SetTarget().
  DataRate AdjustedTarget(Timestamp now) const;
  void ExportMetrics(MetricsWriter& w) const override;

};

}  // namespace sm::cc
```
