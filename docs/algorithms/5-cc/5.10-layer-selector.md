# 5.10 Simulcast/SVC layer selection (SFU)

Section 5, *Bandwidth, congestion and unstable links*, of [Problems WebRTC solves](../../02-webrtc-problems-solved.md). Problems addressed:

- Heterogeneous receivers in group calls -> Simulcast and SVC; the SFU forwards a matching layer per receiver

## The issue

In a group call, one sender's video goes to many receivers whose downlinks range from fibre to congested cellular. Encoding separately per receiver does not scale. With simulcast (several encodings) or SVC (layered encoding), the SFU can forward to each receiver the best layer it can handle. That decision is itself a small control loop: switching up too eagerly overloads the receiver, and switching on every bandwidth fluctuation causes visible flapping.

Switches are also constrained by decodability: a receiver can only start a different simulcast encoding at one of its keyframes, and can only add a temporal layer where the new layer does not reference frames it never received.

## Design

Each receiver gets the highest (spatial, temporal) layer whose bitrate fits its bandwidth estimate. Rules that keep the forwarded stream decodable and stable: - switch down immediately when the estimate drops below the layer rate; - switch up only after the estimate has exceeded the next layer's rate

```
   by `up_margin` for `up_hold` (hysteresis);
```

- a spatial switch takes effect only at a keyframe of the target spatial

```
   layer (a keyframe request is raised); temporal up-switches happen at
   layer-sync frames, temporal down-switches at any frame.
```

Spatial switches wait for a keyframe of the target encoding (and request one); temporal up-switches wait for a layer-sync frame.

## Implementation skeleton

Files: [include/sm/cc/layer_selector.h](../../../include/sm/cc/layer_selector.h), [src/cc/layer_selector.cc](../../../src/cc/layer_selector.cc).

Public API (generated from the header; private members omitted):

```cpp
namespace sm::cc {

struct LayerOption {
  int spatial = 0;
  int temporal = 0;
  DataRate bitrate;  // Total rate needed to forward this selection.
};

struct LayerSelectorConfig {
  double up_margin = 1.15;
  TimeDelta up_hold = TimeDelta::Millis(1000);
  EventSink* events = nullptr;
};

struct LayerSelectorStats {
  uint64_t switches_up = 0;
  uint64_t switches_down = 0;
  uint64_t keyframe_requests = 0;
  uint64_t forwarded = 0;
  uint64_t dropped = 0;
};

class LayerSelector : public MetricsSource {
 public:
  // Options sorted from lowest to highest quality.
  LayerSelector(std::vector<LayerOption> options, LayerSelectorConfig cfg = {});
  // Updates the target from the receiver's available bandwidth.
  void OnBandwidth(DataRate available, Timestamp now);
  // Per-frame forwarding decision.
  bool ShouldForward(int spatial, int temporal, bool keyframe, bool layer_sync);
  // True once per pending spatial switch: ask the sender for a keyframe.
  bool TakeKeyframeRequest();
  LayerOption target() const { return options_[target_]; }
  int current_spatial() const { return cur_spatial_; }
  int current_temporal() const { return cur_temporal_; }
  const LayerSelectorStats& stats() const { return stats_; }
  void ExportMetrics(MetricsWriter& w) const override;

};

}  // namespace sm::cc
```

## Test methods

**Unit tests** (deterministic, no network):

- `LayerSelector`: `HysteresisAndKeyframeGating`

**End-to-end test** (sender -> simulated network -> receiver, `tests/e2e/`):

- `E2E_LayerSelector`: `SfuForwardsDecodableStreamWithinBandwidth`

Three L1T3 simulcast encodings (150/500/1500 kbps); the receiver's bandwidth (+-10% noise) goes 2000 -> 700 -> 300 kbps. Checks decodability of every forwarded frame, the time spent over budget and the number of switches.
