# 5.7 Bitrate allocation among streams

Section 5, *Bandwidth, congestion and unstable links*, of [Problems WebRTC solves](../../02-webrtc-problems-solved.md). Problems addressed:

- Sharing bandwidth among streams -> bitrate allocator, with per-stream priority and min/max bitrate

## The issue

A call usually carries several streams over one connection: audio, camera video, perhaps a screen share and data. They compete for one bandwidth estimate. Splitting it evenly gives audio far more than it can use and starves video. Giving everything to video can starve audio, which is the one stream that must never stop.

Streams have different minimum useful rates (video below about 100 kbps is not worth sending), maximums and importance. When bandwidth drops, the least important stream should pause rather than everything degrading together. When it recovers, streams should not flap on and off around the threshold.

## Design

Splits the target rate across streams (audio, camera, screen share, data) with min/max limits and priorities: 1. Fund minimums in priority order. A stream whose minimum cannot be

```
    funded is paused (0), unless enforce_min, in which case it always gets
    its minimum (audio). A paused stream only resumes once it can get
    min * (1 + hysteresis), so streams do not flap on and off.
```

2. Distribute what is left by water-filling, proportional to priority,

```
    up to each stream's max; leftover from capped streams is reshared.
```

A port of webrtc::BitrateAllocator, one observer per stream (audio, video):

```
  - below the sum of the minimums (LowRateAllocation): a stream that enforces
    its minimum gets it, then streams that were active last round get their
    minimum with hysteresis, then paused streams, then the remainder is shared
    evenly among the streams that have an allocation;
  - between the minimums and the maximums (NormalRateAllocation): minimums, then
    the priority rate of each stream in order, then the rest in proportion to
    bitrate_priority up to each stream's capacity;
  - above the maximums (MaxRateAllocation): every stream gets its maximum and
    the surplus is shared evenly up to 2x each maximum.
```

A paused stream resumes at min + max(10 %, 20 kbps), plus the protection share it used last time. The limits (UpdateAllocationLimits) are what libwebrtc hands to the network controller: the sum of the enforced minimums is its lower bound for the target (GoogCC min_total_allocated_bitrate) and the pacing floor. Not ported: the elastic-rate allocation (WebRTC-ElasticBitrateAllocation, off by default; GetUsedRate is nullopt for video). Rates are integer bits per second, as libwebrtc's uint32 bps.

See the [libwebrtc parity inventory](../../design/libwebrtc-parity.md#5-congestion-control) for the differences from libwebrtc. Paused streams resume only at min x 1.1 (hysteresis). A `rtp::Session` runs the port of libwebrtc's `BitrateAllocator` (issue #104; the v1 split was deleted by #167) (`call/bitrate_allocator.cc`): `LowRateAllocation` / `NormalRateAllocation` / `MaxRateAllocation` with min + max(10 %, 20 kbps) and the protection share to resume, and the sum of the enforced minimums (audio, and video as `suspend_below_min_bitrate` is off) is the lower bound of GCC's target (`min_total_allocated_bitrate`, `use_min_allocatable_as_lower_bound_`). The video stream follows `VideoSendStreamImpl`'s encoder activity check (`video_send_stream_impl.cc`, `kEncoderTimeOut` 2 s; issue #375): with no frame encoded since the last check it leaves the allocator, and an encoder reconfiguration or the next encoded frame registers it again; each change of the limits reaches GoogCC as `OnStreamsConfig`, so a stream that comes back can start an allocation probe (`ProbeController::OnMaxTotalAllocatedBitrate`). Remaining: the elastic allocation (off by default in libwebrtc), the padding limit (`max_padding_rate`, with the prober, #48), the per-packet overhead libwebrtc takes off the video payload rate, and the audio min and max from Opus's frame-length range (not in `reference/`, #57).

namespace sm::cc {

struct AllocatableStream {
  std::string id;
  DataRate min;
  DataRate max;
  double priority = 1.0;
  bool enforce_min = false;

class BitrateAllocator : public MetricsSource {
 public:
  explicit BitrateAllocator(double resume_hysteresis = 0.1) : hysteresis_(resume_hysteresis) {}
  void AddStream(const AllocatableStream& s);
  void RemoveStream(const std::string& id);
  std::map<std::string, DataRate> Allocate(DataRate total);

}  // namespace sm::cc

```cpp
namespace sm::cc {

// MediaStreamAllocationConfig.
struct StreamAllocationConfig {
  DataRate min;
  DataRate max;
  DataRate pad_up;
  DataRate priority_rate;  // priority_bitrate_bps: allocated before the proportional share.
  bool enforce_min = false;
  double priority = 1.0;   // bitrate_priority
};

// BitrateAllocationLimits.
struct AllocationLimits {
  DataRate min_allocatable;
  DataRate max_padding;
  DataRate max_allocatable;
  bool operator==(const AllocationLimits&) const = default;
};

class BitrateAllocatorV2 : public MetricsSource {
 public:
  // Called with the stream and its new allocation; returns the protection (FEC
  // and retransmission) bitrate the stream takes out of it, which sets the media
  // ratio of the next hysteresis (BitrateAllocatorObserver::OnBitrateUpdated).
  using Observer = std::function<DataRate(DataRate allocation)>;

  explicit BitrateAllocatorV2(EventSink* events = nullptr) : events_(events) {}

  // Adds the stream, or updates the config of an existing one.
  void AddObserver(const std::string& id, StreamAllocationConfig cfg, Observer on_update = nullptr);
  void RemoveObserver(const std::string& id);
  // OnNetworkEstimateChanged: reallocates and notifies every observer.
  void OnTargetChanged(DataRate target, Timestamp now);

  // The last allocation of the stream; Zero when it is paused or unknown.
  DataRate allocation(const std::string& id) const;
  bool paused(const std::string& id) const;
  DataRate target() const { return DataRate::BitsPerSec(last_target_bps_); }
  const AllocationLimits& limits() const { return limits_; }
  uint64_t pause_events() const { return pause_events_; }
  void ExportMetrics(MetricsWriter& w) const override;

  };
  std::vector<int64_t> Allocate(int64_t bitrate) const;
  void UpdateAllocationLimits();

  EventSink* events_;
  std::vector<Track> tracks_;
  int64_t last_target_bps_ = 0;
  uint64_t pause_events_ = 0;
  AllocationLimits limits_;
};

}  // namespace sm::cc
```

## Verification notes

A unit-test expectation was wrong about how leftover bitrate is shared (it is split by priority between audio and screen); the expectation was corrected. Issue #375: at 1 fps with quality scaling, libwebrtc's start probe sends a third cluster at 2x the 300 kbps estimate (an allocation probe after the video stream timed out and re-registered); with the activity check ours sends it too (642 vs 627 kbps on `issue_335_fps1_keyframe_packets` seed 1).
