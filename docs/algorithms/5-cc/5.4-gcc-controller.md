# 5.4 Send-side bandwidth estimation (GCC network controller)

Section 5, *Bandwidth, congestion and unstable links*, of [Problems WebRTC solves](../../02-webrtc-problems-solved.md). Problems addressed:

- Unknown or changing available bandwidth -> GCC (delay-based and loss-based estimation)

## The issue

Several estimates of the available bandwidth exist at once: delay-based, loss-based, the receiver's REMB hint and probe results. Each also has configured limits. The encoders need one target rate, and the pacer needs a rate to send at. Combining them incorrectly makes the system either ignore a real limit (overshooting into congestion) or let one stale estimate cap everything (stuck at low quality). The combination also has to be wired to the right inputs: transport feedback, RTT updates and periodic ticks.

## Design

Wires transport feedback into the delay-based estimator, the loss-based estimator, the acknowledged-bitrate estimator and the probe machinery, and produces the target rate for the encoders (min of delay-, loss- and REMB-based estimates, clamped to [min, max]) plus a pacing rate (target x pacing_factor) and any probe clusters to send.

The target is min(delay-based, loss-based, REMB), clamped to [min, max]; the pacing rate is 2.5 x target. rtp::SendSideController adds congestion-window pushback (cc/congestion_window_pushback.h, a port of libwebrtc's CongestionWindowPushbackController with its drop-frame-only mode): when the data in flight exceeds target x (min feedback RTT + 350 ms) the encoder drops every N-th captured frame (SendRates::frame_drop_interval, SendSideController::DropCapturedFrame()). The pacing rate is not reduced.

## Implementation skeleton

Files: [include/sm/cc/send_side_bwe.h](../../../include/sm/cc/send_side_bwe.h), [src/cc/send_side_bwe.cc](../../../src/cc/send_side_bwe.cc).

Public API (generated from the header; private members omitted):

```cpp
namespace sm::cc {

struct GccConfig {
  DataRate min_rate = DataRate::KilobitsPerSec(30);
  DataRate start_rate = DataRate::KilobitsPerSec(300);
  DataRate max_rate = DataRate::KilobitsPerSec(10000);
  double pacing_factor = 2.5;
  bool enable_probing = true;
  EventSink* events = nullptr;
};

struct NetworkControlUpdate {
  DataRate target_rate;
  DataRate pacing_rate;
  std::vector<ProbeCluster> probes;
  bool changed = false;
};

class GccController : public MetricsSource {
 public:
  explicit GccController(GccConfig cfg = {});
  NetworkControlUpdate Start(Timestamp now);
  void OnPacketSent(uint16_t transport_seq, Timestamp send_time, DataSize size, int probe_cluster = -1);
  NetworkControlUpdate OnTransportFeedback(const TransportFeedback& fb, Timestamp now);
  void OnRttUpdate(TimeDelta rtt);
  void OnRemb(DataRate remb) { remb_ = remb; }
  // Periodic tick (e.g. every 25 ms): ALR probing and outage handling.
  NetworkControlUpdate OnProcessInterval(Timestamp now, DataRate current_send_rate);
  // Hard reset after a network route change / outage recovery.
  NetworkControlUpdate ResetEstimate(DataRate rate, Timestamp now);
  DataRate target() const { return target_; }
  // Largest (feedback time - send time) among the packets the last feedback
  // reported as received; nullopt if it reported none.
  std::optional<TimeDelta> last_feedback_max_rtt() const { return last_feedback_max_rtt_; }
  const DelayBasedBwe& delay_bwe() const { return delay_; }
  const LossBasedBwe& loss_bwe() const { return loss_; }
  const SendHistory& history() const { return history_; }
  void ExportMetrics(MetricsWriter& w) const override;

};

}  // namespace sm::cc
```

## Test methods

**Unit tests** (deterministic, no network):

- `SendSideBwe`: `StartProbesAndRembCap`

**End-to-end test** (sender -> simulated network -> receiver, `tests/e2e/`):

- `E2E_SendSideBwe`: `CombinesDelayAndLossControllers`

A 1.5 Mbps link through three 20 s phases: clean, 5% loss (GCC 'hold' band) and 20% loss (decrease band). Each phase's target is compared with the previous one.

## Verification notes

Covered by the 5.2 and 5.3 fixes. Pushback (issue #53, [fix record](../../fixes/53-cwnd-pushback.md)): SendHistory counted packets of a lost transport feedback as in flight for 60 s, which would hold the window shut; they are now settled once a later feedback is reported. The library default is on (libwebrtc enables it through the WebRTC-CongestionWindow field trial; rate_control_settings.cc, which holds the default, is not in compare/webrtc/reference).
