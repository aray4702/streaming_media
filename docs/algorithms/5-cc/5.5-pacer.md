# 5.5 Pacer with priority queues

Section 5, *Bandwidth, congestion and unstable links*, of [Problems WebRTC solves](../../02-webrtc-problems-solved.md). Problems addressed:

- Bursts filling router queues (bufferbloat) -> Pacer: smooths packet sends, with priority queues
- Protecting audio over video -> audio prioritized in the pacer; video degrades first

## The issue

Encoders produce a whole frame at once, and a keyframe can be tens of kilobytes. Writing it to the socket instantly sends a line-rate burst that briefly exceeds the bottleneck's capacity. Router queues fill (adding delay for everything behind the burst), packets are dropped, and the congestion controller sees self-inflicted congestion and lowers the rate for no good reason.

Audio packets queued behind a video burst arrive late, which is worse because audio dropouts hurt more than video stutter. Retransmissions are also time-critical. Packets must be spread out at a controlled rate, important traffic must go first, and the queue must never grow so large that video is seconds old when it is sent.

## Design

A port of modules/pacing/pacing_controller.cc, prioritized_packet_queue.cc (M157, compare/webrtc/reference/), behind a `Timestamp now` API with no task queue. Encoders emit a whole frame at once; sending it as a line-rate burst fills router queues (bufferbloat) and causes self-inflicted loss. The pacer releases packets at the pacing rate (usually 2.5 x the target) using libwebrtc's leaky bucket:

```
  - `media_debt` grows with every packet sent and drains at the (adjusted)
    pacing rate; packets may leave in a burst of `send_burst_interval`
    (40 ms) at a time, and the debt is capped at 500 ms of the rate;
  - the time that is credited since the last send is capped at 2 s;
  - a queue that cannot drain within `queue_time_limit` (2 s, judged on the
    average queue time, not the oldest packet) raises the rate;
  - padding fills a requested padding rate, 5 ms of it at a time.
```

Packets are queued per priority level, as PrioritizedPacketQueue does:

```
  0 audio, 1 retransmission, 3 video and FEC (one FIFO), 4 padding
```

(level 2, video retransmission, is only used when audio retransmission is prioritised, which libwebrtc does not do by default). Audio is not paced (it leaves at its enqueue time) but is counted in the debt, as a call with audio in the congestion-control allocation does. Probe clusters are sent at their own rate and tagged so the probe estimator can find them; padding fills a probe when there is no media. BitrateProber is #48's.

See the [libwebrtc parity inventory](../../design/libwebrtc-parity.md#5-congestion-control) for the differences from libwebrtc. A port of libwebrtc's PacingController and PrioritizedPacketQueue (M157, issue #70): a 40 ms burst interval (capped at 63 kB), media debt capped at 500 ms of the rate, 2 s cap on the time credited, a queue-time limit of 2 s judged on the average queue time, audio unpaced but accounted, queue levels audio / retransmission / video+FEC / padding, keep-alive padding every 500 ms while paused or congested, and padding at the padding rate 5 ms at a time. Remaining differences: flushing the queued packets of a stream when a keyframe arrives (needs the sender to mark keyframes; #5), round-robin between SSRCs of one level (one stream per kind in a one-to-one call), the packet TTLs (off by default), `SetCongested` is not driven by the congestion window (pushback stays on the encoder), and `BitrateProber` (#48): a probe cluster is still sent in 5 ms bursts at the probe rate.

## Implementation skeleton

Files: [include/sm/cc/pacer.h](../../../include/sm/cc/pacer.h), [src/cc/pacer.cc](../../../src/cc/pacer.cc).

Public API (generated from the header; private members omitted):

```cpp
namespace sm::cc {

// The queue level is derived from the priority (see above); kFec shares the
// video level.
enum class PacketPriority : int { kAudio = 0, kRetransmission = 1, kVideo = 2, kFec = 3, kPadding = 4 };

struct PacedPacket {
  uint64_t id = 0;  // Caller's handle.
  PacketPriority priority = PacketPriority::kVideo;
  DataSize size;  // Whole datagram: what is budgeted and counted in the queue size.
  Timestamp enqueue_time;
  int probe_cluster = -1;  // Set by the pacer when sent as part of a probe.
  bool is_padding = false;
};

struct PacerConfig {
  // PacingController::Configuration defaults.
  TimeDelta queue_time_limit = TimeDelta::Millis(2000);  // kMaxExpectedQueueLength
  bool drain_large_queues = true;
  TimeDelta send_burst_interval = TimeDelta::Millis(40);  // PacerConfig::kDefaultTimeInterval
  // Audio waits for the budget only with WebRTC-Pacer-BlockAudio (off by default).
  bool pace_audio = false;
  // AccountForAudioPacketsInPacedSender(true), what AudioSendStream does when audio is
  // part of the congestion-control allocation.
  bool account_for_audio = true;
  // Wire size of one padding packet (RTPSender::GeneratePadding, kMaxPaddingLength).
  DataSize padding_packet = DataSize::Bytes(224);
  int circuit_breaker_iterations = 1 << 16;
  EventSink* events = nullptr;
};

struct PacerStats {
  std::array<uint64_t, 5> sent_packets{};
  std::array<int64_t, 5> sent_bytes{};
  uint64_t probe_packets = 0;
  uint64_t drain_boosts = 0;  // Times the queue raised the rate above the pacing rate.
  uint64_t keepalives = 0;
  uint64_t circuit_breaks = 0;
  std::array<Histogram, 5> queue_delay_ms;
};

class Pacer : public MetricsSource {
 public:
  explicit Pacer(PacerConfig cfg = {});
  void SetPacingRates(DataRate pacing, DataRate padding);
  void Enqueue(PacedPacket p);
  void AddProbeCluster(const ProbeCluster& c);
  // Sends everything that is due by `now`. Call at NextSendTime() or sooner.
  std::vector<PacedPacket> Process(Timestamp now);
  Timestamp NextSendTime(Timestamp now) const;
  void Pause();
  void Resume();
  bool paused() const { return paused_; }
  // PacingController::SetCongested: nothing is sent while congested except a
  // keep-alive padding packet every 500 ms.
  void SetCongested(bool congested);
  bool congested() const { return congested_; }

  DataSize QueueSize() const { return queue_bytes_; }
  size_t QueuePackets() const { return queue_packets_; }
  // Age of the oldest queued packet (zero when empty).
  TimeDelta OldestQueueTime(Timestamp now) const;
  // QueueSizeData() / adjusted rate.
  TimeDelta ExpectedQueueTime() const;
  DataRate pacing_rate() const { return adjusted_media_rate_; }
  const PacerStats& stats() const { return stats_; }
  void ExportMetrics(MetricsWriter& w) const override;

  };

  void Start(Timestamp now);
  Timestamp Cur(Timestamp now);
  TimeDelta UpdateTimeAndGetElapsed(Timestamp now);
  bool ShouldSendKeepalive(Timestamp now) const;
  void UpdateBudgetWithElapsedTime(TimeDelta delta);
  void UpdateBudgetWithSentData(DataSize size);
  void UpdatePaddingBudgetWithSentData(DataSize size);
  DataSize PaddingToAdd(DataSize data_sent) const;
  void OnPacketSent(PacketPriority prio, DataSize size, Timestamp send_time);
  void MaybeUpdateMediaRateDueToLongQueue(Timestamp now);
  Timestamp NextUnpacedSendTime() const;
  Timestamp NextSendTimeAt(Timestamp now) const;
  bool GetPendingPacket(Timestamp target_send_time, Timestamp now, PacedPacket* out);
  void ProcessProbe(Timestamp now, std::vector<PacedPacket>& sent);
  void Account(PacedPacket& p, Timestamp now, std::vector<PacedPacket>& sent);

  // PrioritizedPacketQueue.
  static int Level(PacketPriority p);
  void Push(Timestamp now, PacedPacket p);
  bool Pop(PacedPacket* out, Timestamp now);
  void UpdateAverageQueueTime(Timestamp now);
  void SetQueuePauseState(bool paused, Timestamp now);
  TimeDelta AverageQueueTime() const;

  PacerConfig cfg_;
  bool started_ = false;
  Timestamp last_timestamp_ = Timestamp::MinusInfinity();
  bool paused_ = false;
  bool congested_ = false;

  DataSize media_debt_, padding_debt_;
  DataRate pacing_rate_ = DataRate::KilobitsPerSec(750);
  DataRate adjusted_media_rate_ = DataRate::KilobitsPerSec(750);
  DataRate padding_rate_;
  TimeDelta send_burst_interval_;
  TimeDelta queue_time_limit_;
  Timestamp last_process_time_ = Timestamp::MinusInfinity();
  Timestamp last_send_time_ = Timestamp::MinusInfinity();
  bool seen_first_packet_ = false;
  bool boosted_ = false;

  std::array<std::deque<Queued>, kLevels> levels_;
  std::multiset<Timestamp> enqueue_times_;
  DataSize queue_bytes_;
  size_t queue_packets_ = 0;
  TimeDelta queue_time_sum_, pause_time_sum_;
  Timestamp queue_update_time_ = Timestamp::MinusInfinity();
  bool queue_paused_ = false;

  struct ActiveProbe {
    ProbeCluster c;
    int sent_probes = 0;
    int64_t sent_bytes = 0;
  };
  std::deque<ActiveProbe> probes_;
  DataSize probe_debt_;
  uint64_t next_padding_id_ = 1ull << 62;
  PacerStats stats_;
};

}  // namespace sm::cc
```

## Verification notes

The unit tests port the intent of libwebrtc's pacing_controller_unittest.cc (burst interval, debt cap, priorities, long-queue drain on the average queue time, padding, congestion keep-alives). With the 40 ms burst a frame leaves in one burst, so the E2E_Pacer expectation that the paced run beats the unpaced one on audio delay no longer holds (audio is not paced in libwebrtc either); the new expectation is that it is not worse. See docs/design/libwebrtc-parity.md 5.5 and issue #70 for the suite comparison.
