# 5.6 Bandwidth probing

Section 5, *Bandwidth, congestion and unstable links*, of [Problems WebRTC solves](../../02-webrtc-problems-solved.md). Problems addressed:

- Probing for more bandwidth safely -> bandwidth probing (padding / RTX probe clusters)

## The issue

A delay-based controller only learns about capacity it is using: it raises the rate slowly (about 8% per second) and backs off at the first sign of queueing. Starting a call at 300 kbps on a 5 Mbps link therefore takes tens of seconds to reach good quality. When the application sends less than the estimate (a static screen share, a paused video), the estimate is never tested and can become stale in either direction.

Probing sends short bursts at a higher rate (with padding if there is no media) and measures how fast they arrive. A real probe result lets the estimate jump in one step. The probes must be short, and their results must reject measurements that are too sparse to trust.

## Design

ProbeController decides when to probe: at start-up (clusters at 3x and 6x the start rate), again whenever an estimate reaches 70% of the last probe rate (exponential probing upward), when the max bitrate is raised, and periodically while the application is limited (ALR) so a stale estimate can be revalidated. ProbeBitrateEstimator turns the feedback of one probe cluster into a rate: the receive rate if the link could not keep up (receive < 90% of send), else the send rate.

Probe clusters are sent by the pacer at the probe rate, using padding when there is no media; the estimator ignores clusters with too few packets or bytes.

## Implementation skeleton

Files: [include/sm/cc/probing.h](../../../include/sm/cc/probing.h), [src/cc/probing.cc](../../../src/cc/probing.cc).

Public API (generated from the header; private members omitted):

```cpp
namespace sm::cc {

struct ProbeCluster {
  int id = 0;
  DataRate rate;
  int min_probes = 5;
  DataSize min_bytes;
};

struct ProbeControllerConfig {
  double first_multiplier = 3.0;
  double second_multiplier = 6.0;
  double further_probe_threshold = 0.7;
  double further_multiplier = 2.0;
  TimeDelta alr_probe_interval = TimeDelta::Seconds(5);
  TimeDelta probe_duration = TimeDelta::Millis(15);
  EventSink* events = nullptr;
};

class ProbeController : public MetricsSource {
 public:
  explicit ProbeController(ProbeControllerConfig cfg = {}) : cfg_(cfg) {}
  std::vector<ProbeCluster> SetBitrates(DataRate min, DataRate start, DataRate max, Timestamp now);
  std::vector<ProbeCluster> SetEstimate(DataRate estimate, Timestamp now);
  std::vector<ProbeCluster> SetMaxBitrate(DataRate max, Timestamp now);
  // ALR: application-limited (sending well below the estimate).
  void SetApplicationLimited(bool alr, Timestamp now);
  std::vector<ProbeCluster> Process(Timestamp now);
  void EnablePeriodicAlrProbing(bool e) { periodic_alr_ = e; }
  void ExportMetrics(MetricsWriter& w) const override;

};

class ProbeBitrateEstimator : public MetricsSource {
 public:
  void SetClusterInfo(const ProbeCluster& c) { clusters_[c.id].config = c; }
  // Feed every packet result; returns an estimate when a cluster completes.
  std::optional<DataRate> OnPacketResult(const PacketResult& r);
  std::optional<DataRate> FetchAndResetLastEstimate();
  void ExportMetrics(MetricsWriter& w) const override;

  };
  std::map<int, Cluster> clusters_;
  std::optional<DataRate> last_;
  uint64_t estimates_ = 0, invalid_ = 0;
};

}  // namespace sm::cc
```

## Metrics and observability

Every class implements `MetricsSource::ExportMetrics`, so it can be registered in a `MetricsRegistry` and exported as JSON or Prometheus text. Histograms expand to `.count/.mean/.p50/.p95/.p99/.max`.

| Metric | Type |
|---|---|
| `clusters` | counter |
| `alr` | gauge |
| `estimates` | counter |
| `invalid` | counter |

Structured events (`EventSink`, `module/name`): `probe/cluster`.

## Benchmarks

Throughput benchmarks have a speed budget (ns per item, or a minimum real-time factor for media processing); quality benchmarks rerun an end-to-end scenario and gate its outcome. A benchmark passes only if every requirement holds.
