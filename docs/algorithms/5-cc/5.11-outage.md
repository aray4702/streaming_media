# 5.11 Link outage detection and recovery

Section 5, *Bandwidth, congestion and unstable links*, of [Problems WebRTC solves](../../02-webrtc-problems-solved.md). Problems addressed:

- Link outage, then recovery -> encoder pause, then keyframe on recovery; ICE restart if needed

## The issue

Links drop out entirely: a tunnel, an elevator, a Wi-Fi to LTE handover, a NAT rebinding. During the outage nothing comes back from the far end. A sender that keeps encoding fills its queues (and the network's) with media that will be seconds old when the link returns. Its bandwidth estimate is meaningless. The far end's decoder state is lost, so delta frames sent after recovery are undecodable. Recovery needs a deliberate sequence: pause, keep the connection alive, restart ICE if the path is gone, then resume with a keyframe and a cautious rate on what may now be a different path.

## Design

Watches feedback from the remote side (RTCP, transport feedback, any packet). States:

```
  kUp        feedback within degraded_after
  kDegraded  no feedback for degraded_after: stop growing the estimate
  kDown      no feedback for down_after: pause the encoder (sending into
             a dead link only fills queues) and keep sending keep-alives
  ICE restart is requested after ice_restart_after of continuous outage.
```

On the first feedback after kDown: resume, request a keyframe (the decoder state on the far side is stale), and reset the bandwidth estimate to a fraction of the pre-outage value (the path may have changed).

See the [libwebrtc parity inventory](../../design/libwebrtc-parity.md#5-congestion-control) for the differences from libwebrtc. On recovery the estimate is reset to half the last good rate and probing is restarted, because the path may have changed. libwebrtc has no outage monitor, so with `cc v2` the `SendSideController` does not run it (issue #151): the encoder keeps running, the congestion window drops frames, the pacer keeps sending, and the receiver's decode time-out asks for the keyframe once the link is back.

## Implementation skeleton

Files: [include/sm/cc/outage_monitor.h](../../../include/sm/cc/outage_monitor.h), [src/cc/outage_monitor.cc](../../../src/cc/outage_monitor.cc).

Public API (generated from the header; private members omitted):

```cpp
namespace sm::cc {

enum class LinkState { kUp, kDegraded, kDown };
const char* ToString(LinkState s);

struct OutageConfig {
  TimeDelta degraded_after = TimeDelta::Millis(600);
  TimeDelta down_after = TimeDelta::Millis(2000);
  TimeDelta ice_restart_after = TimeDelta::Seconds(5);
  double resume_rate_fraction = 0.5;
  EventSink* events = nullptr;
};

struct OutageActions {
  bool pause_encoder = false;
  bool resume_encoder = false;
  bool request_keyframe = false;
  bool ice_restart = false;
  bool reset_estimate = false;
  DataRate reset_rate;
};

class OutageMonitor : public MetricsSource {
 public:
  explicit OutageMonitor(OutageConfig cfg = {}) : cfg_(cfg) {}
  void OnFeedback(Timestamp now);
  void SetCurrentRate(DataRate r) {
    if (state_ == LinkState::kUp) last_good_rate_ = r;
  }
  OutageActions Process(Timestamp now);
  LinkState state() const { return state_; }
  void ExportMetrics(MetricsWriter& w) const override;

};

}  // namespace sm::cc
```

## Metrics and observability

Every class implements `MetricsSource::ExportMetrics`, so it can be registered in a `MetricsRegistry` and exported as JSON or Prometheus text. Histograms expand to `.count/.mean/.p50/.p95/.p99/.max`.

| Metric | Type |

| `outages` | counter |
| `ice_restarts` | counter |
