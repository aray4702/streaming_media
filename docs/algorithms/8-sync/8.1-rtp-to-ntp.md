# 8.1 RTP -> NTP mapping

Section 8, *Synchronization*, of [Problems WebRTC solves](../../02-webrtc-problems-solved.md). Problems addressed:

- Lip-sync (A/V sync) -> RTCP Sender Reports map the RTP timestamp to NTP wallclock

## The issue

Each RTP stream has its own timestamp clock with a random starting value (48 kHz for Opus audio, 90 kHz for video), unrelated to any wall clock and unrelated to the other streams. To synchronize streams or measure latency, the receiver must convert RTP timestamps into a common time base. RTCP sender reports provide pairs of (wall clock, RTP timestamp), but they arrive only about once per second, the media clock may drift relative to the sender's wall clock, and a sender can restart its RTP clock. Between reports, any RTP timestamp must still map accurately.

## Design

Reports, as libwebrtc M157's RtpToNtpEstimator (rtc_base/rtp_to_ntp_estimator.*).

Each SR pairs the sender's NTP time with the RTP timestamp of the same instant. A least-squares line (NTP units of 2^-32 s on the unwrapped RTP timestamp) through the last `kNumRtcpReportsToUse` 20 pairs maps any RTP timestamp of the stream to the sender's capture wall-clock time; the slope also yields the actual media clock rate, which absorbs sender clock drift. An SR with the same NTP time or the same RTP timestamp as a stored one is the same measurement. A new SR is invalid unless, compared with the newest stored one, its NTP time moves forward by at most 1 h (`kMaxAllowedRtcpNtpInterval`) and its RTP timestamp moves forward by at most `1 << 25` ticks. After `kMaxInvalidSamples` 3 consecutive invalid SRs the history is cleared and the third one starts a new line, so a genuine discontinuity (a sender restart) is followed.

See the [libwebrtc parity inventory](../../design/libwebrtc-parity.md#8-synchronization) for the differences from libwebrtc. 

## Implementation skeleton

Files: [include/sm/sync/rtp_to_ntp.h](../../../include/sm/sync/rtp_to_ntp.h), [src/sync/rtp_to_ntp.cc](../../../src/sync/rtp_to_ntp.cc).

Public API (generated from the header; private members omitted):

```cpp
namespace sm::sync {

class RtpToNtpEstimator : public MetricsSource {
 public:
  static constexpr int kMaxInvalidSamples = 3;
  static constexpr size_t kNumRtcpReportsToUse = 20;
  static constexpr uint64_t kMaxAllowedRtcpNtpInterval = uint64_t{60 * 60} << 32;
  static constexpr int64_t kMaxRtpJump = int64_t{1} << 25;

  enum class UpdateResult { kInvalidMeasurement, kSameMeasurement, kNewMeasurement };
  UpdateResult UpdateMeasurements(timing::NtpTime ntp, uint32_t rtp);
  // NTP time of a media RTP timestamp; value 0 (invalid) without a line.
  // Like libwebrtc's, it advances the RTP unwrapper.
  timing::NtpTime EstimateNtp(uint32_t rtp) const;
  // The same as a Timestamp (Unix epoch).
  std::optional<Timestamp> Estimate(uint32_t rtp) const;
  // libwebrtc's EstimatedFrequencyKhz: 0 without a line.
  double EstimatedFrequencyKhz() const;
  std::optional<double> EstimatedFrequencyHz() const;
  size_t size() const { return measurements_.size(); }
  void ExportMetrics(MetricsWriter& w) const override;

  };
  struct Parameters {
    double slope;   // NTP units per RTP tick.
    double offset;  // NTP units.
  };
  void UpdateParameters();
  int consecutive_invalid_samples_ = 0;
  std::deque<Measurement> measurements_;  // Newest first.
  std::optional<Parameters> params_;
  mutable SeqNumUnwrapper<uint32_t> unwrapper_;
  uint64_t accepted_ = 0, invalid_ = 0, resets_ = 0;
};

}  // namespace sm::sync
```

## Test methods

**Unit tests** (deterministic, no network):

- `RtpToNtp`: `FitsLineAndHandlesWrap`, `RejectsOutliersThenResets`

**End-to-end test** (sender -> simulated network -> receiver, `tests/e2e/`):

- `E2E_RtpToNtp`: `MapsCaptureTimeDespiteDriftAndJitter`

120 s with a sender audio clock 80 ppm off its NTP clock; SRs every second over a jittery link. Every 20 ms the estimated capture time of the current RTP timestamp is compared with the truth.

## Verification notes

No algorithm defects; one unit test's reject counting was corrected. #77 ported libwebrtc M157's SR validation (`rtc_base/rtp_to_ntp_estimator.cc`): it compares a new SR with the newest one (NTP forward by at most 1 h, RTP forward by at most 1 << 25 ticks) and clears the history after 3 invalid SRs, where ours rejected points 30 ms off the fitted line. The line is fitted in NTP units, as libwebrtc fits it. The e2e capture-time error on the 80 ppm clock is unchanged (0.014 ms).
