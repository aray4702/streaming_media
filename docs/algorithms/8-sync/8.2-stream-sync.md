# 8.2 Audio/video synchronization and CNAME sync groups

Section 8, *Synchronization*, of [Problems WebRTC solves](../../02-webrtc-problems-solved.md). Problems addressed:

- Lip-sync (A/V sync) -> the receiver aligns playout delay between streams
- Synchronizing multiple streams from one sender -> shared CNAME, MediaStream grouping

## The issue

Audio and video travel separately and are buffered differently: the audio jitter buffer might hold 60 ms, while video needs decode time and a render queue, and the two may even take different network paths. If each stream simply plays as soon as possible, video typically lags audio by tens to hundreds of milliseconds and lips visibly miss the words. People notice when audio leads video by more than about 45 ms, or lags it by more than about 125 ms (ITU-R BT.1359).

Delays change during a call (jitter buffer growth, route changes), so synchronization must be continuous. It must only apply to streams from the same source (same CNAME), and its corrections must be small and gradual so they are not themselves noticeable.

## Design

StreamSynchronization (video/stream_synchronization.*) and RtpStreamsSynchronizer (video/rtp_streams_synchronizer2.*, call/syncable.h).

Audio and video take different paths (network, jitter buffers, decode), so they play out with different delays. Using each stream's RTP->NTP mapping (RTCP SR), the receiver maps the RTP timestamps of the latest received audio and video packets to sender capture time and computes the relative delay (ComputeRelativeDelay):

```
    relative = (video_receive - audio_receive) - (video_capture - audio_capture)
```

in integer milliseconds, with no update beyond +-`kMaxDeltaDelayMs` 10 s. ComputeDelays adds the difference of the current video target delay and the current audio delay, filters it as `avg = (3 * avg + cur) / 4` (integer, from 0), and does nothing while |avg| < `kMinDeltaMs` 30 ms. Otherwise it moves half of it, at most `kMaxChangeMs` 80 ms, resets the average to 0, and changes one stream at a time: video late -> remove extra video delay if any above the base target, else add audio delay; video early -> remove extra audio delay if any, else add video delay. The outputs are minimum total playout delays for both streams, each capped at base + 10 s, video never below the base.

RtpStreamsSynchronizer runs that every `kSyncInterval` 1 s once a video stream is configured with an audio stream: it reads both Syncables' Info, feeds their SRs to the two RtpToNtpEstimators, skips the run when either has no new packet since the last one, and applies the targets with SetMinimumPlayoutDelay; a failed set lowers that stream's extra delay by 10%. GetStreamSyncOffsetInMs is libwebrtc's A/V offset stat. The library reads no clock: the caller passes `now` and calls Process.

MediaSyncGroups pairs streams for synchronization: only streams of the same CNAME (same participant/capture clock) are synchronized.

See the [libwebrtc parity inventory](../../design/libwebrtc-parity.md#8-synchronization) for the differences from libwebrtc. The 30 ms dead band sits inside the ITU-R BT.1359 detectability window (+45/-125 ms).

## Implementation skeleton

Files: [include/sm/sync/stream_sync.h](../../../include/sm/sync/stream_sync.h), [src/sync/stream_sync.cc](../../../src/sync/stream_sync.cc).

Public API (generated from the header; private members omitted):

```cpp
namespace sm::sync {

class StreamSynchronization {
 public:
  static constexpr int kMaxChangeMs = 80;
  static constexpr int kMaxDeltaDelayMs = 10000;
  static constexpr int kFilterLength = 4;
  static constexpr int kMinDeltaMs = 30;  // Minimum A/V difference to act on.

  struct Measurements {
    RtpToNtpEstimator rtp_to_ntp;
    int64_t latest_receive_time_ms = 0;
    uint32_t latest_timestamp = 0;
  };
  struct DelayTargets {
    int total_audio_delay_target_ms = 0;
    int total_video_delay_target_ms = 0;
  };

  StreamSynchronization(uint32_t video_stream_id, uint32_t audio_stream_id)
      : video_stream_id_(video_stream_id), audio_stream_id_(audio_stream_id) {}
  // libwebrtc's ComputeDelays with `*total_video_delay_target_ms` passed in
  // as `current_video_delay_ms`; nullopt where it returns false.
  std::optional<DelayTargets> ComputeDelays(int relative_delay_ms, int current_audio_delay_ms, int current_video_delay_ms);
  // How many ms later video is rendered relative to audio (negative when
  // audio plays later); nullopt without both estimates or beyond +-10 s.
  static std::optional<int> ComputeRelativeDelay(const Measurements& audio, const Measurements& video);
  // Audio and video are delayed by at least `target_delay_ms`.
  void SetTargetBufferingDelay(int target_delay_ms);
  void ReduceAudioDelay();  // Extra audio delay x 0.9, to recover from errors.
  void ReduceVideoDelay();
  uint32_t audio_stream_id() const { return audio_stream_id_; }
  uint32_t video_stream_id() const { return video_stream_id_; }

  };
  const uint32_t video_stream_id_;
  const uint32_t audio_stream_id_;
  SynchronizationDelays audio_delay_;
  SynchronizationDelays video_delay_;
  int base_target_delay_ms_ = 0;
  int avg_diff_ms_ = 0;
};

// call/syncable.h: what a receive stream gives the synchronizer.
class Syncable {
 public:
  struct Info {
    Timestamp latest_receive_time = Timestamp::Micros(0);  // Of the last RTP packet.
    uint32_t latest_received_capture_rtp_timestamp = 0;
    uint32_t capture_time_rtp = 0;  // From the last SR received.
    timing::NtpTime capture_time_ntp;
    TimeDelta current_delay;  // Current playout delay.
  };
  struct PlayoutInfo {
    Timestamp time;
    uint32_t rtp_timestamp = 0;
  };
  virtual ~Syncable() = default;
  virtual uint32_t id() const = 0;
  virtual std::optional<Info> GetInfo() const = 0;
  virtual std::optional<PlayoutInfo> GetPlayoutRtpTimestamp() const = 0;
  virtual bool SetMinimumPlayoutDelay(TimeDelta delay) = 0;
  virtual void SetEstimatedPlayoutNtpTimestamp(timing::NtpTime ntp, Timestamp time) = 0;
};

class RtpStreamsSynchronizer : public MetricsSource {
 public:
  static constexpr TimeDelta kSyncInterval = TimeDelta::Millis(1000);

  struct StreamSyncOffset {
    int64_t video_playout_ntp_ms = 0;
    int64_t stream_offset_ms = 0;  // Audio playout NTP minus video's.
    double estimated_freq_khz = 0;
  };

  explicit RtpStreamsSynchronizer(Syncable* syncable_video, EventSink* events = nullptr)
      : syncable_video_(syncable_video), events_(events) {}
  // Pairs the video stream with `syncable_audio` (nullptr stops syncing).
  // The first update runs kSyncInterval after `now`.
  void ConfigureSync(Syncable* syncable_audio, Timestamp now);
  // Runs UpdateDelay when the 1 s repeating task is due.
  void Process(Timestamp now);
  std::optional<Timestamp> NextProcessTime() const { return next_run_; }
  // libwebrtc's UpdateDelay (one run of the repeating task).
  void UpdateDelay(Timestamp now);
  std::optional<StreamSyncOffset> GetStreamSyncOffsetInMs(uint32_t rtp_timestamp, int64_t render_time_ms,
                                                          Timestamp now) const;
  uint64_t updates() const { return updates_; }  // Runs that computed new delay targets.
  const StreamSynchronization::DelayTargets& last_targets() const { return last_targets_; }
  void ExportMetrics(MetricsWriter& w) const override;

};

class MediaSyncGroups {
 public:
  enum class Kind { kAudio, kVideo };
  void AddStream(uint32_t ssrc, const std::string& cname, Kind kind);
  void RemoveStream(uint32_t ssrc);
  // (audio ssrc, video ssrc) per CNAME that has both.
  std::vector<std::pair<uint32_t, uint32_t>> SyncPairs() const;

  };
  std::map<uint32_t, Info> streams_;
};

}  // namespace sm::sync
```

## Verification notes

The test's 'before' sample was taken after the first corrections; it is now taken at t=0 (40 ms offset). #77 ported libwebrtc M157's `StreamSynchronization` and `RtpStreamsSynchronizer` (`video/stream_synchronization.cc`, `video/rtp_streams_synchronizer2.cc`, `call/syncable.h`). The filter starts at 0 and resets after each move, one stream changes at a time, the outputs are minimum playout delays set through `Syncable`, and the synchronizer runs every 1 s when both streams have new packets. The e2e offset after settling went from 18.8 to 25 ms, and after the route change from 22.0 to 17 ms. Both are inside the 30 ms dead band. #77 step 2 wires it into the session behind `SessionConfig::av_sync` (scenario `av_sync on`, off by default): `rtp::Session` pairs its first audio and video receive streams as `Call::ConfigureSync` does for one `sync_group`, the receivers give `Syncable::Info` (the last SR and media packet; video's current delay is `VCMTiming::TargetVideoDelay`, audio's NetEq's `FilteredCurrentDelayMs`), and `SessionConfig::audio_rtcp` sends the audio stream's own SR, as libwebrtc's audio RtpRtcp module, which the audio side needs. On `issue_77_av_sync_clean_link` the A/V offset median goes from -53 to -16 ms (seed 1); `sm_compare` sets libwebrtc's `sync_group` for the same scenario. #77 step 3 makes `av_sync` the test bench default on both stacks (scenario `av_sync off` keeps the old behaviour); the receive streams' `Syncable` glue was checked against `audio/channel_receive.cc` and `audio/audio_receive_stream.cc` (parity inventory 8.2a).
