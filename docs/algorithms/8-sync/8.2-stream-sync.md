# 8.2 Audio/video synchronization and CNAME sync groups

Section 8, *Synchronization*, of [Problems WebRTC solves](../../02-webrtc-problems-solved.md). Problems addressed:

- Lip-sync (A/V sync) -> the receiver aligns playout delay between streams
- Synchronizing multiple streams from one sender -> shared CNAME, MediaStream grouping

## The issue

Audio and video travel separately and are buffered differently: the audio jitter buffer might hold 60 ms, while video needs decode time and a render queue, and the two may even take different network paths. If each stream simply plays as soon as possible, video typically lags audio by tens to hundreds of milliseconds and lips visibly miss the words. People notice when audio leads video by more than about 45 ms, or lags it by more than about 125 ms (ITU-R BT.1359).

Delays change during a call (jitter buffer growth, route changes), so synchronization must be continuous. It must only apply to streams from the same source (same CNAME), and its corrections must be small and gradual so they are not themselves noticeable.

## Design

Audio and video take different paths (network, jitter buffers, decode), so they play out with different delays. Using each stream's RTP->NTP mapping (RTCP SR), the receiver maps the latest audio and video RTP timestamps to sender capture time and computes the relative delay:

```
    relative = (video_arrival - audio_arrival) - (video_capture - audio_capture)
```

plus the difference of the current playout delays. Every update the filtered offset is reduced by at most `max_change` (half of it per step, to avoid audible/visible jumps), first by removing extra delay from the stream that is late, then by adding extra delay to the stream that is early. Offsets under `tolerance` are left alone. The extra delays become minimum playout delays of the audio jitter buffer and the video timing.

MediaSyncGroups pairs streams for synchronization: only streams of the same CNAME (same participant/capture clock) are synchronized.

See the [libwebrtc parity inventory](../../design/libwebrtc-parity.md#8-synchronization) for the differences from libwebrtc. The 30 ms dead band sits inside the ITU-R BT.1359 detectability window (+45/-125 ms).

## Implementation skeleton

Files: [include/sm/sync/stream_sync.h](../../../include/sm/sync/stream_sync.h), [src/sync/stream_sync.cc](../../../src/sync/stream_sync.cc).

Public API (generated from the header; private members omitted):

```cpp
namespace sm::sync {

struct StreamSyncConfig {
  TimeDelta tolerance = TimeDelta::Millis(30);
  TimeDelta max_change = TimeDelta::Millis(80);
  TimeDelta max_extra_delay = TimeDelta::Millis(10000);
  double filter = 0.25;  // EMA weight of a new offset sample.
  EventSink* events = nullptr;
};

struct SyncDelays {
  TimeDelta audio_extra;  // Minimum playout delay to add to audio.
  TimeDelta video_extra;
};

class StreamSynchronization : public MetricsSource {
 public:
  explicit StreamSynchronization(StreamSyncConfig cfg = {}) : cfg_(cfg) {}
  RtpToNtpEstimator& audio_map() { return audio_map_; }
  RtpToNtpEstimator& video_map() { return video_map_; }
  void OnAudioPacket(uint32_t rtp, Timestamp arrival);
  void OnVideoFrame(uint32_t rtp, Timestamp arrival);
  // current_*_delay: the stream's current playout delay (jitter buffer +
  // decode + render) *excluding* the extra delay this class requested.
  std::optional<SyncDelays> Update(TimeDelta current_audio_delay, TimeDelta current_video_delay, Timestamp now);
  // Last measured A/V offset: positive means video plays later than audio.
  TimeDelta last_offset() const { return last_offset_; }
  const SyncDelays& delays() const { return delays_; }
  void ExportMetrics(MetricsWriter& w) const override;

};

class MediaSyncGroups {
 public:
  enum class Kind { kAudio, kVideo };
  void AddStream(uint32_t ssrc, const std::string& cname, Kind kind);
  void RemoveStream(uint32_t ssrc);
  // (audio ssrc, video ssrc) per CNAME that has both.
  std::vector<std::pair<uint32_t, uint32_t>> SyncPairs() const;

  };
  std::map<uint32_t, Info> streams_;
};

}  // namespace sm::sync
```

## Metrics and observability

Every class implements `MetricsSource::ExportMetrics`, so it can be registered in a `MetricsRegistry` and exported as JSON or Prometheus text. Histograms expand to `.count/.mean/.p50/.p95/.p99/.max`.

## Test methods

**Unit tests** (deterministic, no network):

- `StreamSync`: `ConvergesAndPrefersRemovingDelay`, `StepIsBounded`, `GroupsByCname`

**End-to-end test** (sender -> simulated network -> receiver, `tests/e2e/`):

- `E2E_StreamSync`: `LipSyncAcrossPathsAndRouteChange`

Audio (30 ms network, 60 ms buffer) and video (90 ms network, 40 ms decode/render) from one CNAME; at 40 s the video path gains 120 ms. Measures the true A/V offset before sync, after settling and after the route change.
