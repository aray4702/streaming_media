# 8.3 Absolute capture time and glass-to-glass latency

Section 8, *Synchronization*, of [Problems WebRTC solves](../../02-webrtc-problems-solved.md). Problems addressed:

- Capture-to-render latency measurement -> absolute capture time extension, timing extensions

## The issue

Glass-to-glass latency (from camera capture to display on the far side) is the number that matters for interactivity, but it is hard to measure. RTP timestamps start at random values and are rewritten by mixers and SFUs. Sender and receiver clocks are not synchronized, often by seconds. A capture-time field that travels with the media, plus an estimate of the clock offset between machines, makes latency measurable through middleboxes. Sending the field in every packet costs bandwidth, so it should only be sent when the receiver cannot work it out itself.

## Design

extension (http://www.webrtc.org/experiments/rtp-hdrext/abs-capture-time).

Payload: 64-bit NTP capture time (UQ32.32) of the media in the packet, optionally followed by a 64-bit signed estimated capture clock offset (Q32.32) between the capturer's clock and the sender's. Unlike the RTP timestamp it survives mixers and SFUs that rewrite RTP timestamps, so the receiver can measure true glass-to-glass latency.

To save bandwidth the sender only attaches it when the receiver could not interpolate it from the previous one (every `max_interval`, when the RTP clock/source changes, or when the interpolation error would exceed `max_error`). The receiver interpolates for the packets in between, and converts capture time to its own clock using a clock offset estimated from RTCP (sender NTP in SR vs. local receive time, minus RTT/2).

See the [libwebrtc parity inventory](../../design/libwebrtc-parity.md#8-synchronization) for the differences from libwebrtc. 

## Implementation skeleton

Files: [include/sm/sync/capture_time.h](../../../include/sm/sync/capture_time.h), [src/sync/capture_time.cc](../../../src/sync/capture_time.cc).

Public API (generated from the header; private members omitted):

```cpp
namespace sm::sync {

struct AbsoluteCaptureTime {
  uint64_t capture_ntp = 0;                  // UQ32.32
  std::optional<int64_t> clock_offset;       // Q32.32
};

std::vector<uint8_t> SerializeAbsoluteCaptureTime(const AbsoluteCaptureTime& a);
std::optional<AbsoluteCaptureTime> ParseAbsoluteCaptureTime(std::span<const uint8_t> data);

struct CaptureTimeSenderConfig {
  TimeDelta max_interval = TimeDelta::Seconds(1);
  TimeDelta max_error = TimeDelta::Millis(1);
};

class AbsoluteCaptureTimeSender : public MetricsSource {
 public:
  explicit AbsoluteCaptureTimeSender(CaptureTimeSenderConfig cfg = {}) : cfg_(cfg) {}
  // Returns the extension to attach to this packet, or nullopt to omit it.
  std::optional<AbsoluteCaptureTime> OnPacket(uint32_t source, uint32_t rtp, int clock_rate,
                                               const AbsoluteCaptureTime& actual, Timestamp now);
  void ExportMetrics(MetricsWriter& w) const override;

};

class AbsoluteCaptureTimeInterpolator {
 public:
  explicit AbsoluteCaptureTimeInterpolator(TimeDelta max_age = TimeDelta::Seconds(5)) : max_age_(max_age) {}
  // `received`: the extension if present. Returns the (interpolated)
  // capture time for this packet, if known.
  std::optional<AbsoluteCaptureTime> OnPacket(uint32_t source, uint32_t rtp, int clock_rate,
                                               const std::optional<AbsoluteCaptureTime>& received, Timestamp now);

};

// Estimates (sender NTP clock - local clock) from SRs, and turns capture
// times into end-to-end latency at render time.
class LatencyEstimator : public MetricsSource {
 public:
  // An SR sent at sender NTP `sr_ntp` arrived locally at `arrival`.
  void OnSenderReport(timing::NtpTime sr_ntp, Timestamp arrival, TimeDelta rtt);
  // Media with this capture time (sender/capturer clock) is rendered now.
  std::optional<TimeDelta> OnRendered(const AbsoluteCaptureTime& capture, Timestamp render_local);
  std::optional<TimeDelta> remote_to_local_offset() const { return offset_; }
  void ExportMetrics(MetricsWriter& w) const override;

};

}  // namespace sm::sync
```

## Test methods

**Unit tests** (deterministic, no network):

- `CaptureTime`: `WireFormatAndInterpolation`, `SenderOmitsInterpolatableExtensions`, `LatencyWithClockOffset`

**End-to-end test** (sender -> simulated network -> receiver, `tests/e2e/`):

- `E2E_CaptureTime`: `GlassToGlassLatencyThroughSfu`

A sender 2.5 s ahead of the receiver; an SFU rewrites RTP timestamps but forwards abs-capture-time; the receiver learns the clock offset from SRs and measures capture-to-render latency for every frame.

## Verification notes

Portability finding: interpolation used long double, which is software-emulated on WebAssembly and made the benchmark miss its budget there (347 ns vs 200). It now uses exact integer arithmetic.
