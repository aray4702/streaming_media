# 3.2 Forward error correction (XOR, ULPFEC/FlexFEC style)

Section 3, *Packet loss*, of [Problems WebRTC solves](../../02-webrtc-problems-solved.md). Problems addressed:

- Loss where a retransmit would arrive too late (high RTT) -> FEC: ULPFEC, FlexFEC

## The issue

Retransmission costs one round trip: the receiver must notice the gap, the request must reach the sender, and the resent packet must come back. With a 300 ms RTT and a 250 ms playout budget the repaired packet always arrives too late, so on long-distance, satellite or cellular paths NACK alone cannot protect interactive video.

Forward error correction sends redundancy before any loss happens, so the receiver can rebuild a lost packet immediately. The cost is bandwidth that is spent whether or not packets are lost. A parity packet can only rebuild one missing packet from the set it covers, so which packets each parity covers decides whether random losses or bursts of consecutive losses are recoverable.

## Design

Media packets are grouped (typically one video frame per group). For a group of k packets the encoder emits m = ceil(k * protection) parity packets; each one is the XOR of a subset of the group chosen by a mask.

```
  kInterleaved: parity j covers packets i with i % m == j. Any burst of
                up to m consecutive losses is recoverable.
  kBlock:       parity j covers a contiguous block of about k/m packets.
```

The decoder recovers iteratively: any parity packet with exactly one missing protected packet reconstructs it, which may unlock others.

Wire format of a FEC packet payload (big endian):

```
  base_seq:16  mask:64  len_xor:16  ts_xor:32  pt_marker_xor:8  payload_xor
```

A port of libwebrtc's ULPFEC path, file by file:

```
  ForwardErrorCorrection   modules/rtp_rtcp/source/forward_error_correction.cc
  packet masks             forward_error_correction_internal.cc and the
                           fec_private_tables_{random,bursty} masks
  FEC header               ulpfec_header_reader_writer.cc
  UlpfecGenerator          ulpfec_generator.cc (sender, RED wrapping)
  UlpfecReceiver           ulpfec_receiver.cc (RED demux, recovery)
```

with libwebrtc's constants: at most 48 media packets per FEC block, 2- or 6-byte masks (L bit), protection factor in Q8 (0..255 = 0..100% of the media packets), kMinMediaPackets 4 above protection 80, kMaxExcessOverhead 50 (Q8), and the random and bursty mask tables for up to 12 media packets (interleaved masks are generated for 13 or more).

Packets are raw RTP bytes, as in libwebrtc: the FEC XOR covers the first two header bytes, the timestamp, the length after the 12-byte fixed header and everything after it (CSRCs, extensions, payload, padding).

Wire format of one ULPFEC packet, carried as the single block of a RED packet whose block PT is the ULPFEC payload type (RFC 5109 7.3 and 7.4):

```
  E L P X CC M PT-recovery | SN base | TS recovery | length recovery
  protection length | mask (16 bits, or 48 bits when L is set)
  XOR of the protected payloads
```

Not ported (libwebrtc doesn't use it on this path): FlexFEC. Unequal protection is ported (GeneratePacketMasks) but, as in UlpfecGenerator, the generator never asks for it.

See the [libwebrtc parity inventory](../../design/libwebrtc-parity.md#3-packet-loss) for the differences from libwebrtc. Recovery is iterative (peeling decoder): every recovered packet is fed back, which can complete other parity equations. Masks are 64-bit, so groups are capped at 48 packets. The wire format is this library's own (documented in the header), not RFC 8627 FlexFEC; the masking and recovery logic is the same. Issue #29 replaces that format with ULPFEC (RFC 5109) over RED (RFC 2198), ported from libwebrtc M157 (`forward_error_correction.cc`, `forward_error_correction_internal.cc`, `ulpfec_header_reader_writer.cc`, `ulpfec_generator.cc`, `ulpfec_receiver.cc`): `loss/ulpfec.h`, with libwebrtc's random and bursty packet mask tables (read from the pinned prebuilt libwebrtc, as `reference/` has only their headers), interleaved masks above 12 packets, Q8 protection factors, kMinMediaPackets 4 above protection 80 and kMaxExcessOverhead 50. Its first PR adds the module only; the session layer still sends the old format until the next step of #29 switches it over and removes `loss/fec.h`.

## Verification notes

ULPFEC (#29, first PR): unit tests check the RFC 5109 byte layout, the L bit, recovery of every RTP header field across the sequence-number wrap, zero columns for sequence gaps, malformed input, the generator's block rules and RED wrapping, and a generator-to-receiver run with 5% loss. The bursty tables recover every run of up to m consecutive losses for all (k, m) up to 12, as `fec_private_tables_bursty.h` states; the test fails if the random table is used in their place. XOR FEC: a unit test initially expected 2 recoveries but the decoder recovered 3: a packet was rebuilt from parity before its own late arrival, which is correct, so the expectation was fixed.
