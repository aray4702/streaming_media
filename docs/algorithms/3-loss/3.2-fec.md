# 3.2 Forward error correction (XOR, ULPFEC/FlexFEC style)

Section 3, *Packet loss*, of [Problems WebRTC solves](../../02-webrtc-problems-solved.md). Problems addressed:

- Loss where a retransmit would arrive too late (high RTT) -> FEC: ULPFEC, FlexFEC

## The issue

Retransmission costs one round trip: the receiver must notice the gap, the request must reach the sender, and the resent packet must come back. With a 300 ms RTT and a 250 ms playout budget the repaired packet always arrives too late, so on long-distance, satellite or cellular paths NACK alone cannot protect interactive video.

Forward error correction sends redundancy before any loss happens, so the receiver can rebuild a lost packet immediately. The cost is bandwidth that is spent whether or not packets are lost. A parity packet can only rebuild one missing packet from the set it covers, so which packets each parity covers decides whether random losses or bursts of consecutive losses are recoverable.

## Design

Media packets are grouped (typically one video frame per group). For a group of k packets the encoder emits m = ceil(k * protection) parity packets; each one is the XOR of a subset of the group chosen by a mask.

```
  kInterleaved: parity j covers packets i with i % m == j. Any burst of
                up to m consecutive losses is recoverable.
  kBlock:       parity j covers a contiguous block of about k/m packets.
```

The decoder recovers iteratively: any parity packet with exactly one missing protected packet reconstructs it, which may unlock others.

Wire format of a FEC packet payload (big endian):

```
  base_seq:16  mask:64  len_xor:16  ts_xor:32  pt_marker_xor:8  payload_xor
```

See the [libwebrtc parity inventory](../../design/libwebrtc-parity.md#3-packet-loss) for the differences from libwebrtc. Recovery is iterative (peeling decoder): every recovered packet is fed back, which can complete other parity equations. Masks are 64-bit, so groups are capped at 48 packets. The wire format is this library's own (documented in the header), not RFC 8627 FlexFEC; the masking and recovery logic is the same.

## Implementation skeleton

Files: [include/sm/loss/fec.h](../../../include/sm/loss/fec.h), [src/loss/fec.cc](../../../src/loss/fec.cc).

Public API (generated from the header; private members omitted):

```cpp
namespace sm::loss {

enum class FecMaskType { kInterleaved, kBlock };

struct FecParams {
  double protection = 0.0;  // Parity packets per media packet, 0..1.
  FecMaskType mask = FecMaskType::kInterleaved;
};

struct FecConfig {
  uint32_t fec_ssrc = 0;
  uint8_t fec_payload_type = 118;
  int max_group_size = 48;  // Mask is 64 bits; keep headroom.
  EventSink* events = nullptr;
};

struct FecStats {
  uint64_t media_packets = 0;
  uint64_t fec_packets = 0;
  int64_t media_bytes = 0;
  int64_t fec_bytes = 0;
  uint64_t recovered = 0;       // Decoder side.
  uint64_t fec_received = 0;
  uint64_t fec_useless = 0;     // Dropped with nothing to recover.
};

// Mask helper exposed for tests: bit i set = media packet i protected.
uint64_t FecMask(int k, int m, int j, FecMaskType type);
int FecPacketsFor(int k, double protection);

class FecEncoder : public MetricsSource {
 public:
  explicit FecEncoder(FecConfig cfg = {});
  void SetParams(const FecParams& p) { params_ = p; }
  const FecParams& params() const { return params_; }
  // Adds a media packet. When end_of_group is true (e.g. RTP marker at the
  // end of a frame) or the group is full, returns the parity packets.
  std::vector<RtpPacket> AddMediaPacket(const RtpPacket& p, bool end_of_group);
  const FecStats& stats() const { return stats_; }
  void ExportMetrics(MetricsWriter& w) const override;

};

class FecDecoder : public MetricsSource {
 public:
  explicit FecDecoder(FecConfig cfg = {}, size_t window = 512);
  // Feed every received media packet; returns packets recovered as a result.
  std::vector<RtpPacket> OnMediaPacket(const RtpPacket& p);
  std::vector<RtpPacket> OnFecPacket(const RtpPacket& fec);
  const FecStats& stats() const { return stats_; }
  void ExportMetrics(MetricsWriter& w) const override;

  };
  std::vector<RtpPacket> TryRecover();
  void Store(const RtpPacket& p, int64_t useq);
  FecConfig cfg_;
  size_t window_;
  SeqNumUnwrapper<uint16_t> unwrapper_;
  std::map<int64_t, RtpPacket> media_;
  std::deque<Parity> parity_;
  FecStats stats_;
};

}  // namespace sm::loss
```

## Test methods

**Unit tests** (deterministic, no network):

- `Fec`: `MasksCoverEveryPacket`, `RecoversSingleLossExactly`, `InterleavedRecoversBurstUpToM`, `BlockMaskCannotRecoverTwoInSameBlock`, `IterativeRecoveryAcrossParityPackets`, `ZeroProtectionEmitsNothing`

**End-to-end test** (sender -> simulated network -> receiver, `tests/e2e/`):

- `E2E_Fec`: `RandomLossHighRtt`, `InterleavedBeatsBlockOnBursts`

Same video stream at 150 ms one-way delay (NACK disabled): random 5% loss with block masks, and Gilbert-Elliott bursty loss comparing interleaved against block masks. Frames must be complete within the 250 ms budget.
