# 3.4 Packet loss concealment (PCM domain)

Section 3, *Packet loss*, of [Problems WebRTC solves](../../02-webrtc-problems-solved.md). Problems addressed:

- Lost audio frames -> PLC in NetEq (Opus in-band FEC / DRED are codec features, see notes)

## The issue

Some audio will be missing even with FEC, RED and retransmission: a burst longer than the redundancy, or a packet that arrives after its playout time. The audio device still needs 10 ms of samples every 10 ms. Playing silence causes an audible gap and clicks at both edges; repeating the last frame verbatim produces a metallic buzz with a discontinuity at each repetition.

Speech is locally periodic (voiced sounds repeat with the pitch period), so the most natural continuation repeats the last pitch period with smooth joins. That only sounds right for a short time: after a few tens of milliseconds the synthetic tone becomes obviously artificial and must fade out. When real audio resumes, the joint must be crossfaded or it clicks. Opus has its own concealment and FEC, but G.711, raw PCM and many embedded decoders do not.

## Design

For each lost frame the concealer extends the signal by repeating the last pitch period (found by normalized autocorrelation), mixes in matched-level noise when the history is unvoiced, and fades out after `fade_start` so long outages decay to silence. When real audio resumes it crossfades from the synthetic continuation into the new frame to avoid a click.

Codecs with built-in recovery (Opus LBRR in-band FEC, DRED, NetEq's codec-internal PLC) should be preferred when available; this module is the fallback that works for any PCM source (G.711, raw PCM, decoder without PLC) and the "expand" operation used by the audio jitter buffer.

See the [libwebrtc parity inventory](../../design/libwebrtc-parity.md#3-packet-loss) for the differences from libwebrtc. Opus LBRR (in-band FEC) and DRED live inside the Opus codec and are used automatically when the codec is Opus; they are not reimplemented here. This module is the codec-agnostic fallback and the 'expand' operation of the audio jitter buffer (4.5).

## Implementation skeleton

Files: [include/sm/loss/plc.h](../../../include/sm/loss/plc.h), [src/loss/plc.cc](../../../src/loss/plc.cc).

Public API (generated from the header; private members omitted):

```cpp
namespace sm::loss {

struct PlcConfig {
  int sample_rate = 16000;
  int min_pitch_hz = 60;
  int max_pitch_hz = 400;
  float fade_start_ms = 10;   // Full-level concealment before fading.
  float fade_length_ms = 50;  // Linear fade to silence after that.
  float merge_ms = 5;         // Crossfade length into resumed audio.
  float voiced_threshold = 0.5f;
};

struct PlcStats {
  uint64_t good_frames = 0;
  uint64_t concealed_frames = 0;
  uint64_t concealed_samples = 0;
  uint64_t concealment_events = 0;  // Bursts of consecutive concealed frames.
  uint64_t merges = 0;
  Histogram burst_length_frames;
  int last_pitch_lag = 0;
  float last_correlation = 0;
};

class PacketLossConcealer : public MetricsSource {
 public:
  explicit PacketLossConcealer(PlcConfig cfg = {});

  // Call with every decoded frame. Modified in place when it follows a
  // concealed frame (crossfade).
  void OnGoodFrame(std::span<float> frame);
  // Produces `out.size()` samples of concealment.
  void Conceal(std::span<float> out);

  bool in_concealment() const { return concealing_; }
  // Gain of the next concealed sample (1 outside a concealment): the fade
  // that NetEq's Expand::MuteFactor tracks.
  float gain() const;
  const PlcStats& stats() const { return stats_; }
  void ExportMetrics(MetricsWriter& w) const override;

};

}  // namespace sm::loss
```

## Test methods

**Unit tests** (deterministic, no network):

- `Plc`: `ContinuesPeriodicSignal`, `FadesToSilenceOnLongLoss`, `MergeAvoidsDiscontinuity`, `UnvoicedHistoryUsesNoise`

**End-to-end test** (sender -> simulated network -> receiver, `tests/e2e/`):

- `E2E_Plc`: `SpeechOverLossyLink`

20 s of synthetic voiced speech, 10 ms frames, 10% random loss. Compares the whole-signal SNR of the concealed output against zero insertion, and the SNR/level inside the lost frames.
