# 3.7 NACK/FEC protection selection

Section 3, *Packet loss*, of [Problems WebRTC solves](../../02-webrtc-problems-solved.md). Problems addressed:

- Picking a protection level -> loss-rate-driven trade-off between FEC and NACK, based on RTT

## The issue

NACK and FEC protect against loss in different regimes, and a fixed choice is wrong most of the time. NACK costs almost nothing when there is no loss but adds one round trip of delay per repair, which is useless when the RTT is long. FEC repairs instantly but always costs bandwidth, which wastes capacity on clean links and steals bitrate from the video itself.

The right mix depends on the current RTT, the loss rate and whether losses come in bursts, and all three change during a call (Wi-Fi to LTE, a congested hop). Choosing too little FEC leaves frames broken; choosing too much reduces quality and can even cause the congestion that creates the loss.

## Design

FecControllerDefault (modules/video_coding/fec_controller_default.cc) with media_opt_util.cc's VCMLossProtectionLogic and protection methods, read from compare/webrtc/reference/ (issue #29).

- The method is fixed by what the stream has on (SetProtectionMethod, as

```
  RtpVideoSender's constructor calls it): kNackFec with NACK and FEC,
  kFec with FEC alone, kNack with NACK alone, kNone with neither. Only the
  FEC methods ask for FEC; kNone makes no protection request at all.
```

- The loss is a max filter over 10 s (kLossPrHistorySize 10 windows of

```
  kLossPrShortFilterWinMs 1000 ms) of the fraction lost the network
  estimate carries.
```

- The delta-frame code rate comes from kFecRateTable (fec_rate_table.h),

```
  indexed by the effective bits per frame (scaled by the resolution against
  704x576) and the filtered loss in 1/255, at least 20% (first partition)
  once there is loss and more than one packet per frame, at most 128/255.
  Key frames get the larger of the table at the boosted rate, twice the
  delta rate and the loss itself, also capped at 128/255.
```

- kNackFec drops the delta rate to 0 below kLowRttNackMs (20 ms RTT) and

```
  keeps it above (the RTT adjustment is the constant 1.0; NACK is never
  switched off), turns FEC off altogether when a frame is smaller than
  400/700/1000 bytes (by resolution) with an RTT under 200 ms
  (BitRateTooLowForFec), and spreads FEC over max(2 * fps * RTT + 0.5, 1)
  frames, at most 6 (kUpperLimitFramesFec). kFec uses one frame.
```

- The rates are converted from "of all packets" to "of the media packets"

```
  (ConvertFECRate), the Q8 rate ULPFEC's generator takes, and the masks are
  always random.
```

The other half of FecControllerDefault::UpdateFecRates, the encoder rate (the target less the measured RTX and FEC share, capped at 0.5), is rtp::SendSideController::AllocatedVideoTarget. Takes `now`, reads no clock and starts no thread.

See the [libwebrtc parity inventory](../../design/libwebrtc-parity.md#3-packet-loss) for the differences from libwebrtc. A port of libwebrtc M157's `FecControllerDefault` (`modules/video_coding/fec_controller_default.cc`) with `media_opt_util.cc`'s `VCMLossProtectionLogic`, `VCMFecMethod` and `VCMNackFecMethod` and the `kFecRateTable` of `fec_rate_table.h`, copied value for value (#29). The method follows what the stream has on (`kNackFec`, `kFec`, `kNack`, `kNone`); the loss is the max of the last 10 one-second windows; the delta rate comes from the table by effective bits per frame and loss, at least 20% with loss and more than one packet per frame, at most 128/255; key frames get at least twice that and the loss; `kNackFec` sends no delta FEC below 20 ms RTT, none at all for small frames under 200 ms RTT (`BitRateTooLowForFec`), and spreads FEC over up to 6 frames by RTT. The rates are converted to a share of the media packets (`ConvertFECRate`) and the masks are random. `rtp::Session` owns one per video send stream, as `RtpVideoSender` does: it calls `UpdateFecRates` when the target, the fraction lost or the RTT changes (`CongestionControlHandler::GetUpdate`), with the video payload rate, the sent frame rate and GoogCC's fraction lost, and sets the delta and key parameters on the sender; `UpdateWithEncodedData` runs on every frame and `SetVideoEncodingData` on each encoder reconfiguration. The encoder rate half of `UpdateFecRates` (the measured protection share, capped at 0.5) is `SendSideController::AllocatedVideoTarget`. The sent frame rate is `SendStatisticsProxy::GetSendFrameRate` (`video/send_statistics_proxy.cc`, #710): libwebrtc's `RateTracker` (`sm::RateTracker`, 10 buckets of 100 ms) counts each encoded frame, starts at the first captured frame (`OnIncomingFrame`), reports 0 for its first 100 ms and is rounded; `Session` exports it as `video_encode_frame_rate`. Remaining difference: `_corrFecCost` is not computed, since M157 reads it nowhere.

## Implementation skeleton

Files: [include/sm/loss/fec_controller.h](../../../include/sm/loss/fec_controller.h), [src/loss/fec_controller.cc](../../../src/loss/fec_controller.cc).

Public API (generated from the header; private members omitted):

```cpp
namespace sm::loss {

// media_optimization::VCMProtectionMethodEnum.
enum class ProtectionMethod : uint8_t { kNack, kFec, kNackFec, kNone };

// What FecControllerDefault hands to VCMProtectionCallback::ProtectionRequest.
struct FecProtectionRequest {
  ulpfec::FecProtectionParams delta;
  ulpfec::FecProtectionParams key;
};

class FecControllerDefault : public MetricsSource {
 public:
  // media_optimization::kLowRttNackMs, the kNackFec method's low threshold.
  static constexpr int64_t kLowRttNackMs = 20;

  explicit FecControllerDefault(EventSink* events = nullptr);

  // SetProtectionMethod: kNackFec, kNack, kFec or kNone.
  void SetProtectionMethod(bool enable_fec, bool enable_nack);
  ProtectionMethod method() const { return method_; }
  // SetEncodingData, on each encoder (re)configuration: the resolution, the
  // temporal layers and RtpConfig::max_packet_size. Until the first call:
  // 704x576, one layer, 1460 bytes.
  void SetEncodingData(size_t width, size_t height, size_t num_temporal_layers, size_t max_payload_size);
  // UpdateWithEncodedData, for each encoded frame: the packets per frame
  // (size / max payload) of delta and key frames, filtered with
  // ExpFilter(0.9999) over the ms since the previous frame of that type.
  void UpdateWithEncodedData(size_t encoded_size, bool keyframe, Timestamp now);
  // UpdateFecRates, on each network estimate change (RtpVideoSender::
  // OnBitrateUpdated): the video payload rate, the sent frame rate, the
  // fraction lost (0-255) and the RTT. Returns the protection request, or
  // nullopt for kNone (no request is made).
  std::optional<FecProtectionRequest> UpdateFecRates(DataRate estimated_bitrate, int actual_framerate_fps,
                                                     uint8_t fraction_lost, int64_t round_trip_time_ms, Timestamp now);

  // VCMLossProtectionLogic state, for tests and metrics.
  uint8_t filtered_loss() const { return filtered_loss_; }
  float packets_per_frame() const { return packets_per_frame_.filtered; }
  float packets_per_frame_key() const { return packets_per_frame_key_.filtered; }
  int max_frames_fec() const { return max_frames_fec_; }
  const FecProtectionRequest& last() const { return last_; }
  void ExportMetrics(MetricsWriter& w) const override;

  };
  // VCMProtectionParameters.
  struct Params {
    int64_t rtt = 0;
    float loss_pr = 0;
    float bit_rate = 0;
    float packets_per_frame = 0;
    float packets_per_frame_key = 0;
    float frame_rate = 0;
    uint16_t codec_width = 0;
    uint16_t codec_height = 0;
    int num_layers = 1;
  };
  // VCMFecMethod::ProtectionFactor and BitsPerFrame; VCMNackFecMethod's.
  void FecProtectionFactor(const Params& p);
  int BitsPerFrame(const Params& p) const;
  bool BitRateTooLowForFec(const Params& p) const;
  int ComputeMaxFramesFec(const Params& p) const;
  // VCMLossProtectionLogic::UpdateMethod with the selected method's UpdateParameters.
  void UpdateMethod(const Params& p);
  // VCMLossProtectionLogic::UpdateMaxLossHistory and MaxFilteredLossPr.
  void UpdateMaxLossHistory(uint8_t loss_pr255, int64_t now_ms);
  uint8_t MaxFilteredLossPr(int64_t now_ms) const;

  static constexpr int kLossPrHistorySize = 10;
  static constexpr int kLossPrShortFilterWinMs = 1000;
  struct LossSample {
    uint8_t loss_pr255 = 0;
    int64_t time_ms = -1;
  };

  EventSink* events_;
  ProtectionMethod method_ = ProtectionMethod::kNone;
  size_t max_payload_size_ = 1460;
  size_t codec_width_ = 704, codec_height_ = 576;
  int num_layers_ = 1;
  ExpFilter packets_per_frame_, packets_per_frame_key_;
  int64_t last_packets_per_frame_update_ms_ = 0, last_packets_per_frame_key_update_ms_ = 0;
  LossSample loss_history_[kLossPrHistorySize];
  uint8_t short_max_loss_pr255_ = 0;
  uint8_t filtered_loss_ = 0;
  // The selected method's protection factors (VCMProtectionMethod) and max frames.
  uint8_t protection_factor_k_ = 0, protection_factor_d_ = 0;
  int max_frames_fec_ = 1;
  FecProtectionRequest last_;
  uint64_t updates_ = 0, requests_with_fec_ = 0;
};

}  // namespace sm::loss
```

## Verification notes

Unit tests (`FecController`) check the table rates against values worked out by hand from `kFecRateTable`, the first-partition minimum, the 128/255 cap, the 10 s max filter, the 20 ms NACK-only threshold, `BitRateTooLowForFec`, `max_fec_frames` and the packets-per-frame filter. `E2E_Protection.AdaptiveAcrossRtt`: NACK only at 18 ms RTT (overhead 5%), FEC from 20 ms (overhead 45% at 20 ms, 39% at 80, 35% at 300; libwebrtc's table at 1.9 Mbps and 5% loss), on time 99.3% or more. On `issue_29_ulpfec_over_red`, seeds 1-10, FEC goes from 375 to 392 kbps (libwebrtc 444) and video e2e p95 from 174 to 242 ms (libwebrtc 232). The sent frame rate (#710): `RateTracker` ports libwebrtc's `rate_tracker_unittest.cc`, and `Session.SentFrameRateIsSendStatisticsProxysRateTracker` and `VideoSendController.SentFrameRateStartsAtTheFirstCapturedFrame` check the rate the protection logic takes; on `issue_29_ulpfec_over_red` seeds 1-80 the means stay within seed spread (`video.avg_kbps` 973.6 -> 976.9, libwebrtc 986.8; FEC 498 -> 494 kbps). Video RED+ULPFEC is off beside NACK for H.264 and Generic, as libwebrtc's `ShouldDisableRedAndUlpfec` decides (`rtp::ShouldDisableRedAndUlpfec`, [fix record #7](../../fixes/7-no-fec-beside-nack.md)); the controller only runs where libwebrtc would protect (NACK off, or VP8/VP9).
