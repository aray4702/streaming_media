# 9.2 RTP sender and send-side controller

Section 9, *RTP/RTCP session layer*, of [Problems WebRTC solves](../../02-webrtc-problems-solved.md). Problems addressed:

- Packetization, sequence numbers, RTX history and RED -> RtpSender
- Pacing, transport-wide sequence numbers and congestion control hand-off -> SendSideController

## The issue

Without a sender component, every application turns encoded frames into packets itself: sequence numbers, payload types, timestamps, marker bits, RED wrapping for audio, a history for retransmission and the pacing that keeps a keyframe from leaving as one burst. Mistakes here are silent: a wrong sequence number breaks NACK, a packet missing from the history cannot be repaired, and an unpaced burst fills the bottleneck queue. The congestion controller also needs every packet numbered and timed in the same order in which it is sent, so packetizing and pacing have to agree.

## Design

RTP sender of one media stream (docs/design/rtp-session.md, sections 4.3 and 7): turns encoded frames into RTP packets. It assigns sequence numbers, SSRC, payload type, timestamps and the marker bit, writes the MID header extension, wraps audio in RED (RFC 2198), keeps the packet history and answers NACKs with RTX (RFC 4588), and feeds the optional ULPFEC generator. It does not send anything: every packet is handed out through TakePackets() with the pacer priority it needs, and rtp::SendSideController paces, numbers (transport-wide sequence number) and serializes it.

Payloads are opaque chunks here, as in the test bench today. A codec packetizer (H.264, plan PR 7) supplies the chunks. Takes `now`, reads no clock and starts no thread.

Send-side controller of the RTP session layer (docs/design/rtp-session.md, sections 5.1 and 7): one per transport, shared by every stream. It owns the pacer, the GCC network controller and the outage monitor, and ties them to the packets of rtp::RtpSender:

```
  - Enqueue() hands a packet to the pacer with its priority;
  - Process() releases what is due, writes the transport-wide sequence
    number (and abs-send-time when negotiated), tells GCC about the send
    (libwebrtc's PacketRouter::SendPacket),
    counts the bytes of the 500 ms send-rate window, and returns datagrams
    ready for the socket;
  - transport feedback, RTT and REMB go to GCC, and the new target and
    pacing rate come back as `target()` and `rates()`;
  - the GCC process interval (25 ms) runs from Process(). As in libwebrtc,
    nothing pauses the encoder on a feedback time-out: the outage monitor
    only follows the link (#151), and TakeActions() stays empty.
```

Padding and probes are real padding-only RTP packets made by the padding stream registered with SetPaddingSender().

ComputeRates() is the test bench's original video_rate() arithmetic: target minus the audio wire rate, divided by (1 + FEC protection) and clamped. ComputeMeasuredRates() is what the session uses (issue #21): the share taken off is what RTX and FEC actually used in the last second, as in libwebrtc's FecControllerDefault. Both are then lowered by congestion-window pushback (cc/congestion_window_pushback.h). Takes `now`, reads no clock and starts no thread.

See the [libwebrtc parity inventory](../../design/libwebrtc-parity.md#9-rtp-session-layer) for the differences from libwebrtc. RtpSender builds packets and never sends; every packet leaves through TakePackets() with a pacer priority. SendSideController (one per transport) numbers, paces and serializes them. Padding and probes are real padding-only RTP packets. RTX of RED is retransmitted as sent, as in libwebrtc's RtxReceiveStream. Packet size is capped at 1200 bytes, libwebrtc's kVideoMtu. Interop for RTP with MID, transport-cc and abs-send-time, RTX and padding is in compare/webrtc/rtcp_interop.cc. The encoder budget (SendSideController::ComputeMeasuredRates) takes off the share of the video stream's send rate that was RTX or FEC, capped at 50%, as libwebrtc's FecControllerDefault::UpdateFecRates (compare/webrtc/reference/modules/video_coding/fec_controller_default.cc). By default the share is of the last second's bytes. `send_rate_stats` (off; #224) measures it as libwebrtc does, from one RateStatistics per media type (RtpSenderEgress::GetSendRates, rtp_sender_egress.cc:340, rtc_base/rate_statistics.cc): a repair stream that starts after 1.5 s without one counts at its rate since it started, so the share reaches the cap within about 100 ms of the RTX that follows a capacity drop, instead of over a second. There is no retransmission rate cap, as in M157. Differences that remain: the FEC amount (#7, FecControllerDefault's media_opt_util choice) and keyframe requests (#23); the encoder floor of 30 kbps applies even when the audio alone exceeds the target (#37).

namespace sm::rtp {

enum class PacketKind : uint8_t { kAudio, kVideo, kRtx, kFec, kPadding };

class RtpSender;

// One RTP packet on its way to the pacer.
struct SenderPacket {
  RtpPacket packet;
  PacketKind kind = PacketKind::kVideo;
  cc::PacketPriority priority = cc::PacketPriority::kVideo;
  bool is_key_frame = false;  // Video media packet of a keyframe.
  bool first_packet_of_frame = false;
  RtpSender* sender = nullptr;  // The stream that made it, told when the pacer sends it.
};

struct RtpSenderConfig {
  uint32_t ssrc = 1;
  uint8_t payload_type = 96;
  int clock_rate = 90000;  // 90000 video, 48000 Opus.
  bool video = true;       // Picks the packet kind and pacer priority.
  uint16_t initial_seq = 0;
  // Largest payload of one video packet (the whole packet stays within
  // libwebrtc's kVideoMtu of 1200 bytes). Clamped so the whole packet (with
  // the 12-byte fixed header) is 100 to 1500 bytes, the range libwebrtc's
  // RTPSender::SetMaxRtpPacketSize accepts: a smaller value would leave no
  // room for padding or media (issue #257).
  size_t max_payload_size = 1200 - 12;

  // RTX (RFC 4588). Without an RTX SSRC, NACKs cannot be answered.
  std::optional<uint32_t> rtx_ssrc;
  uint8_t rtx_payload_type = 97;
  loss::RtxConfig rtx;  // History size; its SSRC and payload type are overwritten.

  // RED (RFC 2198), audio. `red_distance` previous frames are repeated.
  std::optional<uint8_t> red_payload_type;
  int red_distance = 1;

  // Video RED (RFC 2198) + ULPFEC (RFC 5109), as libwebrtc's RTPSenderVideo
  // and RtpSenderEgress with a UlpfecGenerator: every media packet is wrapped
  // in RED, and the FEC packets go on the media SSRC.
  bool fec = false;
  loss::ulpfec::UlpfecConfig ulpfec;

  // MID (RFC 8843) is written on the first `mid_packets` packets, or until
  // AcknowledgeMid() when the peer has answered. Needs the extension mapped.
  std::string mid;
  int mid_packets = 0;
  const sync::ExtensionMap* extensions = nullptr;  // Not owned; must outlive the sender.

  EventSink* events = nullptr;
};

struct RtpSenderStats {
  uint64_t media_packets = 0;
  int64_t media_payload_bytes = 0;  // Payload octets of media packets, what the SR counts.
  uint64_t frames = 0;
  uint64_t fec_packets = 0;
  int64_t fec_payload_bytes = 0;
  uint64_t rtx_packets = 0;
  uint64_t padding_packets = 0;
  uint64_t payload_padding_packets = 0;  // RTX payload padding (GeneratePadding), a subset of padding_packets.
  uint64_t nacks_without_rtx = 0;
  uint64_t mid_packets = 0;
  uint64_t audio_level_packets = 0;
};

// Splits `bytes` into the fewest chunks of at most `max_payload` bytes, as
// even as possible (the first chunks take the remainder), like the test
// bench's frame packetization.
std::vector<size_t> SplitEvenly(size_t bytes, size_t max_payload);

class RtpSender : public MetricsSource {
 public:
  explicit RtpSender(RtpSenderConfig cfg = {});

  // Audio: one frame becomes one packet (RED-wrapped when configured).
  // With `level` and the audio-level extension (RFC 6464) mapped, the packet
  // carries it, as libwebrtc's ChannelSend does when the level id is set.
  void SendAudio(std::span<const uint8_t> frame, uint32_t rtp_timestamp, bool marker, Timestamp now,
                 std::optional<audio::AudioLevel> level = std::nullopt);
  // Header bytes of the next media packet with the extensions it will carry
  // (transport-cc, abs-send-time and, while it is repeated, MID): what
  // libwebrtc's RtpSenderVideo reads from the packet templates to size the
  // payload (rtp_sender_video.cc, `max_payload_len`).
  size_t MediaHeaderSize() const;
  // Video: one packetized frame. The marker is set on the last chunk. With
  // FEC each packet is wrapped in RED (rtp_sender_video.cc BuildRedPayload).
  // `keyframe` marks its media packets for the pacer (keyframe flush).
  void SendVideoFrame(std::span<const std::vector<uint8_t>> chunks, uint32_t rtp_timestamp, Timestamp now,
                      bool keyframe = false);

  // The pacer is releasing `p` (SendSideController::Process, before OnPacketReleased). A media or
  // FEC packet gets its RTP sequence number here, as libwebrtc's PacketRouter does
  // (modules/pacing/packet_router.cc:217, rtp_rtcp_impl2.cc:352); until then it carries 0.
  void AssignSequenceNumber(SenderPacket& p);
  // The pacer sent `p` (SendSideController::Process). The RTX history takes media packets
  // here (the packet as it goes out, RED-wrapped when RED is in use, so a resend is identical
  // apart from the RTX header) and learns that a resend left the queue. With FEC a video
  // packet goes to the ULPFEC generator without its RED header (RtpSenderEgress::SendPacket,
  // rtp_sender_egress.cc:186-216), so the FEC covers the numbered packet.
  void OnPacketReleased(const SenderPacket& p, Timestamp now);
  // The FEC packets the last OnPacketReleased generated, for the pacer to enqueue
  // (PacketRouter::FetchFec, PacingController::ProcessPackets). Their sequence numbers are
  // assigned when the pacer releases them.
  std::vector<SenderPacket> TakeFecPackets();
  // Bytes a video packet's payload leaves for FEC: RTPSenderVideo::FecPacketOverhead
  // (rtp_sender_video.cc:263-280), the ULPFEC header, the RED header and the header
  // extensions an FEC packet can carry (kFecOrPaddingExtensionSizes). 0 without FEC.
  size_t FecPacketOverhead() const;
  // A measured RTT (history retention).
  void SetRtt(TimeDelta rtt, Timestamp now) { rtx_.SetRtt(rtt, now); }
  // Packets the peer acknowledged by transport-wide feedback leave the history.
  void OnAcknowledged(std::span<const uint16_t> seqs) { rtx_.CullAcknowledged(seqs); }

  // NACK from the peer (RtcpIncoming::nacks). The RTX packets are queued for
  // the pacer at retransmission priority.
  void OnNack(std::span<const uint16_t> seqs, Timestamp now, TimeDelta rtt);

  // A padding-only packet whose whole size is as close to `total_bytes` as
  // padding allows (at least a header plus one byte, at most 255 bytes of
  // padding). On the RTX SSRC when RTX is configured, like libwebrtc's
  // RTPSender::GeneratePadding, else on the media SSRC.
  SenderPacket MakePadding(size_t total_bytes, uint32_t rtp_timestamp, Timestamp now);

  // RTPSender::GeneratePadding (rtp_sender.cc:418-459), for a sender with RTX:
  // `target_bytes` of padding for the pacer, as a list of packets with their real
  // sizes. A video sender first answers with RTX payload padding, the newest large packet of
  // the history resent on the RTX SSRC (AppendPayloadPadding: only while at least
  // kMinPayloadPaddingBytes (50) are left, and never a packet that takes the total over
  // kMaxPaddingSizeFactor (3.0) x the target); the remainder is empty padding on the RTX
  // SSRC, packets of kMaxPaddingLength (255) bytes (an audio sender: of the bytes left, at
  // least kMinAudioPaddingLength (50)). Like libwebrtc, with RTX the empty padding waits for
  // a media packet unless transport-cc or abs-send-time is registered. All of them are
  // PacketKind::kPadding at padding priority; nothing is queued, the caller enqueues them.
  std::vector<SenderPacket> GeneratePadding(size_t target_bytes, uint32_t rtp_timestamp, Timestamp now);

  // The peer acknowledged the MID: stop repeating it.
  void AcknowledgeMid() { mid_remaining_ = 0; }

  // FEC protection for the next frames, for delta and key frames alike; the
  // generator applies them from the next protected packet.
  void SetFecParams(const loss::ulpfec::FecProtectionParams& p) { SetFecParams(p, p); }
  // RtpRtcp::SetFecProtectionParams: what loss::FecControllerDefault asks for each frame type.
  void SetFecParams(const loss::ulpfec::FecProtectionParams& delta, const loss::ulpfec::FecProtectionParams& key);
  // The delta-frame and key-frame parameters last set.
  const loss::ulpfec::FecProtectionParams& fec_params() const { return fec_params_; }
  const loss::ulpfec::FecProtectionParams& key_fec_params() const { return key_fec_params_; }
  // The ULPFEC generator, when FEC is on.
  const loss::ulpfec::UlpfecGenerator* ulpfec() const { return ulpfec_.get(); }

  // Everything queued since the last call, in the order to enqueue it.
  std::vector<SenderPacket> TakePackets();

  // Counters of the media stream for the RTCP sender report.
  RtcpSenderState SenderState() const;
  // RTP timestamp of the last media packet; padding carries it, like libwebrtc.
  uint32_t last_rtp_timestamp() const { return last_rtp_timestamp_; }
  const RtpSenderConfig& config() const { return cfg_; }
  const RtpSenderStats& stats() const { return stats_; }
  const loss::RtxSender& rtx() const { return rtx_; }
  void ExportMetrics(MetricsWriter& w) const override;

};

}  // namespace sm::rtp

namespace sm::rtp {

struct SendSideConfig {
  // libwebrtc's GoogCC and PacingController (#61; their v1 alternatives were deleted in #167).
  cc::GccConfig gcc;
  cc::PacerConfig pacer;
  cc::OutageConfig outage;
  cc::CongestionWindowConfig cwnd;
  // Bytes the transport adds to every datagram (UDP + IPv4), counted in the
  // pacer budget and in GCC's send history.
  int64_t transport_overhead_bytes = 28;
  TimeDelta gcc_interval = TimeDelta::Millis(25);
  TimeDelta send_rate_window = TimeDelta::Millis(500);
  // Largest share of the sending rate repair traffic may take away from the
  // video encoder (libwebrtc FecControllerDefault::overhead_threshold_).
  double max_repair_share = 0.5;
  TimeDelta repair_window = TimeDelta::Seconds(1);
  // How the repair share is measured (issue #224). On: one RateStatistics per
  // media type, as RtpSenderEgress::GetSendRates, so a repair stream that has
  // just started (after 1.5 windows without one) counts at its rate since it
  // started. Off: the bytes of each type over the last `repair_window`.
  bool send_rate_stats = false;
  // The transport's CongestionControlHandler between GoogCC and the allocator (cc/control_handler.h,
  // issue #204): the allocator, and with it the encoder target and its protection share, changes only
  // when the handler passes an update on, and the encoder pauses while the pacer queue is above 2 s.
  // Off: every GoogCC update reallocates and the encoder reads the live protection share (until the
  // port is judged against libwebrtc as a whole, program.md 0.2).
  bool control_handler = false;
  DataRate video_min = DataRate::KilobitsPerSec(30);
  DataRate video_max = DataRate::KilobitsPerSec(10000);
  // With the allocator (RtpVideoSender::OnBitrateUpdated): the packet size
  // the overhead rate is computed for (RTP max_packet_size; the transport
  // overhead is added) and the RTP header bytes of a media packet (12 plus the
  // transport-wide sequence number and abs-send-time extensions; libwebrtc's
  // ExpectedPerPacketOverhead is the header the sender actually builds).
  int64_t max_packet_size = 1200;
  int64_t rtp_overhead_bytes = 24;
  EventSink* events = nullptr;
};

// The split of the target the encoders need (design 7.3).
struct SendRates {
  DataRate target;       // GCC target for everything the session sends.
  DataRate audio_rate;   // Audio wire rate taken off first.
  DataRate video_target; // What the video encoder may produce (after congestion-window pushback).
  // Congestion-window pushback (issue #53): drop every N-th captured frame
  // (0 = none); `video_target` is already lowered to match. See
  // SendSideController::DropCapturedFrame().
  int frame_drop_interval = 0;
  // `control_handler`: the last update passed on had a zero target (the pacer queue above 2 s), so the
  // encoder drops every captured frame (VideoStreamEncoder::EncoderPaused).
  bool encoder_paused = false;
};

// A datagram released by the pacer.
struct ReleasedPacket {
  std::vector<uint8_t> bytes;  // RTP, ready for the socket (SRTP is the host's job).
  PacketKind kind = PacketKind::kVideo;
  // Transport-wide sequence number. Numbering starts at 1, as libwebrtc's
  // PacketRouter, and a packet without the extension mapped has none (0) and is not reported to GCC.
  uint16_t transport_seq = 0;
  DataSize wire_size;          // Size the pacer and GCC accounted, with transport overhead.
  int probe_cluster = -1;
  Timestamp send_time;
};

struct ControllerActions {
  bool pause_encoder = false;
  bool resume_encoder = false;
  bool request_keyframe = false;
};

struct SendSideStats {
  uint64_t released = 0;
  uint64_t padding = 0;
  uint64_t unknown_ids = 0;
  uint64_t flushed = 0;  // Packets a keyframe flushed from the pacer queue.
  int64_t released_bytes = 0;
};

class SendSideController : public MetricsSource {
 public:
  // `extensions` (not owned, may be null) maps the transport-wide sequence
  // number and abs-send-time; without them the packets carry neither.
  explicit SendSideController(SendSideConfig cfg = {}, const sync::ExtensionMap* extensions = nullptr);

  void Start(Timestamp now);

  // Registers the streams with libwebrtc's BitrateAllocator
  // (call/bitrate_allocator.cc, issue #104), as
  // AudioSendStream::ConfigureBitrateObserver and VideoSendStreamImpl::
  // GetAllocationConfig do, and lifts the network controller's lower bound to the
  // sum of the enforced minimums. Call before Start(). `audio_wire_rate` is the
  // fixed audio rate (min = max = priority rate, enforce_min true, as for a
  // constant-bitrate Opus stream); zero means no audio stream. The video stream
  // (min `video_min`, max `video_max`, enforce_min true: suspend_below_min_bitrate
  // is off by default) is registered when `video` is true.
  void ConfigureAllocation(DataRate audio_wire_rate, bool video);

  // The stream whose SSRC pads and probes. Not owned.
  void SetPaddingSender(RtpSender* sender);

  // RtpTransportControllerSend::SetPacingFactor: the pacing factor of the
  // streams (StreamsConfig::pacing_factor), which GoogCC uses in place of its
  // defaults (cc::GccController::SetPacingFactor). The session sets 1.1 when it
  // adds a video stream with transport-cc, as VideoSendStreamImpl does (#187).
  void SetPacingFactor(double factor);

  // RtpTransportControllerSend::EnablePeriodicAlrProbing (StreamsConfig::
  // requests_alr_probing): ALR probes every 5 s while application limited. The
  // session requests it for an audio stream with transport-cc, as
  // AudioSendStream::ConfigureStream does unless WebRTC-Audio-AlrProbing is
  // disabled (audio_send_stream.cc:158-159, 297-308; issue #62).
  void EnablePeriodicAlrProbing(bool enable);

  void Enqueue(SenderPacket p, Timestamp now);
  // Releases due packets, and runs the GCC timer.
  std::vector<ReleasedPacket> Process(Timestamp now);
  Timestamp NextProcessTime(Timestamp now) const;

  // Feedback from the peer.
  void OnTransportFeedback(const cc::TransportFeedback& fb, Timestamp now);
  void OnRtt(TimeDelta rtt) { gcc_.OnRttUpdate(rtt); }
  void OnRemb(DataRate remb) { gcc_.OnRemb(remb); }
  // Loss between two receiver reports (GoogCC OnTransportLossReport).
  void OnLossReport(int64_t packets_lost_delta, int64_t packets_delta, Timestamp now);

  // Encoder pause/resume and keyframe decisions since the last call. Nothing makes
  // them since the v1 outage handling was deleted (#167): libwebrtc has none.
  ControllerActions TakeActions();

  // Encoder side of congestion-window pushback: call once per captured frame
  // before encoding it; true means skip the frame (libwebrtc
  // VideoStreamEncoder::OnFrame, cwnd_frame_drop).
  bool DropCapturedFrame();

  DataRate target() const { return target_; }
  DataRate send_rate(Timestamp now);
  // RtpVideoSender::OnBitrateUpdated's payload rate: the video allocation less
  // the packet overhead rate, which FecControllerDefault::UpdateFecRates takes.
  // Zero without an allocation (ConfigureAllocation).
  DataRate VideoPayloadRate() const;
  SendRates ComputeRates(DataRate audio_wire_rate, double fec_protection) const;
  // As above, but the share taken off is what the sender actually spent on
  // RTX and FEC in the last second, exactly as libwebrtc's FecControllerDefault::
  // UpdateFecRates does: (sent_nack + sent_fec) / (video + nack + fec), capped at
  // `max_repair_share` (0.5).
  SendRates ComputeMeasuredRates(DataRate audio_wire_rate) const;
  // Share of the video stream's send rate that was RTX or FEC, as of the last Process(): of the bytes
  // released in the last `repair_window`, or with `send_rate_stats` of RtpSenderEgress::GetSendRates'
  // rates (RateStatistics over `repair_window`), where a repair stream that has just started counts at
  // its rate since it started.
  double repair_share() const;

  const cc::BitrateAllocatorV2& allocator() const { return allocator_; }
  cc::GccController& gcc() { return gcc_; }
  cc::Pacer& pacer() { return pacer_; }
  cc::OutageMonitor& outage() { return outage_; }
  const cc::CongestionWindowPushback& congestion_window() const { return cwnd_; }
  const SendSideStats& stats() const { return stats_; }
  void ExportMetrics(MetricsWriter& w) const override;

  };
  std::unordered_map<uint16_t, SentMedia> sent_media_;
  uint64_t next_id_ = 1;
  uint16_t transport_seq_ = 0;
  struct Released {
    Timestamp time;
    int64_t bytes;
    PacketKind kind;
  };
  void ExpireRepair(Timestamp now);
  std::deque<Released> repair_window_;
  int64_t repair_bytes_ = 0, video_bytes_ = 0;
  // `send_rate_stats`: RtpSenderEgress::send_rates_, one BitrateTracker per media
  // type over `repair_window` (kBitrateStatisticsWindow, 1 s), read as of the last Process().
  RateStatistics video_rate_, rtx_rate_, fec_rate_;
  Timestamp last_process_ = Timestamp::MinusInfinity();
  DataRate target_;
  Timestamp last_gcc_ = Timestamp::MinusInfinity();
  std::deque<std::pair<Timestamp, int64_t>> window_;
  int64_t window_bytes_ = 0;
  ControllerActions actions_;
  SendSideStats stats_;
};
