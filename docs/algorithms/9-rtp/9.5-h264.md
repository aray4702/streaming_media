# 9.5 H.264 packetization (RFC 6184) and fake encoder

Section 9, *RTP/RTCP session layer*, of [Problems WebRTC solves](../../02-webrtc-problems-solved.md). Problems addressed:

- Video payload format on the wire -> H.264 packetization-mode 1: single NAL, STAP-A, FU-A; mode 0: single NAL units

## The issue

Video must be carried in RTP packets small enough to fit the path MTU. A keyframe is far larger than one packet, so the payload format decides how an access unit is split and how the receiver finds where a frame starts and ends. H.264 (RFC 6184) defines single NAL unit packets, aggregation of small NAL units (STAP-A, typically SPS and PPS) and fragmentation of large ones (FU-A). A packetizer or depacketizer that disagrees with libwebrtc's makes the call fail to decode, so the format is checked against libwebrtc's own parser.

## Design

H.264 RTP payload format (RFC 6184), packetization-mode 1 (docs/design/ rtp-session.md, sections 6.1 to 6.4). Follows libwebrtc's RtpPacketizerH264 (modules/rtp_rtcp/source/rtp_format_h264.cc) and VideoRtpDepacketizerH264: single NAL unit packets, STAP-A aggregation and FU-A fragmentation. STAP-B, MTAP and FU-B belong to mode 2, which libwebrtc does not negotiate: its depacketizer takes them (and types 0 and 30-31) as single NAL units it reads nothing from, and so does ours.

An access unit is handed over as an Annex-B byte stream (start codes 00 00 01 or 00 00 00 01). The packetizer removes the start codes, the depacketizer puts one back per NAL unit. The RTP marker bit goes on the last packet of the access unit (the caller sets it; RtpSender::SendVideoFrame does). No clock, no threads, no allocation outside the returned vectors.

A stand-in for an H.264 encoder, for the test bench, the examples and the tests (docs/design/rtp-session.md, section 6.3). Follows libwebrtc's FakeH264Encoder (test/fake_encoder.cc): the bitstream is not decodable, but it has the real NAL structure. A keyframe is SPS (nal type 7, 8 bytes), PPS (type 8, 11 bytes) and an IDR slice (type 5) with the rest of the frame; a delta frame is one non-IDR slice (type 1). Differences from libwebrtc's fake: a keyframe is made when asked for, not on a fixed 1-in-10 cycle; the SPS and PPS are valid parameter sets of the same sizes (the ones sm_compare's model encoder gives libwebrtc, issue #339), so the sender's SPS VUI rewrite (#342) parses them as libwebrtc's does; and the slice filler never contains a zero byte, so no start code or emulation-prevention concern arises and what the packetizer splits is what the depacketizer joins. The first byte after a slice header has its top bit set, which is first_mb_in_slice = 0, the marker the depacketizer uses to find frame starts.

The outgoing H.264 SPS VUI rewrite libwebrtc applies to every keyframe before packetization (issue #342). Follows libwebrtc M157's FrameEncodeMetadataWriter::UpdateBitstream (video/frame_encode_metadata_writer.cc), which VideoStreamEncoder:: AugmentEncodedImage calls, and SpsVuiRewriter (common_video/h264/sps_vui_rewriter.cc): each SPS gets a VUI with bitstream_restriction (max_num_reorder_frames 0, max_dec_frame_buffering = max_num_ref_frames), added when missing or rewritten when it allows reordering, so a decoder outputs each frame at once; access unit delimiters are dropped; every other NAL unit is copied.

Differences from libwebrtc: there is no color space input (libwebrtc's `color_space` argument is the encoded image's, which is unset for the encoders this library models, and then the video signal type is copied as is), and the result histogram (WebRTC.Video.H264.SpsValid) is the count in SpsRewriteStats. The SPS fields up to the VUI are read as libwebrtc's SpsParser::ParseSpsUpToVui (common_video/h264/sps_parser.cc) and the RBSP escaping is h264_common.cc's ParseRbsp/WriteRbsp (#568). The receive side (VideoRtpDepacketizerH264, sm/rtp/h264.h) uses the same rewrite.

See the [libwebrtc parity inventory](../../design/libwebrtc-parity.md#9-rtp-session-layer) for the differences from libwebrtc. Follows libwebrtc's RtpPacketizerH264 and VideoRtpDepacketizerH264 (checked by the interop test against H26xPacketBuffer). The fake encoder follows FakeH264Encoder and differs in making a keyframe when asked, in valid SPS and PPS of the filler's sizes (sm_compare's model encoder, #339), and in never writing a zero byte into the filler. An IDR alone counts as a keyframe, as in libwebrtc by default. Before packetizing a keyframe the session rewrites its SPS VUI as libwebrtc's FrameEncodeMetadataWriter::UpdateBitstream and SpsVuiRewriter do (#342): a VUI with bitstream_restriction (no frame reordering) is added or fixed, and AUDs are dropped. There is no color space input (the encoders modelled set none, so the video signal type is copied). The depacketizer ports VideoRtpDepacketizerH264::Parse (#568): which payloads it drops (an SPS, PPS or slice header that doesn't parse, a nested STAP-A or FU-A, an FU-A under 2 bytes), where frames start, the SPS's resolution, and the incoming SPS VUI rewrite; reassembly follows H264SpsPpsTracker::CopyAndFixBitstream. The SPS fields are read as libwebrtc's SpsParser, with H264::IsValidResolution's level 5.2 bound, and the PPS and slice ids as PpsParser::ParsePpsIds and ParseSliceHeader (ids bounded by kMaxPpsId and kMaxSpsId). Each unit's ids go to the receiver's parameter-set tracker (RTPVideoHeaderH264::nalus). The packetization mode is the one the host negotiated (VideoStreamConfig::h264_packetization_mode, mode 1 by default): mode 0 sends each NAL unit alone and fails a frame with a unit that does not fit, as RtpPacketizerH264::PacketizeSingleNalu (#655). Session::SendVideo returns the size of the access unit after the rewrite, which VideoStreamEncoder::RunPostEncode gives the frame dropper and the bitrate adjuster.

```cpp
// NAL units of an Annex-B stream, start codes removed, as views into `annexb`.
// Zero-length units (back-to-back start codes) are skipped; bytes before the
// first start code are ignored. A stream with no start code yields one unit
// holding all of it, so a bare NAL unit is accepted too.
std::vector<std::span<const uint8_t>> SplitAnnexB(std::span<const uint8_t> annexb);

// libwebrtc's RtpPacketizer::PayloadSizeLimits (rtp_format.h): the payload
// room of a middle packet, and how much less the first, the last and a
// single packet of the frame have, because their headers carry more
// extensions.
struct PayloadSizeLimits {
  int max_payload_len = 1200 - 12;
  int first_packet_reduction_len = 0;
  int last_packet_reduction_len = 0;
  int single_packet_reduction_len = 0;
};

// libwebrtc's H264PacketizationMode (RFC 6184 packetization-mode), which
// RtpPacketizerH264 takes from RTPVideoHeaderH264 (rtp_format.cc:64-69).
enum class H264PacketizationMode {
  kNonInterleaved,  // Mode 1: single NAL unit, STAP-A and FU-A packets.
  kSingleNalUnit,   // Mode 0: one NAL unit per packet, no aggregation or fragmentation.
};

class H264Packetizer {
 public:
  // RtpPacketizerH264 (rtp_format_h264.cc) with the reductions of `limits`.
  // Mode 1 (GeneratePackets, l.70-100): a unit larger than the room of its
  // packet is split by FU-A with SplitAboutEqually, the rest are aggregated by
  // STAP-A. Mode 0 (PacketizeSingleNalu, l.204-226): each unit is one packet.
  // Empty when the frame cannot be packetized (max_payload_len of 2 or less for
  // an FU-A, no room for a byte in the first or last packet, or in mode 0 a unit
  // larger than the room of its packet).
  static std::vector<std::vector<uint8_t>> Packetize(std::span<const uint8_t> annexb, const PayloadSizeLimits& limits,
                                                     H264PacketizationMode mode = H264PacketizationMode::kNonInterleaved);

  // The payloads of the RTP packets of one access unit, in order, each at most
  // `max_payload` bytes (at least 3 is needed for FU-A; smaller is raised).
  // Empty input gives no payloads.
  static std::vector<std::vector<uint8_t>> Packetize(std::span<const uint8_t> annexb, size_t max_payload);
};

// What one RTP payload holds: VideoRtpDepacketizerH264::Parse's video header
// (video_rtp_depacketizer_h264.cc).
struct H264PayloadInfo {
  bool valid = false;  // False: Parse returns nullopt there (the packet is dropped).
  // is_first_packet_in_frame: an SPS, PPS, AUD or SEI unit, or a slice whose
  // first_mb_in_slice is 0 (in an FU-A, the first fragment of a slice only).
  bool first_packet_in_frame = false;
  bool idr = false;  // An IDR slice (nal_unit_type 5), or its first FU-A fragment.
  // frame_type kVideoFrameKey: an SPS or an IDR slice in a single NAL unit or
  // STAP-A, or any FU-A fragment of an IDR slice (ParseFuaNalu reads the
  // original NAL type from every fragment).
  bool keyframe = false;
  bool sps = false;  // An SPS that parsed (single NAL unit or STAP-A).
  bool pps = false;  // A PPS whose ids parsed (single NAL unit or STAP-A).
  // The SPS's resolution (video_header.width/height), 0 without an SPS.
  uint32_t width = 0;
  uint32_t height = 0;
  bool fu_start = false;  // An FU-A fragment with the start bit.
  bool fu_end = false;    // An FU-A fragment with the end bit.
  bool fu_continuation = false;  // An FU-A fragment without the start bit.
  // RTPVideoHeaderH264::nalus: each non-empty unit of a single NAL unit or
  // STAP-A with the ids it carries (SPS: its id; PPS: both; slice: its PPS
  // id), and an FU-A's first fragment with its slice's PPS id (-1 for an SPS
  // or PPS, whose ids an FU-A doesn't give). Other fragments have none.
  std::vector<VideoNaluInfo> nalus;
};

class H264Depacketizer {
 public:
  // VideoRtpDepacketizerH264::Parse without keeping state. A single NAL unit
  // or STAP-A is dropped when a unit is an SPS that SpsVuiRewriter cannot
  // parse, a PPS or slice whose ids don't parse, or a nested STAP-A or FU-A; an
  // FU-A when it is shorter than its two header bytes. Empty units are
  // skipped. The FU-A start and end bits are not checked, as in libwebrtc.
  static H264PayloadInfo Parse(std::span<const uint8_t> payload);

  // Rebuilds the Annex-B access unit from the payloads of one frame's packets,
  // in sequence order, as H264SpsPpsTracker::CopyAndFixBitstream: a start
  // code before each unit and before the first fragment of an FU-A. An SPS is
  // rewritten as the depacketizer rewrites it on receive (SpsVuiRewriter,
  // kIncoming). False if a payload is one Parse drops; `out` is left with
  // what was appended.
  static bool Reassemble(std::span<const RtpPacket> packets, std::vector<uint8_t>& out);
};

// VideoPayloadParser for H.264: tells the receiver where frames start and
// whether they are keyframes. By default an IDR slice alone makes a keyframe
// (libwebrtc's default); the receiver's `keyframe_needs_parameter_sets`
// requires SPS and PPS as well (libwebrtc's sps-pps-idr-in-keyframe mode).
class H264PayloadParser : public VideoPayloadParser {
 public:
  VideoPayloadInfo Parse(const RtpPacket& p) const override;
  bool Reassemble(std::span<const RtpPacket> packets, std::vector<uint8_t>& out) const override {
    return H264Depacketizer::Reassemble(packets, out);
  }
};

}  // namespace sm::rtp
```

```cpp
namespace sm::rtp {

// SPS: profile_idc 66 with constraint_set0-2 and level 3.1 (profile-level-id
// 42e01f), sps id 0, log2_max_frame_num_minus4 0, pic_order_cnt_type 2, one
// reference frame, 320x192 (20x12 macroblocks), frame macroblocks only, no
// cropping, no VUI. A 1280x720 SPS does not fit in 7 bytes; nothing decodes
// the frames, so the size is not used.
inline constexpr uint8_t kFakeH264Sps[7] = {0x42, 0xe0, 0x1f, 0xda, 0x05, 0x06, 0x64};
// PPS: pps id 0 and sps id 0 (the ids the slice headers' first byte, 0xAA,
// refers to), CAVLC, one slice group, QP 26, deblocking control present, then
// two flat 4x4 scaling lists (all 16), which fill it to 10 bytes.
inline constexpr uint8_t kFakeH264Pps[10] = {0xce, 0x3c, 0x61, 0x0f, 0xff, 0xe4, 0x21, 0xff, 0xfc, 0xc0};

// An Annex-B access unit of exactly max(bytes, the smallest valid frame) bytes.
inline std::vector<uint8_t> MakeFakeH264Frame(bool keyframe, size_t bytes) {
  constexpr uint8_t kStart[4] = {0, 0, 0, 1};
  std::vector<uint8_t> out;
  auto parameter_set = [&](uint8_t header, std::span<const uint8_t> body) {
    out.insert(out.end(), kStart, kStart + 4);
    out.push_back(header);
    out.insert(out.end(), body.begin(), body.end());
  };
  auto slice = [&](uint8_t header, size_t nal_bytes) {
    out.insert(out.end(), kStart, kStart + 4);
    out.push_back(header);
    for (size_t i = 1; i < nal_bytes; ++i) {
      out.push_back(i == 1 ? 0xAA : static_cast<uint8_t>(0x11 + (i * 7) % 0xE0));
    }
  };
  if (keyframe) {
    parameter_set(0x67, kFakeH264Sps);
    parameter_set(0x68, kFakeH264Pps);
    const size_t used = out.size();
    const size_t idr = bytes > used + 4 + 2 ? bytes - used - 4 : 2;
    slice(0x65, idr);
  } else {
    slice(0x41, std::max<size_t>(bytes, 4 + 2) - 4);
  }
  return out;
}

}  // namespace sm::rtp
```

```cpp
namespace sm::rtp {

// The SPS fields SpsVuiRewriter reads (libwebrtc's SpsParser::SpsState, up to
// vui_parameters_present_flag).
struct SpsState {
  uint32_t width = 0;
  uint32_t height = 0;
  uint32_t profile_idc = 0;
  uint32_t level_idc = 0;
  uint32_t id = 0;
  uint32_t log2_max_frame_num = 4;
  uint32_t pic_order_cnt_type = 0;
  uint32_t log2_max_pic_order_cnt_lsb = 4;
  uint32_t max_num_ref_frames = 0;
  uint32_t frame_mbs_only_flag = 1;
  uint32_t separate_colour_plane_flag = 0;
  bool vui_params_present = false;
};

// libwebrtc's H264 namespace bounds (common_video/h264/h264_common.h:38-63).
inline constexpr uint32_t kH264MaxReferenceIndex = 31;
inline constexpr uint32_t kH264MaxSpsId = 31;
inline constexpr uint32_t kH264MaxPpsId = 255;
// Level 5.2's limits (H.264 table A-1), which libwebrtc applies to every SPS.
inline constexpr int64_t kH264MaxMacroblockFrameSizeLevel52 = 36864;
inline constexpr int64_t kH264MaxMacroblockDimensionLevel52 = 543;
inline constexpr int64_t kH264MaxPixelDimensionLevel52 = kH264MaxMacroblockDimensionLevel52 * 16;

// H264::IsValidResolution (h264_common.h:56-64): both dimensions positive and
// at most 8688 pixels, and at most 36864 macroblocks in a frame.
constexpr bool IsValidH264Resolution(int64_t width, int64_t height) {
  if (width <= 0 || height <= 0 || width > kH264MaxPixelDimensionLevel52 ||
      height > kH264MaxPixelDimensionLevel52) {
    return false;
  }
  const int64_t width_in_mbs = (width + 15) / 16;
  const int64_t height_in_mbs = (height + 15) / 16;
  return width_in_mbs * height_in_mbs <= kH264MaxMacroblockFrameSizeLevel52;
}

// H.264 7.4.1: removes emulation prevention bytes (00 00 03 -> 00 00).
std::vector<uint8_t> ParseRbsp(std::span<const uint8_t> data);
// H.264 7.4.1: appends `rbsp` to `out` with an emulation prevention byte after
// every two zero bytes that precede a byte of 3 or less.
void WriteRbsp(std::span<const uint8_t> rbsp, std::vector<uint8_t>& out);

// The SPS fields up to and including vui_parameters_present_flag, from an SPS
// RBSP without its NAL header byte. Empty when it does not parse.
std::optional<SpsState> ParseSpsUpToVui(std::span<const uint8_t> rbsp);

enum class SpsRewriteResult { kFailure, kVuiOk, kVuiRewritten };

struct SpsRewriteStats {  // libwebrtc's kSentSps* histogram samples.
  uint64_t vui_ok = 0;
  uint64_t rewritten = 0;
  uint64_t parse_failures = 0;
};

// SpsVuiRewriter::ParseAndRewriteSps: `sps` is an SPS NAL unit payload without
// its header byte, still escaped. On kVuiRewritten the escaped new payload is
// appended to `destination`; otherwise `destination` is unchanged. `parsed`,
// if given, receives the SPS fields whenever they parse (kVuiOk and
// kVuiRewritten).
SpsRewriteResult ParseAndRewriteSps(std::span<const uint8_t> sps, std::vector<uint8_t>& destination,
                                    SpsState* parsed = nullptr);

// libwebrtc's PpsParser::ParsePpsIds and PpsParser::ParseSliceHeader
// (common_video/h264/pps_parser.cc:44-88), the fields of a PPS and a slice
// header that VideoRtpDepacketizerH264 reads: the leading ue(v) fields of
// H.264 7.3.2.2 (pic_parameter_set_id, seq_parameter_set_id) and 7.3.3
// (first_mb_in_slice, slice_type, pic_parameter_set_id) from the unescaped
// RBSP. Empty when the data ends first or an id is out of bounds (a PPS id
// over kH264MaxPpsId, an SPS id over kH264MaxSpsId). Both take the NAL unit
// payload without its header byte.
struct PpsIds {
  uint32_t pps_id = 0;
  uint32_t sps_id = 0;
};
std::optional<PpsIds> ParsePpsIds(std::span<const uint8_t> pps);
struct SliceHeader {
  uint32_t first_mb_in_slice = 0;
  uint32_t pic_parameter_set_id = 0;
};
std::optional<SliceHeader> ParseSliceHeader(std::span<const uint8_t> slice);

// SpsVuiRewriter::ParseOutgoingBitstreamAndRewrite on an Annex-B access unit:
// SPS units rewritten where needed, AUDs dropped, the rest copied with their
// start codes. Each SPS result is counted in `stats` if given.
std::vector<uint8_t> ParseOutgoingBitstreamAndRewrite(std::span<const uint8_t> annexb,
                                                      SpsRewriteStats* stats = nullptr);

}  // namespace sm::rtp
```

## Verification notes

Introduced by #32 plan PR 7. The 24-byte SPS+PPS packet that now opens the call exposed a start-up fragility in the pacer and probing code (first probe cluster rejected), tracked in #48. Per-suite results are recorded by ctest and CI; tools/run_all.sh does not run these suites yet. #342: the keyframe's STAP-A [SPS, PPS] is 77 B on both stacks (72 B before), checked on `clean_link`'s per-packet trace against libwebrtc's, and the rewritten bytes are checked against libwebrtc's SpsVuiRewriter by `sm_rtcp_interop` (25 access units). #568: the depacketizer's accept and drop rules, frame starts and receive-side SPS rewrite are unit-tested against video_rtp_depacketizer_h264.cc case by case (`unit.H264`); the bench's frames are rewritten on send, so the receive side finds kVuiOk and no suite metric moves. The PPS and slice id bounds, the SPS resolution bound and the per-unit ids are unit-tested against pps_parser.cc, h264_common.h and video_rtp_depacketizer_h264.cc (`unit.H264`, `unit.SpsVuiRewriter`); no suite metric moves.
