# 9.1 RTCP engine, SDES and BYE

Section 9, *RTP/RTCP session layer*, of [Problems WebRTC solves](../../02-webrtc-problems-solved.md). Problems addressed:

- Receiver and sender reports, RTT and feedback -> one RTCP engine per session
- Early feedback (NACK, PLI, FIR, loss notification, transport-cc, REMB) -> compound packets sent at once

## The issue

A call needs a steady side channel next to the media. The sender must tell the receiver how its RTP timestamps map to wall-clock time (sender reports) and the receiver must report loss, jitter and delay so the sender can measure the round trip. When something goes wrong the receiver must say so at once: which packets are missing, that a keyframe is needed, which packets arrived and when. These rules are easy to get subtly wrong: reports sent too often waste bandwidth, too rarely leave RTT stale, and every compound packet must start with a report and carry the CNAME that lets the receiver group audio and video for lip-sync.

## Design

RTCP engine of the RTP session layer (docs/design/rtp-session.md, section 8): schedules sender and receiver reports, builds the compound datagrams that carry them and the early feedback (NACK, PLI, FIR, loss notification, transport-cc, REMB), and splits incoming compounds into typed results for the caller to dispatch. Follows libwebrtc's RTCPSender and RTCPReceiver: reports every 1 s with video and 5 s without (optionally randomized 0.5 to 1.5x), a first report at about half the interval, SR/RR first and SDES CNAME after it, and early feedback sent at once.

The engine owns no media state. Report blocks come from the registered timing::ReceiveStatistics, sender counters are pushed in with SetSenderState, and the caller decides when feedback is wanted (the NACK, keyframe and transport-cc modules keep their own throttles). Takes `now`, reads no clock and starts no thread.

RTCP source description (SDES, RFC 3550 6.5) and goodbye (BYE, RFC 3550 6.6) packets. SDES carries the CNAME that libwebrtc puts in every compound packet; BYE announces that a source leaves the session. Layouts follow libwebrtc's rtcp_packet/sdes and bye. Pure functions: no clock, no state. Part of the RTP session layer (docs/design/rtp-session.md, section 8.2).

See the [libwebrtc parity inventory](../../design/libwebrtc-parity.md#9-rtp-session-layer) for the differences from libwebrtc. Follows libwebrtc's RTCPSender and RTCPReceiver for the report interval (1 s with video, 5 s without, randomization 0.5 to 1.5x, first report at half the interval) and for the compound layout (SR or RR first, SDES CNAME after it). Reports are timed as (issue #76 group 3; the fixed-grid v1 and the `rtcp` switch were deleted in #167) RTCPSender::ComputeTimeUntilNextReport: whole milliseconds drawn from [0.5, 1.5] x the minimum, at least 1 ms, and min(360 s / kbit/s, interval) for a video sender above 72 kbit/s; the rate is the sender's egress rate over 1 s, every packet type with its RTP header, as `RtpSenderEgress::GetSendRates(now).Sum()` (issue #217). A report due within 100 ms is sent ahead of a video keyframe (RTCPSender::TimeToSendRTCPReport, issue #101). NACK, PLI, FIR and loss notification carry the full SR/RR (report blocks) and SDES and restart the report timer, as RTCPSender::PrepareReport does in compound mode; transport-cc and REMB keep an empty leading RR where libwebrtc's SendCombinedRtcpPacket sends none (issue #201). Differs in having one engine per session where libwebrtc has one per SSRC, which one-to-one calls allow. Wire layouts are checked against libwebrtc's parsers in compare/webrtc/rtcp_interop.cc (CI job compare-webrtc).

```cpp
namespace sm::rtp {

struct RtcpConfig {
  uint32_t local_ssrc = 1;  // RTCP sender SSRC of reports and feedback.
  std::string cname;        // SDES CNAME; empty = no SDES.
  bool has_video = true;    // Picks the default report interval.
  // Nominal interval between reports; zero = 1 s with video, 5 s audio only
  // (libwebrtc's rtcp_report_interval_ms).
  TimeDelta report_interval = TimeDelta::Zero();
  // Time from the first Process call to the first report; zero = half the
  // interval, like RTCPSender. Lets the test bench keep its report phases.
  TimeDelta first_report_delay = TimeDelta::Zero();
  // Intervals follow libwebrtc's `RTCPSender::ComputeTimeUntilNextReport`
  // (#76): every interval is a whole number of milliseconds drawn from
  // [0.5, 1.5] x the minimum, at least 1 ms, and a video sender above
  // 72 kbit/s uses min(360 / kbit/s s, interval) (RFC 3550 6.2).
  // Reduced-size RTCP (RFC 5506): early feedback is sent without the leading
  // SR/RR. Only when the peer negotiated it.
  bool reduced_size = false;
  // Datagrams are split before they pass this size (libwebrtc's
  // kMaxRtcpPacketSize is the RTP MTU).
  size_t max_datagram_bytes = 1200;
  uint64_t seed = 1;  // Seeds the interval randomization.
  EventSink* events = nullptr;
};

// What the caller knows about the media it sends, for the SR.
struct RtcpSenderState {
  uint32_t ssrc = 0;
  uint32_t packet_count = 0;
  uint32_t octet_count = 0;
  // The RTP timestamp that corresponded to `reference_time`; the SR carries
  // this extrapolated to the report time with `clock_rate`.
  uint32_t rtp_timestamp = 0;
  Timestamp reference_time = Timestamp::Millis(0);
  int clock_rate = 90000;
  // The sender's rate over the last second, every packet type with its RTP
  // header (ModuleRtpRtcpImpl2::GetFeedbackState: RtpSenderEgress::GetSendRates(now).Sum()),
  // for the video report interval. Empty: derived from `octet_count`.
  std::optional<DataRate> send_bitrate;
};

enum class RtcpOutKind { kReport, kFeedback };

struct RtcpOutgoing {
  std::vector<uint8_t> bytes;  // One datagram, ready for the socket.
  RtcpOutKind kind = RtcpOutKind::kReport;
};

struct RtcpRemb {
  DataRate bitrate = DataRate::Zero();
  std::vector<uint32_t> ssrcs;
};

// What one incoming datagram contained. Nothing is dispatched by the engine;
// the caller routes each list (design section 8.3):
//   sender_reports      -> ReceiveStatistics::OnSenderReport, sync::RtpToNtp
//   report_blocks, rtts -> GCC OnRttUpdate, NackTracker, KeyframeRequester,
//                          RtxSender, FecControllerDefault
//   transport_feedback  -> GccController::OnTransportFeedback, OutageMonitor
//   nacks               -> RtxSender::OnNack
//   keyframe_requests   -> encoder (PLI, and FIR once per seq_nr)
//   remb                -> GccController::OnRemb
struct RtcpIncoming {
  bool valid = false;  // False when the datagram was malformed.
  std::vector<timing::SenderReport> sender_reports;
  std::vector<timing::ReportBlock> report_blocks;  // From SR and RR, all senders.
  std::vector<TimeDelta> rtts;                     // One per usable report block.
  std::vector<loss::Nack> nacks;
  std::vector<cc::TransportFeedback> transport_feedback;
  std::vector<uint32_t> keyframe_requests;  // Media SSRC of each PLI / new FIR.
  std::vector<loss::LossNotification> loss_notifications;  // Informational only.
  std::vector<RtcpRemb> remb;
  std::vector<SdesChunk> sdes;
  std::vector<Bye> byes;
  size_t ignored = 0;  // Packets of a type the library does not interpret.
};

struct RtcpStats {
  uint64_t reports_sent = 0, sr_sent = 0, rr_sent = 0;
  uint64_t feedback_datagrams = 0;
  uint64_t nack_sent = 0, nack_seqs_sent = 0, pli_sent = 0, fir_sent = 0, lntf_sent = 0;
  uint64_t transport_cc_sent = 0, remb_sent = 0;
  uint64_t bytes_sent = 0;
  uint64_t datagrams_received = 0, malformed = 0, ignored = 0;
  uint64_t sr_received = 0, rr_received = 0, report_blocks_received = 0;
  uint64_t nack_received = 0, pli_received = 0, fir_received = 0, fir_duplicates = 0;
  uint64_t lntf_received = 0, transport_cc_received = 0, remb_received = 0;
  uint64_t sdes_received = 0, bye_received = 0;
};

class RtcpEngine : public MetricsSource {
 public:
  // Incoming FIR sequence numbers are remembered for at most this many
  // (sender, media) pairs; the table is cleared when it fills.
  static constexpr size_t kMaxFirTracked = 64;

  explicit RtcpEngine(RtcpConfig cfg = {});

  // --- Setup (before traffic) -------------------------------------------------
  // Sender side: the SR is sent instead of an RR once this is set.
  void SetSenderState(const RtcpSenderState& s);
  // Receive statistics whose report block goes into every report. Not owned.
  void AddReceiveStatistics(timing::ReceiveStatistics* stats);
  // Local media SSRCs, to pick the report blocks that describe our own
  // streams for the RTT. With none registered every block counts.
  void AddLocalMediaSsrc(uint32_t ssrc);

  // --- Egress -----------------------------------------------------------------
  // Early feedback; sent by the next Process. Several in one Process share one
  // compound datagram (split at max_datagram_bytes). The sender SSRC of every
  // message is set to cfg.local_ssrc.
  void QueueNack(uint32_t media_ssrc, std::span<const uint16_t> seqs);
  void QueuePli(uint32_t media_ssrc);
  void QueueFir(uint32_t media_ssrc);  // The engine numbers the requests.
  void QueueLossNotification(loss::LossNotification l);
  void QueueTransportFeedback(cc::TransportFeedback fb);
  void QueueRemb(DataRate bitrate, std::span<const uint32_t> ssrcs);
  // Announces that the local sources leave the session (RFC 3550 6.6).
  void QueueBye(std::span<const uint32_t> ssrcs, std::string reason = {});

  // `RTCPSender::TimeToSendRTCPReport(send_keyframe_before_rtp)`: a report is
  // due. With a keyframe about to be sent on a video stream a
  // report due within 100 ms counts, so it goes out before the large frame.
  bool ReportDue(Timestamp now, bool keyframe_before_rtp = false) const;
  // Sends the report now (`SendRTCP(kRtcpReport)`) and schedules the next one
  // an interval from `now`. Returns nothing before the first Process.
  std::vector<RtcpOutgoing> SendReport(Timestamp now);

  // Emits the report if one is due and all queued feedback.
  std::vector<RtcpOutgoing> Process(Timestamp now);
  // When Process must run next: now if feedback is queued, else the next report.
  Timestamp NextProcessTime(Timestamp now) const;

  // --- Ingress ----------------------------------------------------------------
  RtcpIncoming OnRtcp(std::span<const uint8_t> datagram, Timestamp now);

  const timing::RttEstimator& rtt() const { return rtt_; }
  const RtcpStats& stats() const { return stats_; }
  size_t fir_tracked() const { return fir_seq_in_.size(); }
  void ExportMetrics(MetricsWriter& w) const override;

  };
  std::vector<Queued> queue_;
  std::map<uint32_t, uint8_t> fir_seq_out_;                       // media ssrc -> next seq_nr
  std::map<std::pair<uint32_t, uint32_t>, uint8_t> fir_seq_in_;   // (sender, media) -> last seq_nr
  void UpdateSendRate(Timestamp now);
  std::deque<std::pair<Timestamp, uint32_t>> rate_samples_;
  DataRate send_rate_ = DataRate::Zero();
  timing::RttEstimator rtt_;
  RtcpStats stats_;
};

}  // namespace sm::rtp
```

```cpp
namespace sm::rtp {

// SDES item type (RFC 3550 6.5). Only CNAME is sent by the library; other
// types are parsed and handed back untouched.
inline constexpr uint8_t kSdesCname = 1;

struct SdesItem {
  uint8_t type = 0;  // 1..255; 0 is the list terminator and cannot be an item.
  std::string text;  // At most 255 bytes.
};

struct SdesChunk {
  uint32_t ssrc = 0;
  std::vector<SdesItem> items;
};

// At most 31 chunks fit the 5-bit source count.
inline constexpr size_t kMaxSdesChunks = 31;
inline constexpr size_t kMaxRtcpText = 255;

// Serializes one SDES packet. Returns an empty vector when it cannot be
// encoded: no chunks, more than 31 chunks, an item of type 0 or with text
// longer than 255 bytes, or a packet longer than the 16-bit length allows.
std::vector<uint8_t> SerializeSdes(std::span<const SdesChunk> chunks);

// Parses exactly one SDES packet (header included). Returns nullopt for a
// wrong type, bad version, length mismatch or a chunk that runs past the end.
// Padding (P bit) is stripped.
std::optional<std::vector<SdesChunk>> ParseSdes(std::span<const uint8_t> data);

struct Bye {
  std::vector<uint32_t> ssrcs;  // 0..31 sources leaving.
  std::string reason;           // Optional, at most 255 bytes.
};

// Returns an empty vector for more than 31 sources or a reason over 255 bytes.
std::vector<uint8_t> SerializeBye(const Bye& b);
std::optional<Bye> ParseBye(std::span<const uint8_t> data);

}  // namespace sm::rtp
```
