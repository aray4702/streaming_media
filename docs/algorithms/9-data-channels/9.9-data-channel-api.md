# 9.9 DCEP and the data channel API

Section 9, *Data channels*, of [Problems WebRTC solves](../../02-webrtc-problems-solved.md). Problems addressed:

- Application messages between browsers and servers -> DATA_CHANNEL_OPEN/ACK, reliable and partially reliable channels, in-band and negotiated

## The issue

On the association, channels are opened with DCEP (DATA_CHANNEL_OPEN and ACK), have a label, an ordering, a reliability mode and a stream id whose parity follows the DTLS role. The API must follow what browsers do, so a message from a browser's `RTCDataChannel` arrives as sent, and the whole feature must be absent when switched off.

## Design

The data channel API, after libwebrtc M157's api/data_channel_interface.{h,cc} and pc/data_channel_utils.h (compare/webrtc/reference/). C7 part 4 (#1070), built with SM_WITH_DATACHANNEL=ON.

Differences from libwebrtc: no reference counting or proxies (channels are std::shared_ptr and every call runs on the caller's thread, as the rest of the library), DataBuffer holds a std::vector, and the deprecated `reliable` field of DataChannelInit is left out.

DCEP (RFC 8832) DATA_CHANNEL_OPEN and DATA_CHANNEL_ACK, after libwebrtc M157's pc/sctp_utils.{h,cc} (compare/webrtc/reference/). C7 part 4 (#1070).

One data channel over SCTP, after libwebrtc M157's pc/sctp_data_channel.{h,cc} (compare/webrtc/reference/). C7 part 4 (#1070), built with SM_WITH_DATACHANNEL=ON.

The channel runs the DCEP handshake (an opener sends DATA_CHANNEL_OPEN and waits for DATA_CHANNEL_ACK; an acker answers the OPEN; a negotiated channel has none), the states connecting -> open -> closing -> closed, the closing procedure (an outgoing stream reset once the send buffer is empty) and the buffered amount reporting (OnBufferedAmountChange once 100 KiB was sent or the buffer emptied). It holds a weak reference to its controller (DataChannelController), as libwebrtc's WeakPtr.

Differences from libwebrtc: no signaling/network thread split, no proxy and no SendAsync (one thread, as the library); calls that may send take `Timestamp now`; observers are called directly instead of through a posted task.

The connection's data channels, after libwebrtc M157's pc/data_channel_controller.{h,cc} (compare/webrtc/reference/). C7 part 4 (#1070), built with SM_WITH_DATACHANNEL=ON.

Creates channels (in-band ones allocate an even or odd stream id by DTLS role once it is known; negotiated ones reserve theirs), answers a remote DATA_CHANNEL_OPEN with a new channel, routes received messages, stream resets, buffered-amount-low and transport closure to the channels, and sends their data on the SCTP transport.

Differences from libwebrtc: one thread, so the tasks libwebrtc posts to the network thread (a new channel's OnTransportReady) run from Process(now), and those it posts to the signaling thread (OnDataChannel) are called directly; no PeerConnection behind it (the new-channel callback replaces PeerConnectionObserver::OnDataChannel); no DataChannelEventObserverInterface; events go to an EventSink.

libwebrtc M157 counterpart: `api/data_channel_interface.h`, `pc/sctp_utils.{h,cc}`, `pc/sctp_data_channel.{h,cc}`, `pc/data_channel_controller.{h,cc}`. Differences from libwebrtc: [libwebrtc parity inventory](../../design/libwebrtc-parity.md), section [10.20](../../design/libwebrtc-parity.md#1020-data-channels-dcep-and-the-data-channel-api-srcpcsctp_utilssctp_data_channeldata_channel_controllercc-c7-part-4-1070), [10.21](../../design/libwebrtc-parity.md#1021-data-channels-on-the-endpoint-srcpcpeer_endpointcc-c7-part-5-1091). Requirement C7 parts 4 and 5. The runtime switch is per connection: off means no association, and a remote data section is rejected. Even and odd stream ids follow the DTLS role.

namespace sm::pc {

using sctp::PriorityValue;
using sctp::RtcError;
using sctp::RtcErrorType;

// RTCDataChannelInit (api/data_channel_interface.h).
struct DataChannelInit {
  // Deliver messages in order (true) or as they arrive (false).
  bool ordered = true;
  // maxPacketLifeTime in ms; partial reliability by time. Not together with maxRetransmits.
  std::optional<int> maxRetransmitTime;
  // Retransmissions before a message is abandoned; partial reliability by count.
  std::optional<int> maxRetransmits;
  // Sub-protocol name, sent in DATA_CHANNEL_OPEN.
  std::string protocol;
  // True: the application negotiated the channel out of band with `id`; no DCEP handshake.
  bool negotiated = false;
  // Stream id for a negotiated channel; -1 = allocate by DTLS role.
  int id = -1;
  std::optional<PriorityValue> priority;
};

// A message, text or binary.
struct DataBuffer {
  DataBuffer(std::vector<uint8_t> d, bool is_binary) : data(std::move(d)), binary(is_binary) {}
  explicit DataBuffer(std::string_view text) : data(text.begin(), text.end()), binary(false) {}
  size_t size() const { return data.size(); }
  std::vector<uint8_t> data;
  bool binary;
};

class DataChannelObserver {
 public:
  virtual ~DataChannelObserver() = default;
  // state() changed.
  virtual void OnStateChange() = 0;
  // A message arrived.
  virtual void OnMessage(const DataBuffer& buffer) = 0;
  // buffered_amount() dropped by `sent_data_size` bytes.
  virtual void OnBufferedAmountChange(uint64_t /*sent_data_size*/) {}
  // The transport's max message size is known.
  virtual void OnMaxMessageSize(int /*max_message_size*/) {}
};

enum class DataState { kConnecting, kOpen, kClosing, kClosed };

inline const char* DataStateString(DataState state) {
  switch (state) {
    case DataState::kConnecting:
      return "connecting";
    case DataState::kOpen:
      return "open";
    case DataState::kClosing:
      return "closing";
    case DataState::kClosed:
      return "closed";
  }
  return "";
}

// DataChannelInterface::MaxSendQueueSize(): 16 MiB.
inline constexpr uint64_t kDataChannelMaxSendQueueSize = 16 * 1024 * 1024;

// pc/data_channel_utils.h.
struct DataChannelStats {
  int internal_id = 0;
  int id = -1;
  std::string label;
  std::string protocol;
  DataState state = DataState::kConnecting;
  uint32_t messages_sent = 0;
  uint32_t messages_received = 0;
  uint64_t bytes_sent = 0;
  uint64_t bytes_received = 0;
};

}  // namespace sm::pc

  virtual void SetBufferedAmountLowThreshold(StreamId sid, size_t bytes) = 0;

 protected:
  virtual ~SctpDataChannelControllerInterface() = default;
};

// The controller's liveness token: channels keep a weak_ptr to it (libwebrtc's WeakPtr<...>).
using ControllerHandle = std::shared_ptr<SctpDataChannelControllerInterface*>;

struct InternalDataChannelInit : public DataChannelInit {
  enum OpenHandshakeRole { kOpener, kAcker, kNone };
  InternalDataChannelInit() = default;

  // maxRetransmitTime below 0 are dropped, above 65535 clamped, as libwebrtc.
  explicit InternalDataChannelInit(const DataChannelInit& base);
  bool IsValid() const;
  OpenHandshakeRole open_handshake_role = kOpener;
  // The DTLS role to use for the stream id when DTLS has not decided it yet.
  std::optional<p2p::SslRole> fallback_ssl_role;
};

class SctpSidAllocator {

// The runtime switch per connection (C7): with data channels off, a connection has no SCTP transport, so no
// association, and creating a channel fails. On, it owns the SCTP transport over the connection's DTLS
// transport (sm/sctp/) and the controller. libwebrtc has no such switch (a PeerConnection always offers data
// channels when asked); the default is on, as libwebrtc. On the endpoint (sm/pc/peer_endpoint.h, #1091) the same
// switch is PeerEndpointConfig::enable_data_channels, which also decides the m=application section.
class DataChannelSession {
 public:
  struct Config {
    bool enable_data_channels = true;
    // The SCTP association's settings (ports, max message size; a=sctp-port, a=max-message-size).
    sctp::SctpOptions sctp;
    sctp::DcSctpTransport::Config transport;
  };
  DataChannelSession(Timestamp now, p2p::DtlsTransport* dtls, Config config);
  ~DataChannelSession();
  DataChannelSession(const DataChannelSession&) = delete;
  DataChannelSession& operator=(const DataChannelSession&) = delete;

  bool enabled() const { return sctp_ != nullptr; }
  // Starts the association (after the description was applied). False if data channels are off.
  bool Start(Timestamp now);
  // createDataChannel(); fails with kInvalidState when data channels are off for this connection.
  std::shared_ptr<SctpDataChannel> CreateDataChannel(Timestamp now, std::string_view label,
                                                     const DataChannelInit& config, RtcError* error = nullptr);
  void SetOnDataChannel(std::function<void(std::shared_ptr<SctpDataChannel>)> callback);
  void SetEventSink(EventSink* sink);
  // Null when data channels are off.
  sctp::SctpTransport* sctp_transport() { return sctp_.get(); }
  DataChannelController* controller() { return controller_.get(); }

  Timestamp NextProcessTime() const;
  void Process(Timestamp now);

};
